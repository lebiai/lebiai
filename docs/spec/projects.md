## 0-fp. 第一性原理（P0 第零条）

- **拒绝的类比：**
  1. **不是**「加一个 Slack 频道 / 共享文件夹」——那是把「大家一起干活」当成一个容器问题；
     容器解决不了「这活谁接、接没接住」。
  2. **不是**「给工位之间通一条消息总线」——那会让每个人物的边界糊掉（谁都能替谁下结论，
     而硬拦正是本产品的立身之处，见 `personas.md` §6）。
  3. **不是**「把几个工位的记忆合并成一个大池子」——合并之后，「这是谁的专业口径」就没了。
- **拆出的真：**
  1. 用户要的不是「更热闹的界面」，是**一件活被干完**。活有接力的形状：每一步有产出物，
     产出物就是接力棒，交接点有明确的「谁交给谁」。
  2. 用户的原话是「**工位之间不通这次对话——光指路不算交活**」（2026-09-15 大导演会话）。
     所以缺的不是「聊天室」，是**接力这一动作本身**：A 的产出物要能成为 B 的输入。
  3. 真正的困难不在消息分发，在**归属**：这段会话是谁的、这条记忆是谁的、这份文件是谁的。
     现有产品只认两档（全局 / 某个人物）。项目组逼出第三档。
  4. 判断权和写作权是两件事，**不能合并**（主编定了又写，那道「审」就空了）；
     同理也不存在「谁都能写」——`personas.md` §6 的硬拦必须继续生效。
- **如何从真推出：**
  - 归属加第三档：会话 / 记忆 / 文件三处都多一个「项目组」。
  - 接力做成**可见的、由用户点的**一步（v1 手动），因为「不点头不往下走」是既有规矩；
    自动起跑（定时/触发）留到 v2，那时它已经被跑熟、被信任。
  - 一个项目组一张群像：成员是人物，但**每个人物仍然是它自己**——边界、口吻、硬拦都不变。

## 1. 一句话

**项目组 = 一个会话，几个固定的人，一件周而复始的活。**

第一个项目组：**《财富早知道》**——面向资本市场投资者的**盘前**财经资讯栏目，一天一期；
交付形态是**能直接读的书面稿**（数字人与成片在系统外，见 [`caifu-zaozhidao-news-standard.md`](./caifu-zaozhidao-news-standard.md)）。

## 2. 用户看到什么

### 2.1 侧栏

工位是「人」，项目组是「事」，两者并列、分开一节：

```
工位
  情报王海燕 / 产业专家扫地僧 / 主编吕老师 / 记者小宋 / 编辑雨天 / 主播小雨 / …
项目组
  财富早知道        ← 一行，带这活跑到哪了
```

- 点进项目组 → 打开**那一个**会话（日复一日同一条，见 §4.1）。
- 一行小字显示这活跑到哪了：`待你点头` / `在小宋手上` / `进行中` / `还没开工`。
  缺人时这一行**优先说缺谁**，那就成了色（琥珀）。

### 2.2 项目组会话里长什么样

- 每条消息带**说话人**（人名 + 头像）。分不清谁说的，这个界面就没有意义。
- 顶部写**组名**，不是人物名。不另做「这一期」看板：活在对话里，文件在产出里。
- 选题单等你点头时，自己出一张卡（唯一必停的一步）。
- 记忆、材料、产出三处仍然按全局口径可见（§5.3），组内的东西不藏着。
- **第 1 期落地的是**：组名（头部）· 顶部名册（桌上几人 / 缺席几人，点开列全
  含缺席）· 说话人标签（每条回复标出**这一轮开口的人**）。头像与按天分隔条见 §11。

### 2.3 空 / 载 / 错态

| 态 | 表现 |
|----|------|
| 空 | 新项目组：「今天还没开工。说一句，或者等第一份情报进来。」（问候语下面一行小字） |
| 载 | 谁在干活就在谁的名字旁转：**看得见是「吕老师在写」，不是「系统忙」** |
| 错 | 一句人话 + 原动作还在（沿用 2026-09-13 约定：**不喊红叉**） |
| 料不够 | 吕老师照实说「今天只够出两条」，**不硬凑**（沿用王海燕「宁缺不凑」的口径） |
| 要改 | 选题被否或用户说改，理由要落在决定上，否则下一棒没法改 |
| 越界 | 沿用硬拦 + 指路（`personas.md` §6），组内也一样拦 |

## 4. 三处归属（本规格的核心）

### 4.1 会话

- 新增一种会话：**项目组会话**。`SessionMeta` 增加项目组归属（与 `persona` 并列，二者互斥）。
- **一个项目组只有一条会话**，日复一日往下走——与工位同一条规矩。
  因此它**必然很长**：上下文压缩（`docs/records/20260916-gui-context-compaction.md`）与
  按天归档（§4.4）是它的生存前提，不是加分项。
- 说话人：`Message` 需要能标「这句是谁说的」。**实现细节留待实施计划**，
  但规格定死一件事：**界面上永远能看出谁在说**。

### 4.2 记忆

`owner` 从两档扩到三档：**全局 / 某个人物 / 某个项目组**。

**判据一句话：换个项目还算数吗？**

| 归谁 | 例子 |
|------|------|
| **人**（人物 owner） | 雨天的审核规则、王海燕的采集纪律、小宋的成稿笔法——手艺，跨项目通用 |
| **组**（项目组 owner） | 选材标准、弃稿标准、公告吃 1/3、主稿条数、盘前交付、往期怎么定的——只对这个栏目算数 |
| **全局**（空） | 关于你本人的偏好与标准（不变） |

- 写入仍**自动打标**：在谁的会话里说的归谁；在项目组会话里说的，**看内容**——
  关于手艺的归当前说话人，关于这个栏目的归项目组。**判不准时归项目组**（宁可窄，不要串味）。
- 注入：项目组会话里，每个人看见「全局 + 自己 + 本项目组」；**别人的专业口径一条都不给**
  （`personas.md` §5.4「注入隔离」在项目组里继续成立）。
- 「它记得的」管理页加归属标签与筛选项（沿用 §5.4「管理可见」）。

### 4.3 文件

- 项目组有**自己的归档区**：`财富早知道/<日期>/…`，一期的三件产物（情报、选题单、成稿）都在里面。
- **但这不是一道墙。** `personas.md` §5.6 写的是「在办 / 我的材料 / 产出：只记出处，**不隔离**」，
  理由是产出属于用户。本规格**不改这条**：
  - 项目组归档区是**归档 + 编目**：给文件加「哪个项目的、哪一期的」两个标签与目录；
  - 文件仍然属于你、仍然全局可搜（这就是 §C 折中：跨工位只翻**已交付的产出与材料**）；
  - **不做密室**：不存在「只有项目组能看见」的文件。
- 一天一期的产出按日期分目录，`outputs/` 平铺的问题顺手治掉。

### 4.4 会话按天归档（长会话的生存条件）

- 界面上默认展开**最近若干轮**，更早的按天收起：`9 月 16 日 · 第 7 期 · 41 轮`，点开才看。
- 后端**按需读**：一段会话不再整个文件解析出来（用户那条已 1.0M），
  走「先读需要的部分、要更多再往上翻」——`read_session_listing` 已经是这个路子。

## 5. 一期怎么走（棒跟产物走）

```
你 ──「开工」──▶ 王海燕 获取信息
                    │
                    ▼
              吕老师 选题定调 ──▶【 你点头 】
                    │                   │
                    │             （不点头就停在这）
                    ▼
              小宋 梳理成稿 ──▶ 你 交付
```

- **棒跟产物走**：料落盘 → 吕老师；选题点头 → 小宋；成稿落盘 → 这一天就走完。
  不是用户点「交给…」，也不是模型自己宣布交了棒。
- 开工第一棒是王海燕。选题没点头，下一棒不接。
- 要跳步或加料：说话点名桌上的人（「海燕再补两条」）。点了两个就不猜。

### 5.1 教学回路：它得先学会你

**「停下来问你」和「学你」是两件事。** v1 的打断只留两处：选题点头、
真出事（料实在不够）。但**教学不受这个限制——任何时刻都能教**，
不必等站在某个审批点上。少问、多记：把「要不要」的打断压到最低，
把「你说过什么」的吸收做到最大。

为什么这件事是主线而不是加分项：**这活要能交付，前提是标准能成；而标准只能从用户身上长出来。**
产品写不死——吕老师那套选材标准，是 2026-09-15 从**一个样本**反推出来的初稿
（当事人自己交代过：样本量=1，比例不可当精确分布）。往下每一版，都得靠你教。

**两个载体**

| 载体 | 是什么 | 归谁 | 例子 |
|------|--------|------|------|
| **我们的标准** | 这个项目组的活文档：选什么、不选什么、怎么排、怎么念 | **项目组** | 公告吃 1/3；数字前置；风险信号优先 |
| **我的手艺** | 某个人物的口径与做法 | **那个人物** | 雨天的审稿口径；王海燕的采集纪律 |

规矩：

1. **随时可教**：你的一句纠正 → 落成标准或手艺的一条。**不点头不落盘**（沿用既有规矩：
   「它记得的」里你点头才留下）。
2. **有版本、有出处**：每条标准记「什么时候、因为什么、谁说的」，能回看、能改、
   改错了能退回上一版。
3. **按最新版干活**：每期开工时人物读的是**当版**标准，不是你最初那版。
4. **教了要看得见**：出活之后你能看出**它这期是按哪一版标准干的**。
   看不见，你就没法判断它到底学没学会——这条是教学能不能持续的前提。
5. **人物不因为「在组里」就变成同一个人**：标准是共享的，手艺还是各归各的（§4.2）。

## 6. 「决定」要有自己的载体（现在没有）

选题单**不是文件，是决定**。现在系统只认文件，所以
「当时为什么改成那样」永远翻不到（用户真实吃过这个亏）。

这张桌子上要你点头的决定**只有选题单**。审稿意见仍是引擎认得的一种类型
（雨天工位上用），**不在这三步里、不在这张桌上**。

规格定死：

- 一份决定有：**谁定的、什么时候、定了什么、因为什么**，四样缺一不可。
- 决定落在项目组的期目录里，与产物同寿；同时进项目组记忆（可被检索、可被翻旧账）。
- 界面上一眼可读：选题单是一张清单（哪几条进、什么顺序、每条为什么进）。
- 用户读的那份正文**按三板块分段**（宏观 / 产业动态 / 资本市场）：**一条新闻一组、一组固定三行**——
  `ID ｜ 来源` / 这条新闻是什么（一句话）/ 为什么播它（角度与侧重）；板块里有几条就写几组。
  三板块之后是弃稿台账。

## 7. 授权与名册（v1 默认，可改）

- 项目组 **v1 内置**（不占授权码）：谁都有这一个组。
- 成员是人物，仍然各受授权码控制。
- 桌上三人里，吕老师 / 小宋当初是为这栏目立的岗；扫地僧是工位、不坐这张桌。
  授权码归属沿用既有约定。
- 已下线的林碳小谢、具身智能小金会让**老码出现「不认识的 id」**（不静默，`personas.md` §4.3），
  需要重发码。

### 7.1 组里缺人怎么办 —— **②：组要凑齐，缺谁显示缺席**（2026-09-16 用户拍板）

**规则**：项目组的编制是产品定的（3 人）；**码里有谁，组里就有谁**。缺的人**显示为缺席**，
不假装有人在，也不悄悄藏掉：

- 组内那一格：`缺席 · 需要「主编吕老师」`（灰的、不可点、不可 @）。
- 项目组那一行小字：「这组缺 1 人」——一眼能看出跑不起来的原因。
- 缺席时不硬跑：**该步没人接就停在那**，并说清缺谁、从哪得到（授权码）。
- 只有**全部到齐**，一组才会自动起跑（v2）；v1 由你点。

**拒绝的两条**（写下来免得以后又捡回去）：

1. **组内成员不受码控制** —— 演示最顺，但不买也能用，绕开了卖人物的模式。
2. **静默省略缺席的人** —— 用户会以为这活就该这么干，永远不知道缺了谁、该买什么。

**配套**：另发一个「财富早知道全套」测试码（3 个成员全包），供自己测试与演示用。

## 8. 明确不做（v1）

- 定时 / 自动起跑（到点自己跑、自己流转）——**这是 v2**，且要等 v1 被跑熟。
- 数字人与成片：终点是一份**能直接读的书面稿**，录制在系统外。
- 项目组之间互相喊话、跨项目组检索。
- 组内自动指派（谁该干活由模型自己判断）。
- 人物定义的「项目组专用变体」（同一个人在不同组里是同一个定义）。

## 9. 验收清单（用户语言）

1. 侧栏能看到「财富早知道」，点进去是一个会话，不是一堆会话。
2. 会话里每条消息看得出是谁说的；产物以卡片出现，点开能看全文。
3. 「开工」→ 王海燕出料 → 吕老师报题，**我能看到这份选题单，并在这里点头**。
4. 点头之后，成稿出现。
5. 料齐了、点了头、稿出来了，下一棒自己接，我不点「交给谁」。
6. 别人问起时：项目组自己的记忆（三道门、同日竞争八步）在组内人人可见，
   而小宋的写作习惯**不会**跑到别人头上。
7. 翻旧账：问「上周三为什么把半导体压在末尾」，翻得到（可以慢，但**要告诉我它在翻**）。
8. 会话很长时不卡：过期内容默认收起，历史按天分层，加载不随条数变慢。
9. 我一天不在，那一期就停在原地，**不会自己往下走**。
10. **我随时能教**：随便哪一步、哪一句纠正，说完就落成标准或手艺，
    不必等站在某个审批点上；落没落盘，我当场看得见。
11. **标准本身看得见**：有哪些条、什么时候加的、因为什么；能改、能退回上一版。
12. **看得出它按哪一版干**：这一期的活是按当版标准做的，不是按最初那版。
13. **不串味**：我教雨天的东西不会变成小宋的口径；只有我说「这条是全组的标准」才归组。
14. 下线的三个人不再出现在侧栏和组里；老码里若有他们，提示一句「有 1 个角色这个版本不认识」，
    **不静默**。

## 10. 风险与回滚

| 风险 | 处理 |
|------|------|
| 项目组会话无限增长 | 压缩 + 按天归档 + 后端按需读（§4.4）；三者缺一都会退化 |
| 记忆归属判错（手艺被判成组、标准被判成人） | 判不准归组；「它记得的」可改归属；出问题能被看见 |
| 标准被教歪 / 越教越长 | 有版本、有出处、可退回；条数可见、可合并；界面不鼓励无限堆积 |
| 教了没反应（用户怀疑它没学会） | 教完给一条安静回执 + 出活时标明「按哪一版干的」（§5.1 规矩 4） |
| 多说话人会话把硬拦搞松 | 每个成员仍是自己的定义与边界，越界照拦（§2.3） |
| 用户不再自己盯着 | 停下来等你点头是**特性**，不是 bug；v2 才谈自动 |
| 回滚 | 项目组是新增的一种会话；关掉入口即回到「只有工位」，已有数据不受影响 |

**是否构成方向变更：** 判断为**否**——它展开的是 P0 的「Do / Continuity」与既有人物规格
（「一个搭子，几顶帽子」再加一张「一张桌子，几个人」），不新增品类、不改用户主路径
（桌面 GUI · 对话 · 本地明文）。若你认为这算新品类，**先升 P0**，再动本规格。
