## 1. 一句话

**用户打开 App，看见的是"我的那几个工位"，不是一张空白对话。**
每个人物是一个**常驻会话 + 一顶有职责边界的帽子 + 一份自己的专业记忆**；名单与设定由**产品方**定，随**授权**开放。

一句话关系：**一个搭子，几顶帽子。**

## 2. 用户看到什么

### 2.1 侧栏

```
┌────────────────────────────┐
│ 乐彼AI   你的AI团队            │
│                            │
│ 工位                        │  ← 授权开放（在本机授权名单里的才出现）
│ 情报王海燕   窗口内的资讯，按名单采… │
│ 产业专家扫地僧 热闹我不看，我看门道   │
│ 主编吕老师   播什么，我把着          │
│ 记者小宋    写出来要能直接读       │
│ 编辑雨天    错在哪，我指给你       │
│ 主播小雨    念得顺，才算写好       │
│ ──────────────────────────  │
│ 项目组                      │  ← 一件事一条会话，日复一日（`projects.md`）
│ 财富早知道   一天一期，盘前         │
│ ──────────────────────────  │
│ 工位（自带 · 谁都有）            │
│ 工具人李现在  你卡在哪，我带你走一遍  │
│ 资料员小文   东西给我，先存住       │
│ 大导演      你走过的路，我帮你记    │
│                            │
│ 对话 / 它记得的 / 设置          │
│ 我的搭子                     │
└────────────────────────────┘
```

**排序规则**：授权角色在前、自带角色在后；两组内部按定义注册顺序。

- **没有「最近对话」**，也**没有「+ 新对话」**（用户不建会话）。
- 工位由「内置定义 + 签名授权名单」决定，**不随时间沉底**。
- 每行：`名字 · 一句话身份`。那句来自人物定义的 `role`，写的是**他是谁**，不是**他干什么**。
  职能由**名字**承担（情报王海燕、编辑雨天、主播小雨……），边界由正文「我干什么 / 我不干什么」承担。
  写成对仗标语就输了——那是墙上的价值观，不是一个人。

### 2.2 主路径（改前 → 改后）

| | 改前 | 改后 |
|---|---|---|
| 打开 App | 一个空白对话 + 最近对话列表 | **几个工位** |
| 我是谁 | 不明显 | 顶部一行「情报王海燕 · 今天的事，今天给你」（**已落地** 2026-09-15，见 §2.6） |
| 输入框 | 固定提示语 | 跟着人物变（「给情报王海燕：林碳相关的事」）——**未做** |
| 新活 | 自己建会话、自己找 | 找对应工位；找错了有路可走（见 2.3） |

### 2.3 越界与交接（专职人物）

```
你：帮我把这篇新闻稿改一下
编辑雨天：这不是我这摊——我只审稿。要写稿找小宋，要口播找小雨。
     [ 去找记者小宋 → ]
```

- 拒绝**必须说清去哪**，且指向的人物必须**在这个客户的授权里**。
- 兑现方式是**名册**（**已落地** 2026-09-15）：人物块里列出**本机开着的其他工位**
  （`名字 · 那句自述`，与侧栏逐字一致），并写死「指路只能从这份名单里挑，名单里没有就说没有，
  **不许自己编一个工位名字**」。名册由 `hermes_core::persona::open()` 出——它与侧栏读同一个
  `personas.json`、同一个判据，所以**侧栏有谁，名册里就有谁**。
  在这之前模型手上没有真名单，只能从唯一看得见的名字（技能索引）里挑，于是把技能名
  `xiao-wang` 当成工位指给了用户。
- 「去找记者小宋」是**按钮**：点了才切；模型自己不跳。
- 切换时**你刚才那句话跟着过去**，并标一行「从编辑雨天那边转来」。

### 2.4 三种人物类型

| 类型 | 谁 | 越界时 |
|---|---|---|
| **专职** | 全部在册工位（情报王海燕、产业专家扫地僧、主编吕老师、记者小宋、编辑雨天、主播小雨、资料员小文、工具人李现在、大导演） | **硬拦** + 指路 + 可一键切 |

**「兜底」这一类今天是空的。** 定义结构里 `kind: fallback` 还在（不删口子），但**搭子小乐已于 2026-09-15 暂时下线**：
「什么都接」的工位没有边界，越界硬拦对它无从谈起，实测里它最容易替别人下结论。
下线的方式是 `personas/xiao-le.md` 里一行 `retired: true`——**定义留在仓库，从名册里滤掉**，
恢复就是删掉那一行。在它回来之前，每个工位都必须拦得住、指得清。

**已下线（定义留在仓库，`retired: true`）**：林碳小谢、具身智能小金（2026-09-16）、搭子小乐（2026-09-15）。
下线含义：不进名册、不进授权码可写名单、名下记忆回落全局；**指路也不许再指向他们**（有测试守着）。

### 2.5 空 / 载 / 错态

- **空态**：工位没内容时用它自己的一句引导（一人一句，写在人物定义里）。
- **载态**：首次开着工位等待时用既有载态；不新增假进度条。
- **错态**：一键切失败 → 一句人话 + 原按钮还在。**不喊红叉**（沿用 2026-09-13 约定）。
- **名册里有我不认识的 id** → 设置里一行「有 1 个角色这个版本不认识」。**不静默**（见 4.3）。

### 2.6 顶部那一行写谁（2026-09-15 落地）

顶栏**不写会话标题**，写**你现在在跟谁干活**：`人物名 · 职责`。

- **有工位** → `情报王海燕 · 今天的事，今天给你`；点侧栏换工位，顶栏立刻跟着换。
- **没有工位的会话**（人物落地之前的老会话、别的渠道进来的会话）→ 退回**这一段对话的主题**；
  主题还是默认值时给产品名。**任何情况下都不回「新对话」**——用户不建会话、不挑标题，
  那三个字是一句没有信息的话。
- 一个工位 = 一段连续的对话。所以某一次的历史标题**不上顶栏**：它和"这段现在正在聊什么"迟早打架。

## 3. 人物模型

### 3.1 定义放哪

**编译进二进制**（与搭子身份协议、内置提示词同一种做法），**不落到数据根**。
理由：定义是**产品设定**，不是用户数据；单一真源、不会被改坏、也不诱导用户以为"这是个我能改的文件"。
透明性由 P0 第二条（本地优先）覆盖的是**用户数据**——会话、记忆仍然全部明文在本机。

### 3.2 字段

```yaml
id: sao-di-seng        # 授权码里引用的就是它（稳定、不复用）
name: 产业专家扫地僧
aka: [扫地僧]           # 别人指路时怎么称呼它（`name` 之外的简称）
                        # 下线之后这份名单就是禁区：活的定义正文里不许再出现
role: 热闹我不看，我看门道  # 侧栏那行一句话
voice: 话少，只说分量        # 人设的"怎么说"，含拒绝时怎么说
skills: []              # 绑定的技能；未绑定的一律不广告（这是"硬"的主要手段）
                        # 例：情报王海燕写 skills: [xiao-wang]（已有资产，不重造）
                        # 专属角色若还没有对应技能，就留空——交付时连同角色一起做
kind: dedicated         # dedicated（专职，硬拦）| fallback（兜底，不拦；今天没有在册的兜底角色）
builtin: false          # true = 自带角色（谁都有，不进授权码；其会话产生的记忆算全局）
retired: false          # true = 暂时下线：定义留着，但不进名册（侧栏没有、授权码发不出）
empty_hint: 哪条消息要我称一下分量？给我原文或链接。
version: 0.1.0
# 正文：干什么 / 不干什么 / 口径 / 越界怎么拒绝并指路（具体清单，不写抽象口号）
```

`builtin: true` 一个字段服务两条规格：① 谁都有（不进授权码，见 §4.2）；② 其会话产生的记忆算全局（见 §5.2）。
不这样做，「是不是自带」就会散落成代码里写死的 id 判断。

可选的 `tools_deny`（不该有的工具）**只留口子，v1 不实现**。

## 4. 名单来自授权

### 4.1 机制

产品做 N 个角色 → 客户端只有一个二进制 → **授权码里写这个人开哪几个**（id 列表）→ 输码后客户端只把那几个开出来。

### 4.2 三个自带不在码里

「工具人李现在」「资料员小文」「大导演」是地基，**谁都有**；码里只放**授权角色**。
码里没写它们 ≠ 它们消失。下线的角色（今天的搭子小乐）同样**不是**授权对象——它只是暂时不存在。

### 4.3 未知 id：忽略，但不静默

我们下架角色、或发错 id 时：客户端**忽略**该 id，并在设置里显示「有 N 个角色这个版本不认识」，同时写一条日志。
静默的后果是客户以为买的东西没生效，而我们完全不知道。

### 4.4 显示只认签名名单

- 名单来自**签名授权**；手改本机文件**不能凭空多出一个角色**。
- 能改的只有"已经开放那个角色的说法"——这不拦（自己的机器），但**名册不以本地为准**。

### 4.5 已知取舍（接受）

只出一个二进制 → **没买的角色定义确实在本地二进制里，逆向可挖**。接受它：角色设定不是核心机密，值钱的是"给谁配了哪几个"；且**显示与执行只认签名名单**。
不可接受的唯一替代是"一个客户一个编译版本"——不运营，否决。

### 4.6 授权码兼容

`LicensePayload` **没有** `deny_unknown_fields`，故**保持 `LEBI1.` 前缀**：加了 `personas` 字段后，老版本客户端读到新码只是忽略该字段、继续可用，不会失效。
码变长无感：3 个 id 约 +80 字符。

预留（v1 不做）：码里再带一组「内联自定义角色」，给以后卖定制留门。

## 5. 记忆归属

### 5.1 一根新轴

`MemoryFrontmatter` 加 `owner: Option<String>`：

- **空 = 全局**（关于用户本人的偏好、标准）
- **有值 = 属于某个人物**（专业口径），或**某个项目组**（这个栏目的标准）

今天所有已有记忆天然是"全局"——**零迁移**，且方向正确。

一组 owner 里谁算数，由**会话**决定（判据只有一处 `hermes_core::persona::memory_owners_for`）：
工位会话 = `[本人物]`；项目组会话 = `[本项目组, 这一轮说话的人]`（说话人不在桌上就只算组）。
**顺序有意义**：第一个是「本会话自己」，越界写入被夹回它。详见
[`projects.md`](./projects.md) §4.2 / §13。

### 5.2 写入与注入

- 写入自动打标：在谁的会话里说的就归谁，`memory_save` **不需要模型自己填**。
- **例外（三个自带角色）**：「工具人李现在」「资料员小文」「大导演」的会话里产生的记忆一律算**全局**。
  理由：它们是地基不是专业分工——若判成某个自带角色私有，
  「所有工位都遵守我的偏好」这条承诺就悄悄不成立了。**专属角色**的会话里才归该角色。
  已下线的角色（今天的小乐）不再持有记忆：`retired` 的 id 从名册里滤掉，归属自然回落到全局。
- 注入：人物会话只给「**全局 + 本人物**」，别人的一条都不给；项目组会话给「**全局 + 本项目组 + 说话人**」。
  判据是一处（`hermes_memory::visible_to_any`：`owner` 为空或命中这组 owner），装配口也只有一处
  （`views_for_any`）。
- 检索：默认只搜「全局 + 当前人物」；要看别人物，必须用户明确说，且先问一句。**跨人物不自动串味。**

### 5.2b 归属的口径与出处

「归谁」的判据是**换个项目还算数吗**：关于你本人的 → 全局；这个栏目的口径 → 项目组；
这顶帽子的手艺 → 那个人物。**判不准归项目组**（宁可窄）。

每条记忆可带 `because`（因为什么，落盘时从候选的 `rationale` 截取，可选、老文件缺栏照读）；
版本是 `supersedes` 链（`version_of` 数出来，防环）——**删掉新版，上一版自己回来**，
所以「退回上一版」不需要第二个状态字段。

### 5.3 反思分流

候选带 `owner`：**关于用户本人的 → 空；关于这份活的专业口径 → 当前人物**。
提示词必须明确要求，**测试必须覆盖**——一旦把用户偏好误挂到某人物名下，那条偏好就只在一顶帽子里生效，是明确的产品 bug。

### 5.4 原则：注入隔离，管理可见

- 「它记得的」是**管理页**：每行一个归属标签（全局 / 林碳小谢 / …），筛选器加一项；管理页新建的记忆**默认全局**。
- 主题 tab 顶部加归属选择器（全局 / 林碳小谢 / …），默认「全局」。

### 5.5 与主题卡的关系

主题卡按**可见范围分区**：全局一份 + 每个**授权角色**各一份（自带角色用全局那份，不额外生成一套卡），
卡的成员**只从它可见的记忆里取**（林碳小谢的会话里不会冒出金子的卡）。
与 2026-09-14 已定的"卡是派生视图、随时可重建"一致；成本只发生在点「整理」时。

### 5.6 在办 / 我的材料 / 产出：只记出处，不隔离

这三样属于**用户**，不属于人物（否则林碳小谢用不了小王留下的材料）。
在办条目上记"哪个人物做的"，回顾时能说清谁干的。一句话：**记忆是"归属即隔离"，这三样是"只记出处、不隔离"。**

## 6. 硬拦三层 + 人设红线

### 6.1 三层

**① 稳定层**：`role` + 正文（干什么/不干什么/口径/越界怎么拒绝并指路）+ `voice` 写进**会话级系统提示**。
位置**固定在搭子协议之后、记忆与卡之前**——人物只能**叠加**在 `companion.rs` 之后，**永不覆盖**。顺序写成实现断言。

**② 不给执行路径**（"硬"的来源）：
- **主要手段 = 技能面收窄**（**已落地** 2026-09-15）：人物在定义里**写了 `skills`**，就只广告名单里的技能；
  林碳小谢的系统提示里**根本没有** `xiao-wang`。
- **「没写」≠「写了空的」**：没写 = **不收窄**（这一层没做之前的行为，逐字节相同）；
  写空名单 = 只剩内置元技能。用 `Option<Vec<String>>` 区分两者——用空 `Vec` 会让
  「谁都没绑技能」的那天所有技能一起消失。今天只开了两个工位收窄：工具人李现在、大导演。
- **收窄的例外**：**内置元技能**（`memory-palace` / `skill-creator` / `find-skills`）**永远保留**——
  它们是搭子的底层纪律，不属于任何专业领域；剥掉会让人物会话失去记忆纪律。
  判据是 `always_active` **或**在 `hermes_skills::BUNDLED_SKILLS` 里（后两个并没有标 `always_active`）。
- **技能不是工位**：技能索引段开头写死一句「这些是技能，不是工位」。
  用户自己装的技能很可能**就取着人名**（本机的 `xiao-wang` / `xiao-wang-2` / `xiao-wen`），
  不点明，模型会把它当成一个可以指过去的工位（2026-09-15 实测）。
- 次要手段 = 工具面收窄（`tools_deny`，v1 不做）。
- 交付路径**不按人物分**（接 5.6）。
- 判据只写一份：`hermes_channel::persona_scope::visible_skills`，GUI 与 CLI/IM 两条路都从这里取。

**③ 交接由用户点**：模型只能输出"建议交接"的结构化事件；切不切由用户点（见 2.3）。

### 6.2 误判

两种误判：该拦没拦（白设）、不该拦拦了（气人）。缓解三条：
① 人物正文写**具体清单**，不写抽象口号；② 拒绝必须指路且目标存在；③ 一键切让误拦代价降到"多点一下"。
**v1 不额外调一次模型做路由判定**（贵、慢、也可能判错）。实测误判多，再加轻量前置判定。

### 6.3 人设红线（可检查）

- **可以不同**：专业词密度、句式、怎么称呼用户、拒绝那句话怎么说。
- **不能不同**：关系基调（不讨好、不卖萌、不冷淡摆架子）、核心纪律（不撒谎、不装记得、有事说事）、**「接住 → 张力 → 选项 → 你定」**这套交互结构。
- **判据**：同一件事三顶帽子说法可不同，但**"它怎么待你"必须一样**。靠改变关系基调才成立的人物 → 是第二个人格 → **否决**。

## 7. 各入口边界

| 入口 | v1 | 说明 |
|---|---|---|
| **GUI**（默认路径） | 全量 | 工位侧栏、人物会话、硬拦 + 一键切、记忆归属、主题卡分区 |
| **server + Flutter** | **最小贯通** | 会话能带人物、能选人物、**归属必须写对**。不做则手机发的话落进"没有人物"的会话，把专业口径写成全局记忆——**数据会被写歪**，所以这条不是"顺手做" |
| **CLI** | `hermes chat --persona <id>` | 不指定 = 今天的行为，自然退化 |
| **IM（微信/飞书/TG）** | 渠道级固定一个人物 | IM 没有工位上下文；"群里那个机器人就是林碳小谢"很自然。**不在聊天里切人物** |

## 8. 首次 seeding 与迁移

### 8.1 顺序

配 Key → 验授权 → 按名单把定义**注册**进当前进程 → 工位出现在侧栏。

### 8.2 工位从定义来，不从会话文件来

侧栏工位由「授权 + 定义」决定；点进去**没有会话就新建一个空的**。
这样"用户把会话删了"不会让工位消失，避开"会话丢了工位就没了"这一整类 bug。

### 8.3 零迁移清单

| 数据 | 迁移动作 |
|---|---|
| 记忆 | 无（没有 `owner` = 全局，天然正确） |
| 主题卡 | 无（现有全局卡仍覆盖全局记忆；人物卡首次点「整理」才生成） |
| 在办 / 材料 / 产出 | 无（只多一个"出处"，旧条目为空） |
| 技能 | 无 |
| 旧会话 | **不迁移**：文件一条不动，界面不再有入口（**已确认**，见 10.10） |

## 10. v1 明确不做

1. 不做人物管理界面（用户不能增删改人物）。
2. 不做"自动判断这活归谁"的第二次模型调用。
3. 不按人物裁工具面（只留 `tools_deny` 口子）。
4. 不做人物级数据隔离（在办/材料/产出只记出处）。
5. 不做自动交接（必须用户点）。
6. 不在 IM 里切人物。
7. 不做人格（只做口吻调味，红线见 6.3）。
8. 不动 `companion.rs` 的身份协议（只叠加）。
9. 不改部署形态：单机、本地明文、无账号、无云同步。
10. **不主动删用户数据**：旧会话只在界面上消失，文件留在磁盘；要删由用户自己动手。

## 11. 验收清单（用户语言）

1. 装好打开，侧栏就有「工具人李现在」「资料员小文」「大导演」，不用我建；
   对话区是一句问候，不自动替我开一段对话。
2. 输授权码后，**多出来**我买的那几个工位，并且有一步可见的提示。
3. 点林碳小谢进去，顶部写着「林碳小谢 · 盯林碳」，输入框提示语跟着变。
4. 我在林碳小谢这里问"帮我写篇新闻稿" → 它不写，告诉我该找具身智能小金，**旁边有个按钮能直接过去**。
5. 点那个按钮过去，我刚才那句话还在，并标着"从林碳小谢那边转来"。
6. 在林碳小谢这儿教的林碳口径，去具身智能小金那儿**问不出来**；反过来也一样。
7. 但「它记得的」里我能看到全部，并且每条标着属于谁。
8. 我教过关于**我自己**的偏好（比如交付要 Word 放桌面），**所有工位都遵守**。
9. 我的旧会话不见了入口，但**东西没丢**（谁也没删我的文件）。
10. 授权过期 → 点进工位被拦住；**人物不消失**。

## 12. 风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 硬拦误判（该拦没拦 / 不该拦拦了） | 具体清单 + 必须指路 + 一键切（代价降到一次点击）；实测不行再加前置判定 |
| 归属写歪（把用户偏好挂到某人物） | 反思提示词明确规则 + 测试覆盖（5.3） |
| 人物多了卡变多、token 上涨 | 卡按可见范围分区，只在点「整理」时生成；上限沿用既有 `MAX_CARDS` |
| 逆向可挖未购买的角色的定义 | 已知取舍（4.5）；显示只认签名名单 |
| 技能面收窄误伤（该有的技能看不见了） | 收窄只关**广告**，不关能力：技能还在磁盘上、还能用 `skill_read` 读到。真要放开，把人物定义里的 `skills:` 删掉即回到不收窄 |
| 名册指到一个用户没有的工位 | 名册取的是**本机开着的**（授权 ∩ 勾选 + 自带），与侧栏同源；测试盯住「自己不进名单」「空名册要说实话」 |
| 回滚 | 名单视为空 → 只剩三个自带；下线的角色删掉 `retired: true` 即回来；记忆 `owner` 字段留着不影响旧行为；旧会话文件始终在磁盘上（界面入口需一并回滚） |

## 13. 实施分期建议（非本文强制 · 供出实施计划用）

| 阶段 | 内容 | 用户可见 |
|---|---|---|
| **1 · 地基** | 人物定义结构；`SessionMeta.persona`；`MemoryFrontmatter.owner`；归属注入 / 检索；反思分流；主题卡分区。用 CLI `--persona` 先验 | **否**（引擎先通，界面未动） |
| **2 · 授权即名单** | 授权 payload 加 `personas`；显示只认签名名单；未知 id 不静默；发码工具 | 输码后能看到"开放了哪几个" |
| **3 · GUI 形状** | 侧栏改造（去最近对话 / 去新对话、工位常驻）；工位会话 seeding；顶部一行与输入框提示语；管理页归属标签与筛选 | **是**（这一阶段之后产品形状就变了） |
| **4 · 硬拦与交接** | 人物块入稳定层（顺序断言）；技能面收窄；建议交接事件；一键切（转话标记 + 失败态） | **是** |
| **5 · 其它入口** | server/Flutter 最小贯通（**归属必须写对**）；CLI `--persona`；IM 渠道级固定人物 | 手机侧 |
| **6 · 收口** | P0 升 v0.12 并同步 AGENTS / P1 / 检查 README；版本号 1.4.0（4 处 + lockfile）；真机目视 | 是 |

**每阶段各自** clippy / fmt / test 全绿 + 台账更新；**阶段 1 是唯一"用户看不见"的阶段**，其余每阶段结束都应可目视。
