# 操作规格 · GUI 字号与层级

> **种类 D**（操作规格）。服从 P0 v0.11。冲突以 P0 为准。
> 落地记录：[`../records/20260918-gui-type-scale-and-phase34-ux.md`](../records/20260918-gui-type-scale-and-phase34-ux.md)

---

## 1. 为什么要有这份规格

字号在 GUI 里曾经是**每人一拍**：`text-[10px]`、`text-[11px]`、`text-[12px]`、
`text-[13px]`、`text-[14px]`、`text-[15px]` 与 `text-xs` / `text-sm` 混着用。
结果是两层损失：

1. **读不清**——二级内容落到 10–11px。汉字在这个尺寸上已经不是「小」而是「看不清」，
   再配上 `#94a3b8` 的淡灰，等于把信息做成装饰。
2. **没层级**——10 和 11 差 1px 没有语义，却让每一屏自己长出一套节奏。

**结论：字号是层级，不是参数。** 一份界面只有三档 + 标题；定义只有一处。

---

## 2. 档位（唯一来源：`index.css` 的 `@theme`）

| 档 | 类名 | 值 | 用在哪 |
|----|------|-----|--------|
| **正文** | `text-app-body` | 15px | 消息正文、卡片主句（记忆一条、材料一条、回执主句） |
| **二级** | `text-app-sub` | 13px | 要读的句子：身份小字、`因为：…`、状态说明、筛选项、工具卡描述 |
| **三级** | `text-xs` | 12px | 角标 / 计数 / chip / 时间戳 / 快捷键提示 |
| 标题 | `text-base` / `text-lg` / `text-xl` | 16 / 18 / 20px | 页面标题、空态问候语 |

**控件文字（按钮、导航项、输入框、tab）用 `text-sm`（14px）**——它们不是「内容层级」，
是操作面，保持 14px 不动。

### 2.1 硬性禁止

- GUI 内**不得**出现 `text-[10px]` / `text-[11px]`。12px 是角标的下限。
- GUI 内**不得**为「正文 / 二级 / 三级」另写 arbitrary px（`text-[13px]` 之类）。
  需要新档 → 先改这份规格，再加 token。
- 消息正文与卡片主句**不得**用 `text-app-sub`（13px）——正文就是正文。

### 2.2 颜色配套

| 档 | 颜色 |
|----|------|
| 正文 | `text-app-fg` |
| 二级 | `text-app-fg-secondary`（`#64748b`）。**不要用 `tertiary`**——12–13px 的灰字必须能读 |
| 三级 | `text-app-fg-tertiary`（`#94a3b8`）允许，但只用于角标类信息 |

### 2.3 行高

- 正文：`leading-relaxed`（1.625）起，消息正文用 `prose-chat` 的 1.65。
- 二级 / 三级：`leading-snug` 或 `leading-relaxed`，**不许**默认（会挤在一起）。

---

## 3. 怎么改字号

1. 先问「这句话是**内容**还是**操作面**」——操作面留 `text-sm`，内容进三档。
2. 内容再问「用户**必须读**吗」——必须读 → 二级（13px）；扫一眼就够 → 三级（12px）。
3. 改完 `rg 'text-\[1[0-9]px\]' ui/src` 应当只剩**规格允许的类型**；字号类任意值应为 0。
4. 密集区（左侧栏工位行、期条、标签行）改完必须目视——字号变大会挤。

---

## 4. 现状核对（每次改动后自查）

```bash
cd crates/hermes-gui/ui/src
rg -c 'text-\[1[0-9]px\]' .            # 应为 0
rg -n 'text-\[(9|10|11)px\]' .         # 应为 0
```
