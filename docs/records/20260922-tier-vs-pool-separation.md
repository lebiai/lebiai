## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「多写一句提醒模型别搞混」（提醒不是约束，模型在长上下文里对「别搞混」这种软话最不敏感）；不是「干脆把两套合成一套分级」（合成会把两件不相干的事绑死：站点属性 vs 公告重要度）。
- **拆出的真：**
  1. **两套分级回答的是两个不同的问题。** 采集端的 `【官方／主流／其他】` 回答「这条从**哪个站**来」（→ 只决定要不要再找一个来源）；公告池的 `A／B／C／D` 回答「这条公告**有多重**」（→ 决定进池还是进主稿）。同一篇文章可以既来自「主流」站、又是 A 级公告 —— **两轴正交**。
  2. **挨得近的分级天然会被拿来换算。** 两套都是「字母/词 + 等级感」，模型在压缩上下文时最容易做的动作就是「【官方】≈ A 级」。所以光写「是两套东西」不够，得**把禁止的动作点名**：不许换算、不许互相标注、不许自己补。
  3. **每一端各自看得见自己那一半。** 王海燕看得到层级、看不到公告池；吕老师两边都看得到。所以**两端都要写**，只写一端等于给另一端留了想象空间。
- **如何从真推出：**
  ① 王海燕端：把「别混」升级为——两套体系、永不许互相套用；**她这一端不许出现 `A／B／C／D`**；下游也不许把 `【官方】` 当重要性；
  ② 吕老师端：`【官方／主流／其他】` 定性为**站点属性**，不参与入选 / 排序 / **公告池分级**；新增一条独立的禁止项——不许拿层级换算等级、不许拿等级改层级、不许把层级写进公告池、缺了不许自己补；
  ③ 用断言把两端都钉死（含一条反钉：采集端契约不许出现 `【A／B／C／D】`）。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 看《选题单》点头的人；以及要接手这两份契约的人。
- **解决什么痛点：** 两套分级现在只靠一句话隔开，模型一旦把 `【官方】` 读成「A 级」，后果是**排序和入选被一个与重要性无关的站点属性污染** —— 用户看到的稿子会莫名偏向官方来源，而理由在台面上看不见。
- **用完后用户多得到什么：** 采集端永远不出现公告池的字母；吕老师那条「只交 ID / 只判重要性」的链路不会因为一个站点标签被带偏。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库

  - [x] 主操作一眼能找（不变）
