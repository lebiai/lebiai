## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：**
  1. **不是**「界面调一下就好看」——把字号一个个改大是把症状抹平：下一屏组件照样各写各的
     `text-[11px]`，三个月后又长回来。**要定的是层级本身，不是这一屏的字号。**
  2. **不是**「归谁等点头之后告诉你」——用户做决定的那一刻，看不到决定的对象。
     事后 toast 是**报账**，不是**知情**。
  3. **不是**「把折叠条做得更明显一点」——它现在在时间线顶部，而长会话永远停在底部：
     问题不是它不好看，是**它在屏幕外**。加粗、变色都救不了一个看不见的东西。
- **拆出的真：**
  1. **字号是层级，不是参数**：一份界面只该有「正文 / 二级 / 三级」三档，且**只有一处定义**。
     现在的 10/11/12/13/14/15px 是 6 个人各拍一次的结果。
  2. **中文有下限**：11px 的汉字在 1x 屏上已经要凑近看，10px 是装饰不是信息。
     二级内容的实际门槛是 **12px（角标）/ 13px（要读的句子）**。
  3. **决定之前要给判据**：`owner` 在入队时就已算好（`InboxItem::session_owner` +
     `MemoryCandidate::owner`），只是没送到界面上。**判据已有，缺的是送达。**
  4. **第 4 期做的是「可发现」，不是「可见」**：折叠条要能在**不滚动**的情况下被发现。
- **如何从真推出：**
  - 层级写进 `@theme`（单一来源），页面只许用三档；`text-[10px]`/`text-[11px]` 在 GUI 里**清零**。
  - `list_pending_review` 带回 `ownerId` / `ownerName`（判据仍**只走**
    `candidate::owner_for` + `memory::owner_label`，不新写一份）；卡片上写「会归到：X」。
  - 时间线顶部做**常驻**一行「更早的日子」（sticky），点开才列那几天——常态一行，永远在视口里。
  - 「退回上一版」从图标 `title` 升成**看得见的文字按钮**（规格 §9 第 4 条要的就是点它）。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 桌面 GUI 用户（默认路径），日复一日在《财富早知道》和几个工位里干活的人。
- **解决什么痛点：**
  ① 二级内容 10–11px + 淡灰（`#94a3b8`），汉字要凑近看；字号没有层级，整页看起来「糊」；
  ② 点头那一刻不知道这条会归到哪个工位/项目组——归属只在事后 toast 里闪一次；
  ③「退回上一版」找不到（只有鼠标悬停的 title）；旧账为什么不能改，没有一句话说；
  ④ 长会话里根本不知道更早的日子还能翻——折叠条在屏幕外。
- **用完后用户多得到什么：** 读得清（三档层级 + 二级色提深）· 点得准（点头前知道归谁）·
  找得到（「更早的日子」常驻一行）· 少一次返工（退回上一版看得见）。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期
  - [x] 不增加无意义确认或噪音
  - [x] 主操作一眼能找；空/载/错态完整
  - [x] 高频路径步骤少、界面干净

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户在工位/项目组会话里干活；在某一步点头让搭子「记住」。
- **怎么走完：**
  - **字号**：不用走——每一屏都受益。用户**先看见**的是同一屏里主次分明、不用凑近看。
  - **归属**：「它记得的 → 待确认」卡片第一行是这句话，第二行是「会归到：情报王海燕」，
    再往下是 出处 / 标签 / 确认 主按钮。**点确认之前**归属就在眼前。
  - **第 4 期**：进工位 → 时间线顶部**常驻**一行 `更早的日子 · N 天`；
    点它 → 展开列出每天（`9 月 15 日 · 12 轮对话`）；点某天 → `正在翻…` → 展开旧账，
    旧账上方一行灰字「**旧账只能看，不能改**」。
- **看起来怎么样：**
  - 层级只有三档：**正文 15px / 二级 13px / 三级 12px**；标题另算（`text-base` 起）。
  - 二级内容颜色从 `tertiary(#94a3b8)` 提到 `secondary(#64748b)`——12px 的灰字也要能读。
  - 空态 / 载态 / 错态沿用现有四态（收起 / 正在翻 / 展开 / 读不出来），不新增状态。
- **好走 / 好看：** 步骤只少不多；归属与退回都把「藏在 title 里的东西」搬到面上。
- **成功标准：** 把 GUI 里 `text-[10px]`/`text-[11px]` 数到 0；点头卡片一屏内看得到归属；
  不滚动就能发现「更早的日子」；`退回上一版` 是文字按钮而不是图标。
- **明确不做什么：** 不重画信息架构 · 不改导航 · 不做主题换色 · 不动引擎与记忆判据 ·
  不引入字体文件（继续用系统字体栈）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：**
  1. **设计 token 缺失**：`index.css` 只定义了颜色/圆角/阴影/动效，**没有字号**，
     于是每个组件用 arbitrary value 自己拍。→ 层级必须进 `@theme`。
  2. **命令面漏字段**：`InboxItemView` 没有归属。归属的**判据已经在**
     （`candidate::owner_for` + `session_owner`），只是没序列化出去。
  3. **折叠条位置**：它是**流内**元素（`ChatView` 时间线首个子节点），
     而滚动容器初始停在底部 → 结构性不可见，不是样式问题。
- **正确的长期默认路径：**
  - 字号：`@theme` 三档 token（`--text-app-body` / `--text-app-sub` + Tailwind `text-xs`），
    组件只用 token；arbitrary px 字号在 GUI 内**禁止**。
  - 归属：`list_pending_review` 复用**同一个判据**算一遍归属并回传；
    界面只显示，不算。**判据仍然只有 `hermes_memory::resolve_owner` 一处。**
  - 折叠条：汇总行 `position: sticky` 在时间线顶部，常驻；展开的日期列表是它的下拉，
    不再随时间线滚走。
- **与引擎/各入口边界：** 只动 `hermes-gui`（命令面 + UI）与一处 `@theme`。
  引擎判据（`resolve_owner` / `visible_to` / `owner_for`）**不碰**；
  server / CLI 的窗口化遗留项不受影响。
- **安全影响：** 无。归属 id 是本机人物/项目组标识，本来就在本机明文里。
- **如何防复发：** 层级写进 spec（[`../spec/gui-typography.md`](../spec/gui-typography.md)）
  并给出禁止项；`text-[1Xpx]` 一旦回到 GUI 就是违规。
- **为何这不是补丁：** 三条都是把「本来该在的地方」补上——层级进 token、归属进命令面、
  折叠条进视口；没有一处是针对某个组件的特判。

## 1. 方案（Plan）

- **目标：** 字号只有三档且读得清；点头前知道归谁；不滚动就能发现「更早的日子」。
- **范围：**
  - **做**：`index.css` 的 `@theme` 字号档 · GUI 内 `text-[10px]`/`text-[11px]` 清零 ·
    消息/卡片正文 15px · 二级色提深 · `InboxItemView` 加 `ownerId/ownerName` ·
    待确认卡显示归属 · 「退回上一版」做成文字按钮 · 时间线顶部常驻「更早的日子」·
    旧账加「只能看」一行 · 规格文档。
  - **不做**：重画 IA / 导航 / 主题换色 / 引擎判据 / 字体文件 / server 与 CLI 的窗口化。
- **用户路径变化：**
  - 待确认卡：`一句话 + 标签 + 确认` → `一句话 + **会归到：X** + 出处 + 标签 + 确认`
  - 长会话首屏：`…看不见折叠条…` → `顶部常驻一行「更早的日子 · N 天」`
  - 记忆卡：`…第 2 版（图标 title 里藏着退回）…` → `第 2 版 + **退回上一版**（文字按钮）`
- **技术要点：**
  - `crates/hermes-gui/ui/src/index.css`（`@theme`）
  - `crates/hermes-gui/ui/src/components/**`（字号替换 + 三处结构改动）
  - `crates/hermes-gui/src/commands/inbox.rs`（`InboxItemView` + 归属字段）
  - `crates/hermes-gui/ui/src/types` / `store`（`InboxItemView` 类型、DayFold 汇总态）
  - `docs/spec/gui-typography.md`（新 · 种类 D）
- **风险与回滚：** 字号放大可能挤坏密集区（EpisodeBar / Sidebar / 标签行）。
  回滚 = 单文件 revert；token 留在 `@theme` 不影响旧类名。

## 2. 实施（Implement）

- **实际改动摘要：**
  1. **字号层级进 `@theme`**（`index.css`）：`--text-app-body` 15px / `--text-app-sub` 13px，
     三级沿用 `text-xs` 12px；`.prose-chat`（消息正文）跟着 `--text-app-body` 走。
  2. **GUI 内 arbitrary 字号清零**：`text-[10px]` 与 `text-[11px]` 共 107 处按「角标 → 12px /
     要读的句子 → 13px」逐条改；`text-[12px]`、`text-[13px]`… 同步收进档位。
     二级内容颜色由 `tertiary(#94a3b8)` 提到 `secondary(#64748b)`（12–13px 的灰字要能读）。
  3. **卡片主句抬到正文档**：记忆卡正文、材料卡名称、待确认候选正文、用户气泡、
     在办列表标题 → `text-app-body`（15px）。
  4. **点头前看得见归属**：`InboxItemView` 加 `ownerId` / `ownerName`（`item_to_view` 里用
     `candidate::owner_for` + `memory::owner_label`，与落盘同一判据）；待确认卡上写
     「会归到：财富早知道 / 全局」。技能候选不带归属。
  5. **待确认卡的决定写成字**：孤立的 ✓/✗ 换成「接受 / 忽略」两个文字按钮。
  6. **「退回上一版」升成可见按钮**：原来只在垃圾桶图标的 `title` 里；现在第 N 版旁边有一颗
     带图标的文字按钮。同一个确认弹层（`confirmAction{id,revert}`）服务删/退回两个动作。
  7. **「更早的日子」常驻视口**：时间线顶部 `sticky` 一行——只有一天时这一行就是那一天，
     多天时先汇总（`更早的日子 · N 天 · M 轮`），点开才列那几天；展开的旧账回到流内，
     上方一行「旧账只能看，不能改」。
  8. **归类判据收成一处**：`companionGroup` / `memoryGroupLabel` 从 `MemoryPanel` 抽到
     `utils/memoryGroup.ts`，记忆卡与待确认卡共用（待确认卡原来直接把 `standards` 这种
     原始 zone 显示给用户）。
  9. **顺手修的挤坏**：侧栏页脚的授权 chip 改成可换行（原来被裁成「不足 1 …」）；
     项目组的「缺人」提示给两行（警示态不许被裁在字中间）。
  10. **目视时抓到的一处真错**：点「退回上一版」后，确认弹层的主按钮写的是「删除」——
      用户按的是「退回」，看到的却是「删除」，会不敢按。`ConfirmPopover` 本来就有
      `confirmLabel`，记忆卡没传。补上（按什么，按钮就写什么）。
- **关键路径/文件：**
  - `crates/hermes-gui/ui/src/index.css` · `utils/memoryGroup.ts`（新）
  - `crates/hermes-gui/ui/src/components/**`（字号替换 + 结构改动）
  - `crates/hermes-gui/src/commands/inbox.rs`（归属字段 + 3 条测试）
  - `docs/spec/gui-typography.md`（新 · 种类 D）
- **偏离方案处：**
  - 方案里「单条折叠条」与「多天汇总」是两件事，实现时合成一个组件分支（只有一天时
    汇总行就是那一天），少一次点击，也不多一套状态。
  - 方案没预料到 `resolve_owner` 在**工位**会话里对 `standards` 判到全局（既有规矩）。
    写归属测试时踩到，改用「手艺」那一档，并把「判到全局 → 不带字段」单独钉了一条。
    这是**测试用例选错**，不是产品行为改动。

## 5. 附注

### 自查用的预览桩（`scripts/preview-ui/`）

桌面 GUI 是 Tauri 壳，前端全部走 `window.__TAURI_INTERNALS__.invoke`，直接开 `ui/dist`
只会白屏。`scripts/preview-ui/`（`mock.js` + `serve.mjs`）把 IPC 桩掉，让同一个前端
能在浏览器里渲染出来做目视。

- **它是开发工具，不是产品入口**：不连后端、不落盘、数字全是写死的。
- **它不能当功能验收**，只能看布局 / 层级 / 空载错态 / 只读性。
- `mock.js` 里每条桩**必须照 Rust 侧真身的形状写**。写错形状看到的是渲染崩溃，
  不是界面——本期就踩了三次（`list_personas`/`list_teams` 该回数组、
  `list_commitments` 该回 `{items}`、`get_config` 少 `providers`）。
- 参考截图（本机 `/tmp`，非仓库产物）：`t4-days-open.png`（更早的日子展开）、
  `t7-memory.png`（会归到：…）、`u1-cards.png` / `u2-dom.txt`（第 2 版 + 退回上一版）。
