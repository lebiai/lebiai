## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：**
  - 不是「先把审计清单打勾」。
  - 不是「空画布挂一个输入框，像聊天工具那样就能说话」。
  - 不是「底栏再留一个对话按钮，免得用户找不到聊天页」。
- **拆出的真：**
  1. 用户要完成的是：打开 → 选人 → 开口干活。没选人时没有工位，就没有对话。
  2. 谁说了算：P0。授权过期锁的是发模型请求的能力；贴码出口在桌面（本机验签）。
  3. 代码已经在 `LicenseGatedProvider` 上锁全部入口；说明书还写「命令行和手机不走这道门」——用户会按说明书理解，对不上。
  4. 空态问候写「说一句就开始」，输入框却不挂；「在办」芯片点了抽屉也不开。
  5. 侧栏工位已经是对话入口；底栏再放「对话」是第二个家。
- **如何从真推出：**
  - 真 2+3 → 升 P0 授权句与代码同词，README 跟着改。
  - 真 1+4+5 → 问候改成「点左边的人」；空态不挂输入框、不挂在办；底栏只留「它记得的 / 设置」。

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 打开桌面 → 选工位 → 说话；或试用到期后续期。
- **怎么走完：** 打开看见工位名单 + 一句「点左边的人，开始干活」→ 点一个人 → 输入框出现。到期：桌面全屏锁可贴码；CLI/手机报错指向桌面。
- **看起来怎么样：** 空态只有问候，没有假芯片、没有第二个「对话」按钮。失败：人话，不是「新建或选择对话」。
- **好走 / 好看：** 主操作就是侧栏的人；少一个底栏入口。
- **成功标准：** 不读说明书能选人说话；到期知道去桌面贴码。
- **明确不做什么：** 不做越界一键切（C）；不做 Flutter 工位（D）；不拆 `LicenseGatedProvider`。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 产品法与代码不一致；空态把「会话」当主对象，而工位才是。
- **正确的长期默认路径：** 授权立法 = 引擎门禁；对话入口 = 工位列表；空态不创建无身份会话。
- **与引擎/各入口边界：** 不改门禁实现；不改 server/Flutter 能力矩阵。
- **安全影响：** 无新出口；密钥仍 0600。
- **如何防复发：** P0 定义卡写「所有入口」；底栏不再列「对话」。
- **为何这不是补丁：** 法与主路径收敛到同一默认，不是给空态加 if。
