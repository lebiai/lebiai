## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「把字号调小让它挤进一行」，也不是「加一个 `whitespace-nowrap` 硬撑」。
- **拆出的真：** 标题与说明之间的那道换行，在页头什么信息都没多给，只多占一行高度。
  这道换行是**固定写死的结构**（`<h1>` 之后接 `<p>`），不是内容需要分行 ——
  两句都很短（4 字 + 25 字），并排读是一句话的读法：**先说要紧的，再补一句口气**。
- **如何从真推出：** 把结构从「上下两块」改成**同一行的两段**（`flex` + 基线对齐 + 小间距），
  宽度不够时**整句**落到下一行 —— 不裁切、不在句子中间断开。这样一行是默认形态，
  窄窗口是退化形态，不存在「硬撑到溢出」。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 每天开「它记得的」看它记住了什么的人。
- **解决什么痛点：** 页头白占一行；标题和说明被拆成两行，读起来像两条不相干的信息。
- **用完后用户多得到什么：** 页头少一行，标题与口气连读，视线不动就看完。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 不增加确认或噪音
  - [x] 窄窗口有退化形态（整句落到下一行，不裁切）
  - [x] 高频路径更短（页头一行）

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户点开「它记得的」，先扫一眼页头确认这是哪儿、这里的规矩是什么。
- **怎么走完：** 页头第一行即 `它记得的  你点头之后留下的偏好、标准和做法。不点头，不落盘。`
  —— 标题深色、说明浅色，同一条基线；下面紧跟三个 tab。
- **看起来怎么样：** 同一行的两段，靠字号与颜色分层，不靠换行分层；
  窗口变窄时说明整句移到下一行，仍是完整一句。
- **好走 / 好看：** 视线一行读完；tab 位置比改动前上移一行。
- **成功标准：** 默认窗口下页头只有一行文字。
- **明确不做什么：** 不改文案；不改字号；不动三个 tab；不动其它页面的页头。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 结构层 —— 页头把「标题」和「一句口气」写成两个块级元素，换行是结构造成的，
  不是宽度造成的（实测：改前在 1280×828 窗口下说明本身并没有折行）。
- **正确的长期默认路径：** 两段放同一个 `flex flex-wrap items-baseline` 容器里，
  行内默认、窄了整段下沉；删掉原来的 `mt-0.5` 与 `max-w-xl`（前者是换行的另一半原因，
  后者是给独立段落准备的宽度上限，行内不需要）。
- **边界：** 只动 `ui/src/components/know/KnowPanel.tsx` 的页头；引擎、命令、数据都不动。
- **安全影响：** 无。
- **如何防复发：** 这是视觉规格，靠目视与构建；不引入测试（无逻辑可测）。
- **为何这不是补丁：** 补丁是「缩小字号」或「`nowrap` 硬撑」；这里是**结构归位**：
  一行本来就不该是两个块。
