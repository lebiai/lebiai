## 0-fp. 第一性原理

- **拒绝的类比：** 不是「主编拍脑袋挑几条、写张单子」的老帽子；也不是把旧定义修修补补
  （旧帽子只有三行「定选题 / 定排序 / 报题」+ 一句「料不够不硬加」，没有取舍标准、
  没有弃稿规则、没有固定框架——下游拿到的是偏好，不是判据）。
- **拆出的真：** 这一岗要解决的是「**写什么、不写什么、怎么写、重点在哪**」四个问题，
  且必须**可回查**。所以它至少要有：一套入选判据、一套弃稿判据、一个固定的内容框架、
  一条「弃掉的也要写明为什么」的留痕规则，以及一份能直接拿去撰稿的产出物。
  谁来定：吕老师定；谁点头：用户；数据在哪：《选题单》落在组里的当天期目录。
- **如何从真推出：** 帽子正文按「判据 → 框架 → 流程 → 留痕 → 报题」重写；四项权责
  （绝对决定权 / 定调权 / 框架定夺权）写死在「我干什么」；「不点头就停在这」保留，
  因为它是全流程唯一必停的一步（P0 / `projects.md` §5）。

## 0. 用户价值

- **谁用：** 点吕老师，或《财富早知道》第二棒。
- **解决什么痛点：** 旧帽子下，取舍是临场偏好——同一条新闻今天进、明天不进说不出为什么；
  弃掉的条目事后翻不到理由；整期调性与板块结构没有硬约束。
- **用完后用户多得到什么：** 一份**可回查**的《选题单》——哪几条进、什么顺序、各占多少秒、
  每条什么角度，外加一份**弃稿台账**（每条弃稿注明落在五条标准里的哪一条）。
  用户否掉一条时，下一棒能看到改的是哪条判据，而不是重猜一遍。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库（仍是帽子 + 一份文件）
  - [x] 步骤可感知、可预期（五步固定）
  - [x] 不增加无意义确认或噪音（唯一必停仍是点头那一步）
  - [x] 主操作一眼能找；空/载/错态完整（沿用原帽子的口径）
  - [x] 高频路径步骤少、界面干净

## 0b. 产品经理视角

- **场景：** 用户在《财富早知道》里说「开工」，海燕交完料，棒到吕老师。
- **怎么走完：** 他通读整份料 → 按六条入选标准挑、按五条弃稿标准砍 → 归三板块、
  资本市场再拆 A 股 / 港股 / 上市公司资本运作 → 给每条定角度与秒数、给每条弃稿写理由 →
  落盘 `outputs/<日期>/选题单-<日期>.md` 并记成 `decision`（`kind: topic-list`，items 按播出顺序）→
  **报给用户点头**。不点头，棒停在这。
- **看起来怎么样：** 对话里他给结论（出哪几条、为什么、砍了哪些），界面上一张选题卡等点头；
  全文在文件里。弃稿台账在《选题单》末尾，不是另开一个界面。
- **好走 / 好看：** 用户不需要记六条标准——判据在他的口径里，用户只需要点头或否掉某条。
- **成功标准：** 用户能只凭这份《选题单》就让小宋写稿；否掉一条后能看出改的是哪条判据。
- **明确不做什么：** 不加新界面、不加新工具、不做投资建议（定选题不是荐股）、
  不把「点头」改成自动流转。
