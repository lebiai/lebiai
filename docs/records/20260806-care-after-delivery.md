## 0. 用户价值

完成**任意工作交付**后，伙伴可在主交付之外给最多 1～3 条贴合用户的可执行改进；不话痨、可定稿关闭。

## 0b. 产品经理

- **场景：** 用户要完成一份工作产出（方案/复盘/改写/计划/代码小结…任意）  
- **路径：** 先交完整结果 → 可选「可改进」短块 → 用户可忽略或说定稿  
- **成功：** 体感「适合我 / 有来有回」；非每句鸡汤  
- **不做：** 不做公众号专用；不第二轮强行 LLM Care API  

## 0c. 架构师

- **根因：** Care 仅有薄协议，模型易漏做或乱做  
- **正确路径：**  
  1. 协议写清「时刻」不是「品类」  
  2. 用户像要交付时 system 追加 Care reminder  
  3. write/edit 工具成功后注入 Care nudge 到下一轮  
  4. 定稿类语句关闭 Care  

## 2. 实施

| 文件 | 内容 |
|------|------|
| `hermes-core/companion.rs` | Care 协议扩展；`should_nudge_care_*` / `care_after_tools_nudge` |
| `hermes-turn` | write/edit 成功后注入 nudge |
| GUI/Server/CLI context | 交付向用户句追加 Care reminder |
| CLI system_prompt | 输出风格对齐 |

## 4. 手测（任意工作，非绑场景）

1. 「帮我写一份本周工作复盘」→ 先完整正文，再可选改进点  
2. 「定稿，不要建议」→ 只有交付，无 Care
