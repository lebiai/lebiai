## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「别的聚合器也只给标题」，不是「模型不够聪明、换个模型就好」，
  也不是「再加几个站点就丰满」——加站点只会让 148 条薄条目变成 200 条薄条目。
- **拆出的真：**
  1. 一卷资讯的价值不在条数，在**每条能不能让人当场判断**。判据就是那四样：
     主体 · 时间 · 核心事实 · 关键数据。缺一样，这条对下游（选题/成稿）就是废的。
  2. 概要之所以薄，**不是站点没有内容，是采集从没打开过文章页**：
     抓的是列表页，而列表页上只有标题。实跑卷里 45 条宏观 **100%** 是标题级，
     因为央行 / 发改委 / 中国政府网的列表页确实只有标题——但它们的**正文页**有全文。
  3. 列表页上还有两样被我们扔掉了：
     ① **每条文章的真实 URL** —— 引擎把站根相对链接 `[标题](/a/b.html)` 原样交出去，
        下游拼不出可点地址，于是写栏目页地址或干脆不写（卷里 6 条「无链接」）；
     ② **Next.js 把正文放在 `<script type="application/json">` 里** —— 被清洗时整块删掉，
        于是「抓得到、抽不到」（上海证券报可见 965 字 vs JSON 里 2047 字；财联社 3644 vs 11310）。
  4. 「拿不到」和「没读到」是两回事：同一份卷里，证券时报首页有当天条目、券商中国有 3 条，
     子代理却交了 **0 条**——静默跳过和真的没有，在文末那个数字里长得一模一样。
- **如何从真推出：**
  1 → 契约加一条硬规则「**先读，再写**」：概要用正文写；写不出正文的条目不许上卷。
  2/3 → 引擎侧**一处修全局**（不是在名单里给每个站打补丁）：
     相对链接按页面 URL 绝对化；`application/json` script 里的中文串作为兜底正文。
  4 → 每个站点必须交「拿了 n 条 / 本页无当天条目」，**静默跳过算事故**。

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户在《财富早知道》里说「开工」，王海燕采完当天资讯，卷摆到用户眼前。
- **怎么走完：** 用户看到的还是同一份三栏卷、同一个格式（**批 3 已经定好的那三行没有变**）：
  等级 · 来源 · 时间 / 完整概要 / 原文链接。区别只在**每条读得完**：
  概要里出现的是事实与数字，而不是「页面未披露」。
- **看起来怎么样：** 条目数会**变少**（例行公告被过滤、标题级条目被剔除），但剩下的每条都站得住。
  文末统计多一句实话：本轮进正文多少条、只读到列表页多少条、几个站拿不到。
- **好走 / 好看：** 用户不用学任何新动作；规则全在采集这一棒内部。
- **成功标准：**
  - 薄条目（概要汉字 < 60）占比从 90.2% 降到 **< 20%**；
  - 东方财富公告里程序性文件占比从 68% 降到 **< 15%**；
  - 点名 7 家媒体里，**页面上确实有当天稿的站不许交 0 条**；
  - 无链接 / 截断链接 **= 0 条**；
  - 成稿字数落进 120 秒规格（≈540 字，±20%）。
- **明确不做什么：**
  - 不做无头浏览器（另一批的事）；不改三栏结构与条目三行格式；不改时间窗口规则；
  - 不为省时间给「进正文」设条数上限（要全量，但**只对写不出内容的条目**进正文）；
  - 不做 GBK 解码（批 5）、不做记忆归属（批 5）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级（三条，各自分层）：**
  1. **引擎 · 清洗层**（`crates/hermes-tools/src/web_fetch.rs`）：相对链接不绝对化 +
     `application/json` script 被整块删除 → 链接缺失与 Next.js 站「抽不到」。
  2. **提示词 · 采集契约层**（`crates/hermes-core/src/personas/wang-hai-yan.md`）：
     契约只要求「列条目」，没要求「读正文」；子代理因此从不打开文章页，静默跳过也不留痕。
  3. **产品定义层**（`crates/hermes-core/src/teams/caifu-zaozhidao.md` + 人物）：
     「盘前两分钟」是口号，没有任何一处把它变成字数/秒数约束。
- **正确的长期默认路径：**
  - 引擎负责「**把网页变成可信的文本 + 可信的链接**」——这是能力，不是某个站的特例；
    修一处，所有 Next.js 站（现在与将来）一起好，名单里不再需要为每个站写特例。
  - 采的人负责「**先读后写**」：先拿列表页定位，再对要上卷的条目并发打开文章页，概要用正文写。
  - 栏目规格必须是**可数**的：120 秒 → 540 字，写进团队与人物定义，选题时按秒分配。
- **与引擎/各入口边界：** 引擎改动落在 `hermes-tools`（`web_fetch` 是四个入口共用的能力），
  不 fork 平行逻辑；提示词改动落在 `hermes-core` 的人物/团队定义（编译期 include_str!）。
- **安全影响：** 无新增网络出口（还是同一个 `web_fetch` + SSRF 校验）；无新增依赖；
  JSON 兜底只读页面自带的 script，不绕登录、不逆向签名接口。数据仍本地明文。
- **如何防复发：**
  - 引擎两条改动各带单测（相对链接绝对化 / JSON 兜底 + 「不足 300 汉字不拼接」）；
  - 契约里把「静默跳过」定义成事故：每站必须交「拿了几条」；
  - 用户语言测试按上面的成功标准逐条量（薄条目占比、程序性文件占比、0 条站点、坏链接数、成稿字数）。
- **为何这不是补丁：** 三条根因各自只改一处：清洗层改「怎么变成文本」，
  契约层改「先读后写」，产品层把口号变成数字；没有为任何单个站点写特例。

## 1. 方案（Plan）

- **目标：** 让卷里每一条都写得出「主体·时间·核心事实·关键数据」，链接可点，站点不静默跳过。
- **范围：**
  - **做（5 件）：**
    1. **引擎 · 相对链接绝对化**：`href/src` 按被抓页面 URL 解析成绝对地址（`url` crate 的 `join`）。
    2. **引擎 · JSON 兜底**：`<script type="application/json">`（含 `__NEXT_DATA__`）里的中文串
       作为兜底正文（抽 ≥300 汉字才拼，上限 12,000 字符）。
    3. **契约 · 先读后写**：第二棒对「写不出内容的条目」并发打开文章页；不许用
       「页面仅列标题 / 未披露」当概要；每站必须交「拿了 n 条 / 本页无当天条目」。
    4. **契约 · 公告过滤**：东方财富公告只留实质事件（重组/收购/定增/减持/回购/立案/退市/
       重大合同/业绩预告/控制权变更/重大风险），例行披露（章程/独董意见/法律意见书/
       股东大会通知/董事会决议/保荐书/中签率/投资者关系记录/盘中停牌）一律丢。
    5. **产品 · 时长可数**：团队与人物定义写死「120 秒 ≈ 540 字」，选题单每条带秒且合计 ≤ 120。
  - **不做：** 无头浏览器；GBK 解码；记忆归属；三栏/三行格式变更；给站点点名「拿不到」。
- **用户路径变化：** 改前「标题卷 → 用户自己猜」；改后「读得完的卷 → 用户当场判断」。
- **技术要点：** `crates/hermes-tools/src/web_fetch.rs`、`crates/hermes-core/src/personas/wang-hai-yan.md`、
  `crates/hermes-core/src/teams/caifu-zaozhidao.md`、`personas/{lv-lao-shi,xiao-song,xiao-yu}.md`。
- **风险与回滚：**
  - 「进正文」可能拉长采集墙钟（批 2 已把采集段压到 ~128s）。**实跑量一个数**；若超过可接受范围，
    回退到「只对写不出完整概要的条目进正文」的更小集合（契约里已经是这个措辞）。
  - JSON 兜底可能让普通页面变胖 → 用「≥300 汉字才拼」+ 12,000 字符上限挡住，并有单测。
  - 公告过滤可能误杀真事件 → 判据写「宁留勿杀」，且文末统计报出被丢条数，方便回查。
  - 回滚：三条改动互不依赖，可分别回退（引擎改动有单测守着）。
- **方案确认：** [x] 已对照 P0/P1（含第七条）· 2026-09-21 用户点单「批 4 开始吧」

## 2. 实施（Implement）

**2.1 引擎 · 一处修全局**（`crates/hermes-tools/src/web_fetch.rs`，零新依赖）

| 改动 | 落点 | 说明 |
|---|---|---|
| 相对链接绝对化 | `absolutize_urls` + `rewrite_relative_url` + `next_url_attr`（`web_fetch.rs:262/311/339`） | 用 `reqwest::Url::join` 按**被抓页面 URL** 解析；`http/https/mailto/tel/data/javascript/#` 原样过；解析失败保留原值，无 `unwrap`。签名加 `base`（`web_fetch.rs:223`，调用点 `:127`） |
| JSON 兜底正文 | `embedded_json_text` / `json_script_bodies` / `collect_json_strings` / `han_count`（`:371/:398/:417`），常量 `:216/:219` | 只认 `type="…/json"` 或 `id="__NEXT_DATA__"` 的 script；抽中文字符串（≥8 字符且 ≥4 汉字、去重、去标签）；**≥300 汉字才拼**、上限 12,000 字符 |
| 顺序 | `clean_html_to_markdown`（`:223–248`） | **先捞 JSON → 再删 script → 再绝对化 → 再转 markdown**，绝对化永远不碰那坨 JSON |

**2.2 契约 · 先读后写**（`crates/hermes-core/src/personas/wang-hai-yan.md`，0.8.0 → 0.9.0）

- 新增「**第二轮：进正文**」一节：列表页只用来定位；写不出「主体·时间·核心事实·关键数据」的条目，
  在**同一条回复里**把文章页 URL 一次性发出去取正文；抽不到正文的条目**丢掉**。
- 子代理契约：不再只要求「列条目」，改为「概要只能来自正文」「链接必须是这一条自己的文章页完整地址」
  「交卷要带**每站回执**（站名=条数，0 条要写为什么）」。
- 红线加两条：**不准拿列表页顶上卷**（出现「页面仅列标题/未披露」即算事故）、**不准静默跳过站点**。
- 「拿不到怎么算」把三种情况分开：本页无当天条目 / 抽不到正文 / 工具报错；文末数字只数后两种。
- 东财公告按接口自带的 `columns[].column_name` 过滤：只留实质事件，例行文件一律丢（宁留勿杀）。
- 主循环那条 `bash` 里的 `awk` 改成：**没有 http 链接或链接重复的条目自动丢弃**（点不开的不如没有），
  统计行加「进正文写概要 k 条」。

**2.3 产品 · 时长可数**（`teams/caifu-zaozhidao.md` + `personas/{lv-lao-shi,xiao-song,xiao-yu}.md`）

- 「盘前两分钟」落成数字：总时长 ≈ **120 秒**，按 **4.5 字/秒** ≈ **540 字**（含开场收尾的全文）。
- 吕老师选题单每条**必填秒数**、全期合计 ≤ 120 秒；超了不许报单。
- 小宋按秒数写（每条 ≈ 秒数 × 4.5 字，全文 ≈ 540 字 ±20%）；小雨口播化不改长度、自数字数（±10%）。

- **偏离方案处：** 无。（方案里「3b 修好」一项在实跑中发现新根因：抽取撞输出上限就放弃 →
  追加一处「抽取加预算重试一次」，见 §3 与 §4 遗留。）
