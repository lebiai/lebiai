## 0-fp. 第一性原理

- **拒绝的类比：** 不是任务 App 的「开工先填验收标准」。
- **拆出的真：**
  1. 人点「开始做」= 要开口做事。交差标准可空，不能挡这一步。
  2. 「等别人 / 拆开」是改一条债的次要动作。藏在看不出的「编辑」里、还没有标题，等于没给。
- **如何从真推出：** 开始做只预填对话输入框。等别人 / 拆开在点「改」之后，各自一块、先写再点。

---

## 0. 用户价值

- **谁用：** 桌面 GUI 用户
- **解决什么痛点：** 点开始做不知道那个框要填什么；按测试说明找不到等别人 / 拆开
- **用完后用户多得到什么：** 开始做立刻能发；改一条时能看见并完成等 / 拆
- **好用性自检：** 不增确认墙；主操作一眼能找

---

## 0b. 产品经理视角

- **场景：** 空对话看见「还有 N 件在办」→ 点开始做。右上角在办 → 点改。
- **怎么走完：**
  - 开始做 → 下方输入框出现「开始做：测试的」，自己按发送
  - 改 → 先改标题/期限；下面一块「等别人」（先写等谁再点）；一块「拆开」（两行再点）
- **看起来怎么样：** 不再弹出「完成算什么？」空框。改里两块有小标题。
- **成功标准：** 不问就懂开始做去哪了；按「改」能点到等别人和拆开
- **明确不做什么：** 不把等/拆做成每条常驻第四、五个主按钮；不自动发送「开始做」

---

## 0c. 架构师视角

- **根因层级：** 操作规格被做成拦路表单；次要动作没有标题
- **正确的长期默认路径：** Cue / 点标题共用预填。pendingStart 删除。改面板分块。
- **与引擎边界：** 只动 GUI 与 `zaiban-work.md` 5.3。落盘字段不变。
- **如何防复发：** 规格写明开始做不问完成算什么
- **为何这不是补丁：** 默认路径改成「开始 = 预填；改 = 等/拆」，不是给空框加说明

---

## 1. 方案

- **目标：** 开始做不拦；等别人 / 拆开找得到
- **范围：** ZaibanCue、ZaibanBlock、zaibanStore、i18n、zaiban-work.md
- **用户路径变化：** 开始做后直接进输入框；编辑改名为改，里面两块有标题
- **风险与回滚：** 不再收集「完成算什么」这一下。可空，可接受。
