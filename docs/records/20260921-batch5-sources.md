## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「这几家反爬、没办法」，不是「模型不够聪明、换个大模型」，
  也不是「再加几个站把窟窿补上」——那是拿新站掩盖旧站没读通。
- **拆出的真：**
  1. 一个站交 0 条，只有三种可能：**(a) 入口错**（打错站 / 打错页）、**(b) 读到了但抽取不可靠**、
     **(c) 编码不对**。三种都能逐条证伪，不该靠猜、也不该写成「站点异常」了事。
  2. 本轮侦察证明**三种同时存在**：
     - **入口错**：名单给北交所的那条 `https://www.bse.cn/api/disc/announcement/annList?seDate=…`
       **根本不存在** —— `bse.cn` 下任何未知路径都返回同一张 4858 字节 404 页；那条 `seDate`
       接口是**深交所**（`www.szse.cn`）的，被抄到了北交所名下。正确入口
       `disclosureInfoController/companyAnnouncement.do` + `startTime/endTime` 实测**当天 62 条**
       （有绝对日期、有 PDF 链接）。
     - **入口错（第二种）**：同花顺名单入口是门户首页 `www.10jqka.com.cn`，那页**本来就没有当天列表**
       （`arc-title` 0 个、无绝对日期）——所以「0 条」是**正确但无用**。当天列表在
       `news.10jqka.com.cn/today_list/`（一页 25 条，带「09月21日 HH:MM」），但它是 **GBK**。
     - **抽取不可靠**：第一财经首页里明明有 **653 处「2026-09-21」**，抽取第一次被推理吃光
       （`stop=MaxTokens`、正文回空串），第二次直接回了错的「本页无当天条目」。
       财联社同一页 18:30 复测能抽出 13 条（页面当时更小）——**同一处根因**：大页 + 推理吃预算。
     - **编码**：同花顺 news 站（以及被删的汽车之家）是 GBK，引擎一律按 UTF-8 解 → 乱码 → 抽取必空。
  3. 「拿不到」和「**看漏了**」必须能被区分：抽取回「本页无当天条目」时，要用**确定性**办法核一遍
     （页面里到底有没有当天日期）——核得上就按「拿不到」记一笔，不许当「本页无当天条目」交卷。
- **如何从真推出：**
   1 → 每个 0 条站先按 (a)(b)(c) 三问证伪，再决定改名单还是改引擎（本批六站全部走完）。
   2 → 改两处：**名单里错的三条入口改对**；**引擎侧把大页抽取与字符集两件事一次修好**（不是给站打补丁）。
   3 → 契约里加一条可执行的核验动作，并把主循环的条目格式校验补上。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级（各一处）：**
  1. **名单层**：两条入口是错的 —— 北交所抄了深交所的接口名（`bse.cn/api/...` 根本不存在）；
     同花顺用了门户首页（那页没有当天列表）。
     （上海证券报整版相对时间、真列表在 `api.cnstock.com` —— 但它在用户定稿的**删除名单**里，
     本批**不给它改入口、不采**，只记备查。）
  2. **引擎层（`hermes-tools`）**：① 无 charset 解码（GBK 页必乱码）；② 抽取把整页原文丢给模型，
     页面越大越容易「推理吃光预算 → 回空串 → 重试又遇到同一段 → 瞎答」。
  3. **契约层**：抽取回「本页无当天条目」时没有确定性核验，于是「看漏了」被当成「没有」。
  4. **引擎层（同日第二处根因，本轮实跑才暴露）**：识日期只认提示词里那一种写法。
     中国证券报首页当天 23 条稿子，日期**只**写在链接路径 `…/2026/09/21/detail_….html` 里，
     而提示词写的是 `2026-09-21` → `focus_count` 全 0 → 切窗切到页头导航、抽取回空，
     连「漏答判别」也一起失效（它同样靠 `focus_count`）。整站交 0 条，回执还写「本页无当天条目」。
- **正确的长期默认路径（含本轮补的第 4 条）：**
  - 识日期一律**同日多写法归一**（`-` / `/` / `.` / 中文 / 8 位连写），不信单一口径；
  - 名单只写**能拿到条目**的入口（列表/接口），并把「正文在哪」写清；
  - 引擎负责「**把网页变成可信文本**」：**先按 charset 解码**，再清洗；大页抽取**输入封顶 +
    回空时换一段**（同一段重复问没有信息增益）；
  - 「本页无当天条目」这类否定回答必须**可核对**（页面里数一遍当天日期）。
- **安全影响：** 无新增出口；新增入口都是公开页/公开 JSON 接口（不签名、不登录）。
- **如何防复发：** 引擎两条各带单测（charset、封顶与换段）；名单里每条入口都在本文件留下实测数字；
  契约把「抽不到但不核」定义成事故。
- **为何这不是补丁：** 三条入口是**事实错误**（打错站/打错页）不是特例逻辑；引擎两处改的是
  「怎么读网页」这个通用能力，六个站只是它的验证样本。

## 1. 方案（Plan）

- **目标：** 用户点名保留的站真的出得来东西；0 条必须给出可核对的原因。
- **范围：**
  - **做（5 件）：**
    1. **引擎 · 按 charset 解码**（`web_fetch.rs`）：读 `Content-Type` / `<meta charset>`，
       gb2312/gbk/gb18030 正确解码（一处修全局）。
    2. **引擎 · 抽取输入封顶 + 回空换段重试**：页面超过 12,000 汉字时只送「当天日期最密的那一段」；
       第一次回空 → 加预算 **并换下一段**（不再重复同一段）。
    3. **名单 · 四处入口改正**：北交所 → `companyAnnouncement.do`（当天 62 条）；
       同花顺 → `news.10jqka.com.cn/today_list/`（GBK，25 条/页）；
       财联社正文 → `/detail/<id>`（免签名）；36氪 → gateway `home/nav/rank/hot` + `newsflash/flow`。
       （**上海证券报不动**：它在用户定稿的删除名单里，不采 —— 侦察结论只作备查。）
    4. **契约 · 否定回答要核验**：抽回「本页无当天条目」时，用 `grep -c <当天日期>` 确定性核一遍；
       页面里确有当天日期 → 按「拿不到」记一笔（禁止当 0 条交卷）。
    5. **（实跑中补）引擎 · 同日多写法 + 抽取提示词**：识日期不只认提示词那一种写法；
       抽取系统提示词明写「日期常只在链接地址里」。（根因见 §0c 第 4 条、§4 实跑 1）
    6. **主循环 · 条目格式校验**：每条必须 `^【[ABC]】`；文末统计里条数 = A+B+C（上一轮出现 136 vs 135）。
  - **不做：** 绕 WAF/验证码；签名接口；新增站点；改格式与窗口。
- **已知取舍（诚实写）：** 36氪正文拿不到（火山引擎 WAF 拦在站点域，换 UA/Referer/m 站/`.json` 全试过）。
  默认按用户「36氪要保留」的意见处理：**只出快讯类条目**（用其快讯正文片段），并在回执里写明
  「36氪：正文被 WAF 拦，只用快讯」。若用户改主意 → 移出名单。
