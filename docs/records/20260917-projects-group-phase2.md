# 变更记录：项目组 · 第 2 期 —— 活跑得起来了（接力 / 决定 / 这一期）

> **For agentic workers:** 本文件同时是**实施计划**。按 `- [ ]` 逐条执行；每步都能单独验证。

**Goal：** 让《财富早知道》**从「一张桌子」变成「一条流水」**：
这一棒交得出去（**接力**）、唯一的必停点有载体（**决定 · 你点头**）、
这一期出了什么在会话里**看得见**（**这一期产物**）。

**Architecture：**
1. **接力** = 会话里的一条**事件**（`SessionEvent::Handoff`），回放成 `Session.flow.holder`；
   「谁在说」从此有第二个来源（默认 = 接口人，交出去 = 接棒的人）。
2. **决定** = 期目录里的**一份带头的文件**（`outputs/<日期>/…`）：**引擎写结构、人物写正文**。
   结构（谁定的 / 什么时候 / 为什么 / 清单 / 状态）由工具 `decision` 落笔，模型不许手写。
3. **这一期** = `outputs/<今天>/` 这个目录本身（不是第二套状态）。会话里那条带直接扫它。

**Spec：** [`../spec/projects.md`](../spec/projects.md) §5 / §6 / §4.3 / §9

## Global Constraints（每条任务都隐含遵守）

1. 中文主词用**「对话」**；关系词用**「搭子」**。
2. **期 = 日期目录**：`outputs/<YYYY-MM-DD>/`（产品既有默认，2026-09-13 起）。
   **不新建第二个产出根**，也不加组子目录——那会把同一栏目跨天的文件切成两种形状。
3. **判据只有一处**：「谁在说」= `persona::speaker_for(persona, team, holder)`；
   「这一期在哪」= 今天的日期目录。
4. **结构由引擎写，正文由人物写**：决定文件的头只能由 `decision` 工具写。
5. **不点头不落盘**（既有规矩）：决定是「待点头」，点头/要改由**用户**点，不由模型代劳。
6. 提示词顺序不变：**搭子协议 → 人物块 → 组块 → 在办 → base → 记忆与卡**。
7. 不新增依赖；根目录只允许 4 个 md。
8. **不提交**——等用户点头（本项目长期约定）。
9. 质量门槛：`cargo fmt --all -- --check` · `cargo clippy --workspace --all-targets -- -D warnings` ·
   `cargo test --workspace` · `tsc + vite build` 全绿。

## 0-fp. 第一性原理（本期）

- **拒绝的类比：**
  1. **不是**「把选题单当成一段聊天文字」——那样「谁定的 / 什么时候 / 因为什么 / 点没点头」
     四样全不存在，用户没法回头问「当时为什么这么定」，也没法点、没法改。
  2. **不是**「给项目组配一套审批系统」——那要有流程引擎、角色权限、状态机 DSL，
     是一个比产品本身还大的东西。v1 只有两种决定：**选题单**和**审稿意见**。
  3. **不是**「让模型自己写一段 YAML 头，我们再解析」——模型写的是给人看的正文；
     让它手写结构，总有一天产出半句话也能解析成「已点头」，那是灾难。
- **拆出的真：**
  1. **「活在哪一棒」必须能被记住**：换个人接，下一轮开口的就不是吕老师了。
     这条**不能只活在界面上**——关掉 App 再打开，还在谁手上不能忘。
  2. **「决定」和「产物」是一对**：决定是「据什么出的这一期」，产物是「出了什么」。
     两者同寿、同处一地，才有「翻旧账」的可能。
  3. **用户是流程里的一环，不是旁观者**：唯一必停点是选题点头；其余不停。
     所以界面必须**给得出那一下**（点头 / 要改），而不是让用户打字说「我同意」。
- **如何从真推出：**
  - 接力落成**会话事件**（跟 `Meta`/`Usage`/`Compaction` 同一层）：回放即状态，不必另存一份。
  - 决定落成**期目录里的文件**：结构与正文分离，由工具写头、由人物写身。
  - 「这一期」**不新造状态**：它就是今天的产出目录 + 里面的决定文件；界面读它，不复制它。

## 0. 用户价值

- **谁用：** 桌面 GUI 用户（默认路径）。
- **解决什么痛点：** 第 1 期之后，组里只有吕老师一个人开口——活跑不动：
  你不点就没人接、点了也没痕迹；出没出稿、审没审过、这一期有哪几件东西，界面上都没有。
- **用完后用户多得到什么：**
  ① 一句话交出去（`交给雨天`），**谁在手上看得见，说的是谁也跟着变**；
  ② 选题单是一张**能点的卡**（清单 + 为什么 + 我点头 / 我改）；
  ③ 会话顶部一条「这一期」，把这一期的产物与决定摆在一起，点开看全文。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库（决定就是一个 md 文件）
  - [x] 不需要用户做任何操作（没有在跑的活时，界面与第 1 期一模一样）
  - [x] 不增加确认或噪音（只有选题点头这一处停，且是你点的）
  - [x] 空 / 载 / 错态完整（空：今天还没有产物；错：决定文件读不动 → 当普通产物，不崩）
  - [x] 高频路径步骤数：交接 = 一次点击；点头 = 一次点击

## 0b. 产品经理视角

- **场景：** 早上进《财富早知道》，说一句「今天开工」→ 王海燕出料 →
  你点 `交给吕老师` → 吕老师报题，会话里出现**选题单卡** → 你点 `我点头` →
  点 `交给小宋` → 稿子出来 → `交给雨天` → 审稿意见卡（放行 / 打回 + 理由）。
- **怎么走完：** 会话头部写 `财富早知道` + 这一期位置；名册那一行右侧多一个 `交给…`；
  点开列出桌上的人（**缺席的灰掉、不可点**）。
- **看起来怎么样：**
  - 会话顶部（名册下面）一条**这一期带**：`这一期 · 2026-09-17` + `3 件产物`，点开列出文件与决定卡。
  - 决定卡是一张清单：`1. 央行开展 5000 亿 MLF · 40 秒`…，下面一行小字写**为什么这么定**，
    再下面一行是**谁定的 · 什么时候**；右下角两个动作 `我点头` / `我改`。
  - 点头后卡上那行状态从 `待点头` 变成 `已点头 · 14:05`，按钮消失（**不留假按钮**）。
  - 交出去之后，那条 `在谁手上` 就在名册里亮着；**下一句回复的名字也跟着换人**。
- **空 / 载 / 错态：**
  - 空：今天还没有产物 → 这一期带只显示 `这一期 · 今天还没有产物`（一条灰字，不摆空框）。
  - 载：沿用既有载态。
  - 错：决定文件读不动（人手工改过 / 半截文件）→ 它就是一普通产物，**不报红叉**。
  - 缺人：接力下拉里缺席的人灰掉并写明缺谁（第 1 期已定）。
- **成功标准：** 一句「开工」之后，**不用打字**就能把这一期推到「稿子已出」；
  关掉 App 再打开，**还在谁手上没变**；选题单点头前后，卡上的状态不一样。
- **明确不做什么：** 自动流转 / 定时起跑（v2）· 内联在时间线里的产物卡（要文件写入事件，留后）·
  决定的历史版本与回看（第 3 期教学回路）· 按天归档与翻旧账（第 4 期）· 跨组喊话。

## 0c. 架构师视角

- **根因层级：** 「这一轮谁在说」在第 1 期被写死成 **接口人**（`speaker_persona` 读了组就返回
  接口人）。只要没有第二个来源，接力就无处可落——而且**会话一旦重启就忘了**，
  所以接力必须是**落盘的事件**，不是内存里的一个字段。
- **正确的长期默认路径：** 接力是**事件流的函数**（`flow.holder`），决定是**文件的头**，
  「这一期」是**目录**。三者都不新增平行状态：界面渲染它们，不复制它们。
- **边界：** 动 `hermes-core`（`SessionEvent::Handoff` + `Flow` + `speaker_for`）·
  `hermes-store`（回放这一事件）· `hermes-tools`（新工具 `decision` + 注册表注入说话人）·
  `hermes-gui`（`hand_off` / `list_episode` / `answer_decision` + 侧栏档位 + 这一期带 + 交接下拉）。
  **不动**：`hermes-channel` 的提示词顺序、Flutter/IM 渠道（它们还没有组这一档）。
- **如何防复发：** ①**唯一判据**：`speaker_for` 是「谁在说」的唯一定义，
  GUI 里那份 `speaker_persona` 删除；②**回放可断言**：append→read 后 `holder` 必须一致；
  ③**决定头只由工具写**：解析失败时降级为普通产物，绝不猜。
- **为何这不是补丁：** 没有为《财富早知道》写任何特判——组还是数据，
  新增的是「事件流能表达接力」和「文件能表达决定」两条**通用**能力。

## 1. 范围

**做：** 接力事件 + 谁在说跟着变 · `decision` 工具与决定文件 · 这一期扫描 · 点头 / 我改 ·
 `交给…` 下拉 · 侧栏小字档位 · 测试 · 文档。
**不做：** 上面 §0b 那段。

**实施中的一处偏差（已记）：** 桌子的规矩里补了两条**事实**（`hermes-core/src/team.rs::block`）——
① 交棒是用户在桌边点的，模型交不出去、也不许假装交出去了；
② 出了决定要落成 `decision` 文件，不许只在对话里说一句。
不改提示词顺序、不给任何人物加职责，只是把「这张桌子怎么运转」写清楚；
没有这两条，模型会自己宣称「我把活交给雨天了」而其实什么都没发生（那是产品大忌）。
有测试钉住（`the_block_lists_the_table_and_marks_the_absent`）。
