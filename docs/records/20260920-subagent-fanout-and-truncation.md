## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是因为「别的产品都有多智能体」；不是把一个人物拆成五个更小的提示词；
  不是让模型在同一个上下文里「扮演」五个角色；不是加超时、加重试次数、把 17 个站点改成 8 个。
- **拆出的真：**
  1. 采集这一步的**物理耗时**由「最慢的那一组网页」决定，不是由站点数决定 —— 所以并行的单位是
     **板块**，不是站点。同一个站再快也不会让总耗时变短；把板块摊开才会。
  2. 慢的**真根不是网络**，是**上下文**：十几页正文回到主会话里，之后每一步都要重发它。
     所以并行不只是为了「同时抓」，更是为了让正文**从不进入主会话**。
  3. 子代理交回来的必须是**条目**，不是网页；主循环只做合并、去重、落盘。
  4. 「一次写整卷」是**输出预算**问题，不是内容问题：推理与工具入参共用一个 `max_tokens`，
     写整卷必然被切。切了以后**那一轮本来要作废** —— 要么加预算重来，要么让模型自己拆小。
- **如何从真推出：**
  1 → 引擎必须允许**一条回复里多个子代理同时跑**（并发护栏按「在飞数」而不是「嵌套深度」计）。
  2 → 子代理的**工具面必须包含网页能力与 bash**，且工具面由**本轮宿主**决定，否则它拿不到真正的抓取能力。
  3 → 人物定义写死「三个板块三个子代理、`system` 放契约、`prompt` 放工单」。
  4 → 输出顶到上限把工具入参截断时，引擎**不许收工**，要把截断当工具结果喂回模型。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 桌面 GUI / CLI 里让「情报王海燕」采当天资讯的用户；以及任何一次「一轮里要派好几个子代理」的活。
- **解决什么痛点：** ① 「三个子代理里只有一个能跑」（另外两个被拒，用户看不到、只看到结果不全）；
  ② 采集合成完三分钟的活，`write` 被截断，**整轮一个字都不交**；
  ③ 桌面端模型**根本看不见**「翻旧账」和「子代理」两个工具（宿主支持、工具面没有）。
- **用完后用户多得到什么：** 采集按板块真并行；下游只读上游产物；一轮里的活不再白跑。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期（工具卡上写着「子代理」）
  - [x] 不增加无意义确认或噪音（`subagent` 免确认，理由见 §2）
  - [x] 主操作一眼能找；空/载/错态完整
  - [x] 高频路径步骤少、界面干净

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户进「财富早知道」或工位，说一句「干活」。
- **怎么走完：** 海燕先确认时间窗口 → **一条回复里同时发出三个子代理**（工具卡上三张「子代理」并排）
  → 三份条目回来 → 海燕合并去重成一份卷 → 落盘（一栏一次）→ 对话里就是这份清单。
- **看起来怎么样：** 主会话里只看得见三张子代理卡；子代理**内部**的抓取过程不进主会话
  （这是设计的重点，不是缺陷：正文不该回到这里）。
- **好走 / 好看：** 用户不用点任何东西；比过去少一次「等它一站在一条回复里抓」。
- **成功标准：** 一条回复里三个子代理都真的在跑；整轮不再因为 `write` 截断而颗粒无收。
- **明确不做什么：** 不做定时任务；不自动起跑；不让子代理再派子代理；不改采集名单。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：**
  1. **并发语义错位**（引擎契约）：`SubagentContext` 用**一个** `Arc<AtomicUsize>` 同时表示
     「嵌套深度」和「同时有几个在跑」，`max_depth = 1`。引擎把同一条回复里的工具调用 `join_all`
     并发执行，于是第一个占住计数、其余全部被拒 —— 「一次派三个」在代码层面不成立。
  2. **工具面真相分叉**（装配）：`tools` 取自启动时缓存的 `state.tools`，而「翻旧账 / 子代理」
     是**每轮**才套上去的壳 → 宿主支持、surface 没有。GUI 与 server 都有这一处。
  3. **输出预算与工具入参共享**（状态机）：`stop_reason != ToolUse` 且工具入参被截断时直接
     `break` 收工，模型永远拿不到「你被截断了，拆小重来」这条信息。
- **正确的长期默认路径：**
  - 嵌套**不靠闸门**：child 的工具表里压根没有 `subagent`（`build_child_host` 从不挂
    `SubagentHost`）——这是**唯一**的嵌套判定点。并发**单列**一个在飞计数器（`max_concurrent = 8`），
    拒收文案也改成并发语义。
  - **工具面只认本轮宿主**：`let tools = host.list_tools()`（GUI / CLI / server 三处同形）。
  - 输出顶到上限的**两种形态**（正文零字 / 工具入参被截断）共用同一次加预算重来的机会；
    用完之后把截断作为工具结果喂回去，**让模型自己拆小**，轮次上限照旧兜底。
- **与引擎/各入口边界：** 三入口（GUI / CLI / server）共享同一引擎与同一形状；子代理的网页能力
  走**同一个**构造点（GUI/CLI `build_web_ctx`、server 新增同语义 `build_web_ctx`），不各自造一份。
- **安全影响：** `subagent` **免确认**：child 用父会话**同一套** `PermissionChecker`，跑不出父的授权范围；
  child 没有确认通道（`run_turn(confirm_tx: None)`），凡仍需点头的工具在它那里**一律拒绝**（fail-closed）。
  免确认换来的只有**并发**，所以并发上限必须留着。数据仍全本地明文。
- **如何防复发：** 变异测试（把 `max_concurrent` 改回 1 → 测试立刻红；把截断的 `continue` 改回
  `break` → 测试立刻红）；`spec()` 里写明「child 的工具表里没有 `subagent`」。
- **为何这不是补丁：** 三处都是**判定点收敛**（嵌套判定唯一、工具面唯一真相、截断处理唯一去处），
  不是加例外。

## 1. 方案（Plan）

- **目标：** 让「一条回复里派多个子代理按板块并行」真的成立并真的更快；让下游只读上游产物。
- **范围：**
  - **做：** `hermes-tools/src/subagent.rs` 并发语义；GUI / CLI / server 工具面与子代理接线；
    `messages`/压缩的口径不动；王海燕与项目组方法论；小宋取料口径；输出截断不再收工。
  - **不做：** 定时任务；子代理的 per-call token/轮次覆盖；`web_fetch` 全文落盘新通道；
    采集名单增删。
- **用户路径变化：** 改前「一个一个站抓 / 子代理只放行一个」→ 改后「一条回复三个子代理」。
- **技术要点：** `hermes-tools`、`hermes-turn`、`hermes-gui`、`hermes-server`、`hermes-cli`、
  `hermes-core/src/personas|teams`。
- **风险与回滚：**
  - 风险 1：并发扇出打爆 provider 限流 → 上限 8 兜底；名额在 `drop` 时归还（panic 也不漏）。
  - 风险 2：`TRUNCATION_RETRY_CEILING = 32_768` 是**工程取舍，非实测**（deepseek-v4-flash 上限未实测）。
  - 回滚：三处改动各自独立，可单独回退。
- **方案确认：** [x] 已对照 P0/P1（含第七条）· 2026-09-20

## 2. 实施（Implement）

**`crates/hermes-tools/src/subagent.rs`（并发唯一判定点）**
- 模块头 `Safety:` 拆成两条：**结构性不嵌套**（child 工具面里没有 `subagent`）+ **并发扇出上限**。
- `depth`/`max_depth` → `in_flight`/`max_concurrent`（`DEFAULT_MAX_CONCURRENT = 8`）；`DepthGuard` → `InFlightGuard`。
- 准入收成一处 `fn try_admit(ctx) -> Option<InFlightGuard>`；拒收文案改成并发语义。
- child 接上网页能力（`with_web_ctx`）—— 不接的话 child 的 `web_fetch` 会倒回整页原文。

**`crates/hermes-turn/src/lib.rs`（截断不再收工）**
- `lost_output_at_cap`：`MaxTokens` 且（正文不可发 **或** 有被截断的工具调用）→ 共用一次加预算重来。
- `stop_reason != ToolUse` 分支：若有被截断的工具调用，`continue`（喂回错误、让模型拆小）而**不是** `break`。
- 用户可见文案：「（推理把这一轮的输出预算用完了…）」→「（这一轮的输出预算用完了…）」（工具入参也算）。

**三入口工具面（同一形状）**
- GUI `crates/hermes-gui/src/commands/chat.rs`：链尾加 `SubagentHost`；`tools` 改由本轮宿主 `list_tools()`；
  删掉启动时那份缓存读取。`state.rs` 新增 `build_web_ctx`。
- CLI `crates/hermes-cli/src/commands/chat/mod.rs`、`commands/agent.rs`：父子共用同一个 `web_ctx`。
- server `crates/hermes-server/src/state.rs|routes/chat.rs|routes/mcp.rs`：补 `StampedHost` + `SubagentHost`；
  `tools` 由本轮宿主决定；**删除**与真实宿主会分叉的 `state.tools` 启动缓存；`/api/v1/mcp/tools` 改问活宿主。

**人物与项目组（方法论）**
- `personas/wang-hai-yan.md` 0.4.0 → 0.5.0：「采集怎么跑」整节改成**派三个子代理按板块并行**
  （宏观 / 产业动态 / 资本市场含公告），写死板块→站点对照表、`system` 放契约 / `prompt` 放工单、
  `allow_tools` 固定两个；落盘改成**一栏一次**（`write` + `edit` 追加），明令不许一次写整卷。
- `teams/caifu-zaozhidao.md` 0.2.0 → 0.3.0：第 1 棒同步成「一条回复里派三个子代理并行」。
