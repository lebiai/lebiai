## 0-fp. 第一性原理

- **拒绝的类比：** 不是把设置做成通用后台、不是把删除藏进悬停当「高级交互」、不是再叠一套弹层皮肤。
- **拆出的真：**
  1. 用户改得了的，必须看得见；看不见的字段不该被「保存」暗写。
  2. 没有他说的日子，就不是债。
  3. 过了的交差比回顾邀请更急。
  4. 删是主权，必须常看得见。
  5. 角标必须落到待审，否则是撒谎。
  6. 死入口 / 死文案 / 弃用包装会让人以为还能走。
  7. 主色、芯片、遮罩各只有一套，才像同一产品。
- **如何推出：** 按审计 1–7 顺序，每条改正确默认路径，同次清旧。

## 0. 用户价值

设置能改进化；收下要自己选日子；过了会先问；删得着；角标点进去就是待审；界面同一套控件。

## 0b. 产品经理

- **场景：** 桌面 GUI。
- **怎么走完：** 设置→更多→记忆与进化/上下文与工具看得见、点保存才写；待收下先选日子；对话里过了先出 Cue；侧栏/技能删除常在；有角标点「它记得的」进待审。
- **看起来：** 芯片/主按钮/遮罩各一套；删除是浅色常驻图标，不是悬停才现身。
- **不做什么：** 不扩 Flutter/IM；不改引擎契约；不代签 8/14 目视。

## 0c. 架构师

- **根因：** 规格有控件、实现只留了 form 字段；Cue 顺序按添加时间排；删除沿用后台悬停；Know 只 `setPanel`。
- **默认路径：** 设置 IA 补控件；accept 无期拒绝；Cue 过了优先；navStore 带 pending 焦点。
- **为何不是补丁：** 每条都回到已写清的规格，并删掉旧路径。

## 1. 方案

1. 进化/工具手风琴补控件。  
2. 待收下无期不能收下。  
3. Cue：过了 > 待收下 > 回顾邀请。  
4. 删会话/技能常驻。  
5. 有待审时点 Know → 「它懂你」+ 待审区。  
6. 清 mcp 空目录、废 i18n、`LicenseBattery`、`check_markitdown`。  
7. `ui.overlay` + 共享 `Chip`；Cue 用 `Button`。

## 2. 实施

1. 设置「记忆与进化」补最小轮数、自动接受（危险副文案）；「上下文与工具」补 token 上限与 allow/deny。保存仍走显式「保存高级设置」。
2. 待收下 / Cue 收下：无选日子则 toast，不再默认「这周」。
3. Cue 顺序：过了 → 待收下 → 回顾邀请 → 合并。
4. 侧栏删会话、技能删：去掉 hover 才现身。
5. 有待审时点「它记得的」→ `openPendingReview`（它懂你 + 待审区）。
6. 删空 `components/mcp/`、MCP/废导航/旧在办 i18n、`LicenseBattery` 包装、`check_markitdown`。
7. `ui.overlay` + 共享 `Chip`；Cue 改用 `Button`。

**偏离方案处：** 无。
