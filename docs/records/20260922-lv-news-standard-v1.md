## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是因为「别人家的栏目都这么筛」「标准写得越长越保险」「把标准全文塞进人设就完事」。
- **拆出的真：**
  1. **我们过去那版「入选六标准」是自己拟的**——从来没经过用户的往期样本回测。而这份 V1.0 是**用户定稿**、且是**合并替代**《方法论 v1—v9》与《Agent 规范 V2.0—V2.1.2》的唯一标准。判据的**来源**错了，不是写少了。
  2. 这份标准里混着**两个物种**：**判据**（谁看都得这么判——财经属性门、归栏、同日竞争）与**工程规范**（状态机、Schema、窗口计算、事件类型码、S 级）。判据进人设（模型每轮要读），工程规范不进提示词（那是引擎/采集端的活）。
  3. 判据里的**证据句**（`n=12`、「实测宏观栏 24% 归错」）对**执行者**是噪音，对**维护者**是命根子——所以它归 `docs/`，不进契约。
  4. 用户的输出格式（三板块 · 一条一组三行）与标准的落笔句式（**主体 + 动作 + 数字**、带时间锚点）**是同一件事的两半**，必须合成一份，不能两处各写一半。
- **如何从真推出：** ① **三层拆**——契约 = 判据执行版（每轮读）；`docs/spec/` = 原件与证据（人读、留档）；引擎规范另开一批。② **删掉一条错口径**：旧契约写「不选国外新闻（**中方主导的涉外事务照收**）」——按 V1.0 元首出访、外交磋商**照样要过财经属性门**，过不了就弃；这条错误正是昨天把「习近平 9/23—25 访美」放上头版的直接原因。③ 用户格式与标准的落笔句式合进同一节「《选题单》长什么样」。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 在「财富早知道」里报题的吕老师那一棒，以及看他报单的用户。
- **解决什么痛点：** ① 审核标准太弱——**政治消息放行上了头条**（11 条里 3 条必砍、1 条存疑）；② 判据散在几份互相打架的旧文档里；③ 判据没有回测依据，"为什么这么判"说不清。
- **用完后用户多得到什么：** 报单里不再出现政治／会议程序消息；每一条的取舍都能追到标准里的某一节；三种产物（主稿 / 公告池 / 弃稿台账）各有明确去向与句式。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期（三道门是三个问句，答不出就弃）
  - [x] 不增加无意义确认或噪音
  - [x] 主操作一眼能找（速查一节就是执行清单）
  - [x] 高频路径更干净（无史、无证据句、无 Schema）

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户在组会话里让吕老师开工；吕老师整读一次资讯卷，逐条过门，出《选题单》，用户点头。
- **怎么走完：** 整读全量 → 逐条过**三道门**（财经属性门 / 三具体门 / 归栏）→ 候选多时按**八步同日竞争**淘汰末位 → **相似复检** → 配结构（主稿 12—20）→ 出单。
- **看起来怎么样：** 正文按 `宏观 → 产业动态 → 资本市场`；**一条新闻一组、一组三行**（`ID ｜ 来源` / 主体+动作+数字 / 为什么播它）；之后三段——**公告池** / **待核实** / **弃稿台账**，没内容写「无」。
- **好走 / 好看：** 用户读完三板块就知道今晚播什么；公告池是长尾收纳，不必翻文件；弃稿台账让"为什么没播"可回查。
- **成功标准：** 昨天那份 11 条选题单里的第 1、2、4 条（元首访美 / 政治局定档 / 央行座谈会）**在这一版下不会出现**。
- **明确不做什么：** 不改三栏目结构、不改 ID 规则、不动引擎；**HOT 与公告池的推送形态暂缓**；不改小宋 / 小雨 / 王海燕（B、C 批）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 提示词层（人设契约）——**判据的来源与归属错了**（我们自己拟的标准，顶替了用户定稿的标准）。
- **正确的长期默认路径：** 判据的**唯一执行副本**在契约（模型每轮读的就是它，不需要额外检索）；语义源头是用户的 V1.0 原件，**留档**在 `docs/spec/`（非权威，供人读与变更对照）；两边各有一句「冲突以契约为准」；漂移由防回归断言兜住。
- **与引擎/各入口边界：** 只动被注入的文本。三个入口（CLI / GUI / server）同源生效。标准里属于引擎的（§8 窗口、§9 事件合并、§22 Schema、事件类型码、S 级）**不进提示词**，另开 C 批。
- **安全影响：** 无（本地明文、无 token / 网络变化）。
- **如何防复发：** `crates/hermes-core/src/persona.rs` 断言钉住 —— **财经属性门 / 三具体门 / 归栏边界规则 / 相似复检 / 同日竞争 / 主稿 12—20 / 公告池 / 弃稿台账 / 必停点**；吕老师契约**不许出现** `秒` / `配速` / `时长` / `分钟`（他不管节目时长，连否定句都不写）；采集端 `A／B／C` 明确「我不看」。
- **为何这不是补丁：** 换的是**判据本身与它的来源**，不是给旧判据打补丁；旧的三条入选／弃稿标准整块删除，不留兼容分支。

## 5. 附注 · 九条遗漏与本批没做的

1. **错口径已修**：旧契约「中方主导的涉外事务照收」删除（元首出访照过第一道门）。
2. **公告池没有独立数据源**：资讯卷只有三栏（实测 181 条里宏观栏 86 条），上市公司公告散在里面、还被归错栏。吕老师要从全量里挑，并**自己定 A／B／C／D**（与采集端 A／B／C 是两套体系）。
3. **待核实没有出口** —— 已补进《选题单》第四段。
4. **`index-<日期>.md` 还带着等级列**（`ID｜A｜来源｜…`）。契约已写"我不看"，但**列还在**（C 批）。
5. **王海燕契约与标准打架**：她要标 `【A／B／C】`；标准要的是**信源可信度三级**（官方／主流／其他）。（C 批）
6. **窗口**：标准 §8 要 `[T_prev, T_current)` + 卷间空档 `COVERAGE_GAP`；我们**没有发布记录**——建议 `T_prev` = 上一期目录日期 + 06:00 并标 `FALLBACK_TIME_WINDOW`。（C 批）
7. **事件级合并（`event_group`）**：标准 §9 要求（传闻→回应、收购→终止…合成一个事件）；我们只靠"按原文链接去重"，不够。（C 批）
8. **HOT / 标题行**：判据里保留（§21.4 句式），**产物暂缓**；但你给的参考成稿**第一行就是 HOT**。建议 B 批由小宋写成稿的标题行，不另立产物。
9. **小雨的位置**：标准里没有"口播稿"这个产物，落笔就是书面语。**留不留，待用户裁决。**
10. **小宋的 540 字硬数作废**（用户已批"改文字稿"）；新口径待 B 批定：不设字数上限，但每条不许超过一段。
11. **GUI 点头卡**：只渲染 `title` + `note`，看不到正文里的「为什么播它」；`Item.seconds` 与卡的秒数显示已成死路（"凡旧必清"待清）。
12. **主稿下限 12 与"料不够就少写"**：标准自己说"配额是目标不是底线"，契约按这条写；昨天 11 条、参考成稿 14 条都低于或接近下限，属正常。
