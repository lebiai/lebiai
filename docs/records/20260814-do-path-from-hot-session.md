## 0-fp. 第一性原理

- **拒绝的类比：** 不是因为「抖音热点」要单独做；不是因为别的 Agent 会探测沙盒所以我们也该探测。
- **拆出的真：** 用户要完成的事永远是一类：**今天的事实** + **一份东西放到他说的位置**。谁说了算：桌面是他说的出口。这一步实际该发生：系统给出今天、一条导出路径做完。用户看见：答案和文件路径，不是实验室日记。
- **如何推出：** 修的是所有同类场景共用的路：日期注入、`~/` 真出口、bash 与 write 同一套桌面规则、正文禁止环境独白、Care 只在真正交付后。不删「认得你」（普法号这类 Continuity）——那是另一条真，先留。

### 这条会话是标本，不是特例

| 本会话表象 | 换一个场景同样会炸 |

| 确认打在每次探测上 | 用户只授权「这一件事」 |

## 0. 用户价值

- **谁用：** 桌面 GUI 默认用户（查今天的事、把结果放到桌面）。
- **解决什么：** 同一类事不再变成调试过程。
- **用完后：** 「今天」不再猜日历；点名桌面可以一次写下；正文不再讲沙盒。
- **好用性自检：** 不增运行时；主路径更短；不增无意义确认； Continuity 能力保留。

---

## 0b. 产品经理视角

- **场景：** 查今天的热点/新闻；写成 Word 放到桌面。也覆盖：今天天气、导出 PDF 到下载。
- **怎么走完：** 发「查今天的 X」→ 按系统日期去查 → 给你结果。再说「放到桌面」→ 一次写下 → 回你路径。
- **看起来怎么样：** 正文是结果；过程区可有人话步骤；没有沙盒/Finder 日记。
- **不做什么：** 不删普法号等「认得你」的记忆能力；不重做搜索后端（本刀只收重试纪律）。

---

## 0c. 架构师视角

- **根因：** GUI/server 没注入日期；`~/` 先当工作区相对路径；bash 沙盒与 write 出口分裂；Care 把任何 write 当交付；协议没禁止对环境说话。
- **默认路径：** 表面一律 `inject_time_header`（不落盘）；`resolve_for_write` 先展开 `~`；沙盒允许与 write 相同的桌面/文稿/下载；Care 看路径像不像用户交付物。
- **为何不是补丁：** 修的是所有入口共用的日期、路径、沙盒、说话纪律，不是 if 抖音。

---

## 1. 方案

- **做：** 日期注入 GUI/server；`~/Desktop` 真写；bash 可写同一出口；正文纪律；Care 收紧。
- **不做：** 改 Continuity/普法号；重做 web_search 抓取质量（另案）。
- **方案确认：** [x] 2026-08-14
