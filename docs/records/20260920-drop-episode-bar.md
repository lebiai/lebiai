## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是栏目就要有「期」的仪表盘（日期、件数、接力链、产物清单叠在对话头上）。那是把电视台的周播表做成了 UI。
- **拆出的真：** 《财富早知道》是一条日复一日的会话，要把口播稿做出来。人在名册上，活在对话里，文件在产出里。用户真正要停下来的只有选题点头。
- **如何从真推出：** 去掉「这一期」这条带。点头只在选题单真的等你时出现。侧栏不再说「今天这期」。接力、决定文件、按天产出目录都还在——那些不是这条带。

- **谁用：** 桌面 GUI，点开财富早知道干活的人。

- **用完后用户多得到什么：** 组会话头只剩名册；要你点头时选题单自己出来；日常少一条装饰。

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户进财富早知道做今天的口播稿。
- **怎么走完：** 看见组名 + 名册 → 对话干活。吕老师写出选题单 → 一条选题卡出现，点「我点头」或「我改」。没有选题等着时，这条卡不出现。
- **看起来怎么样：** 名册下面不再有「这一期 · 日期 · N 件产物」。侧栏小字是 `待你点头` / `在X手上` / `进行中` / `还没开工`，不再冠「今天这期」。
- **成功标准：** 组会话里找不到「这一期」四个字；选题待点头时卡还在；名册和交给…还在。
- **明确不做什么：** 不删决定文件、不删 `list_episode` 扫描、不删接力、不改产出按天目录、不升 P0。

---

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** UI 把「今天的目录扫描」做成了常驻产品面。数据层（今天的文件 + 决定头 + 接力事件）仍然有用，错的是那条带。
- **正确的长期默认路径：** 对话是主面。点头是选题单上的动作，不是期看板的展开。
- **与引擎/各入口边界：** 只动桌面 GUI 与侧栏小字；`decision` 工具、`answer_decision`、handoff 仍走 `hermes-gui` episode 命令。server/CLI 本来没有这条带。
- **安全影响：** 无。
- **如何防复发：** 删掉 `episode.*` i18n；组块/工具回执不再写「在这一期里看到」。
- **为何这不是补丁：** 拿掉一个没有用户任务的面，把点头留在它真正所属的对象上。

---

## 1. 方案（Plan）

- **目标：** 组会话不再出现「这一期」看板。
- **范围：**
  - **做：** 删 EpisodeBar；选题 pending 时只出点头卡；侧栏小字去「今天这期」；工具回执与规格现行段对齐。
  - **不做：** 删决定类型；改接力；改产出目录；重写历史台账。
- **用户路径变化：** 常驻「这一期」带 → 无。待点头时选题卡出现。
- **技术要点：** `PendingNod` 只渲染 `status=pending` 的决定；`teams.rs` hint；`hermes-tools` decision 回执。
- **风险与回滚：** 点头入口变窄（只在 pending 时出现）——这正是要的。回滚即把 EpisodeBar 加回。
- **方案确认：** [x] 已对照 P0/P1 · 2026-09-20
