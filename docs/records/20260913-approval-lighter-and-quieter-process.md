## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「用户嫌烦就把确认全关掉」，不是「再往黑名单里加几条/删几条」，
  也不是「让模型少说两句」。拒绝把「少打扰」做成「少保护」。
- **拆出的真：**
  1. **弹窗的主因是一条判据错误的规则。** `crates/hermes-turn/src/danger.rs:240-254`
     把「内联解释器」整类当高危（`python -c` / `python3 -c` / `perl -e` / `ruby -e` /
     `node -e` / `php -r`）。可它挡不住认真的攻击：换成 `curl -o f && sh f`、
     写个 `.py` 再跑、`bash -c "$(printf …)"`，这条规则一个都不拦。
     对正常干活却是 100% 误伤 —— 抓巨潮/新浪接口后解析 JSON 就用它。
     证据：`python3 -c` 出现在用户 19 个会话里；小王这类采集任务必然用到。
  2. **「始终允许」是假的。** `crates/hermes-gui/src/state.rs:305` 把它初始化为空集，
     全仓没有任何落盘代码（`rg always_allowed_tools` 只有 8 处，全是内存读写），
     且只记住**工具名**。App 一重启就清零 —— 今天 21:48 我重启过 App，
     于是 21:49 那次跑起来弹窗全回来了。
  3. **落盘的基础设施其实早就有了，只是没接上。** `crates/hermes-turn/src/permissions.rs`
     支持 `bash:git *` 这类规则；`ConfigView` / `ConfigUpdate` 已经暴露
     `permissions_allow` / `permissions_deny`；设置面板 `SettingsPanel.tsx:984-991`
     已经能编辑这两个列表。缺的只是「始终允许」没往这里写。
  4. **过程太多是「实时」与「留存」不一致造成的。** 留存侧 `mergeAssistantContent`
     （`utils/displayMessages.ts`）一条规则：**一个提问 = 一个过程折叠 + 一段回答**，
     中间叙述只留最后一段。实时侧不遵守：`chatStore.ts:177` 把每个 textDelta
     一路累加，`toolUseStart` 也把每个工具都摊开。用户那次会话实测：
     34 条 assistant 消息 / 29 次工具调用 / 11 段叙述共 3255 字，
     而留存下来只有最后一段 497 字 —— 边跑边看的量与最后留下的量差了 6.5 倍。
- **如何从真推出：** 真 1 → 删掉内联解释器整类；**保留**真正不可逆的那些
  （`rm -rf` / `sudo` / `mkfs` / `dd` / `curl|sh` / 关机重启 / 反弹 shell / 系统目录
  `chmod`、`chown`），它们在正常干活里几乎不出现，且挡住的是不可逆后果。
  真 2+3 → 「始终允许」写进 `[permissions].allow` 并热更新内存，
  顺手删掉那个内存集合（旧实现同步清理）。真 4 → 实时侧按留存侧同一条规则走：
  文字只显示当前这一段，过程默认收起成一行。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 每个跑长任务的用户（产品默认路径 GUI）。
- **解决什么痛点：** 一次采集任务被弹十几次；关一次 App 之前点过的「始终允许」全作废；
  边跑边看一大屏过程，跑完又塌掉，看到的内容和留下的内容对不上。
- **用完后用户多得到什么：** 同样的活，弹窗从十几次降到零到一次；
  点过的「始终允许」下次开 App 还算数；过程平时只有一行，想看细节点开就行。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期
  - [x] 不增加无意义确认或噪音（只减不增）
  - [x] 空/载/错态完整（过程收起时仍有一行实时状态 + 转圈 + 失败图标）
  - [x] 高频路径步骤少、界面干净

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户说「小王干活」，一个要跑二三十步的采集任务。
- **怎么走完：**
  - 改前：每一步要么弹窗、要么在对话里摊开一行行工具明细；
    跑完过程折叠起来，但中间说过的 3000 多字也一起没了。
  - 改后：过程折成一行实时状态（「查资料、在工作区做事…」＋转圈），
    想细看点开；出错的工具仍在标题行显示失败图标；
    回答区只显示当前这一段。真正需要确认的（删文件、sudo、远程装技能、
    写工作区外）照旧问；用户点一次「始终允许」，写进配置，重启后仍然有效，
    随时可在设置里撤销。
- **看起来怎么样：** 无新增界面。过程折叠更安静；设置里那两个已有的
  允许/拒绝列表开始真的被用上（用户点「始终允许」后能看到多出一条）。
- **好走 / 好看：** 减少点击；对话更干净；回答更醒目。
- **成功标准：** 跑一次小王，弹窗 0–1 次；过程只有一行；回答就是最后那段。
- **明确不做什么：**
  - 不删 `rm -rf` / `sudo` / `curl|sh` / `skill_install` / 系统目录权限这类闸。
  - 不改「一个提问 = 一个过程折叠 + 一段回答」这条既有规则。
  - 不做「本轮全部允许」这种新模式（本轮只做「记住这个工具」）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 判定策略（danger 的分类学）＋ 状态持久化（内存 vs 配置）＋
  前端实时/留存不一致。三层各一处，不是 UI 小毛病。
- **正确的长期默认路径：**
  - 高危判定按**后果**分：不可逆/提权/远程代码进本地 → 必问；
    能在本机解释器里算一段的 → 不该问。
  - 用户表达过的授权意图**落到配置**，而不是进程内存。
  - 同一段内容在「实时」与「留存」两个视图里遵守同一条规则。
- **与引擎/各入口边界：** `danger.rs` 是**引擎**层（`hermes-turn`），
  CLI / GUI / Flutter / IM 全部共用，改一处到处生效；
  「始终允许」落盘 GUI 与 server 各自实现，两边都改，不留半截。
- **安全影响：**
  - 删除的是一条**对真实攻击几乎无效、对正常干活高误伤**的规则；
    保留的闸一个不动。
  - `is_absolute_risk`（`hermes-turn/src/lib.rs:452-459`）保证：即使配置里
    有 allow 规则，`rm -rf` / `sudo` / `skill_install` / MCP 工具**仍然要问**。
    所以「始终允许 bash」不等于「bash 无门」。这条正是可以放心落盘的前提。
  - 落盘写 `config.toml` 用既有的 `write_atomically_600`（临时文件 + 0600 + rename），
    密钥仍 0600。
- **如何防复发：** 在 `danger.rs` 加测试锁住「该问的还问、不该问的不问」两侧；
  在 `commands/config.rs` 加纯函数测试锁住规则写入（字符串级，不依赖真实数据根）。
- **为何这不是补丁：** 补丁是「把弹窗频率调低」；这里是
  **判据归位（按后果）＋ 意图落盘（配置而非内存）＋ 两视图同规则**，
  三处都指向同一件事：打扰只留给真正需要人拍板的地方。

## 1. 方案（Plan）

- **目标：** 跑长任务时弹窗降到 0–1 次；过程默认一行；授权意图跨重启有效。
- **范围：**
  - **做：** 删内联解释器整类；「始终允许」写进 `[permissions].allow` 并热更新；
    删掉内存版 `always_allowed_tools`；实时文字只留当前段；过程折叠默认收起。
  - **不做：** 动 `rm -rf` / `sudo` / `curl|sh` / `skill_install` / 系统目录权限这些闸；
    不引入「本轮全部允许」；不改留存侧合并规则。
- **用户路径变化：**
  - 改前：`python3 -c` 每调一次问一次 → 改后：不问。
  - 改前：点「始终允许」只在本次开机内有效 → 改后：写进配置，重启仍在，设置里可删。
  - 改前：实时把 3255 字叙述全摊开 → 改后：只显示当前这一段（与留存一致）。
  - 改前：边跑边看 29 行工具明细 → 改后：一行实时状态，点开才看明细。
- **技术要点：**
  - `crates/hermes-turn/src/danger.rs`：删内联解释器分支，更新文件头分类说明。
  - `crates/hermes-gui/src/commands/config.rs`：新增规则写入（含纯函数 + 测试）。
  - `crates/hermes-gui/src/commands/chat.rs`、`src/state.rs`：接上并删旧实现。
  - `crates/hermes-server/src/routes/chat.rs`、`src/state.rs`：同步。
  - `crates/hermes-gui/ui/src/store/chatStore.ts`、`components/chat/MessageBubble.tsx`。
- **风险与回滚：** 风险 = 用户点了「始终允许」后某个工具以后不再问。
  已有护栏（绝对高危仍问）＋ 设置里可见可删。回滚 = 还原改动。
