## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「给列表塞一个翻页控件」，不是「按后缀名过滤掉 `.py`」，
  也不是「把两块内容塞进 tab 就算完」。拒绝把「列表好读」做成「列表好看」。
- **拆出的真：**
  1. **记忆的「加入时间」没有成为顺序。** 引擎按 id 排
     （`crates/hermes-memory/src/store.rs:289` `out.sort_by(|a, b| a.id().cmp(b.id()))`），
     而 id 是随机短码（`mem_3619d64c…`）。实测真实数据 30 条记忆：今天新加的 5 条
     散落在 id 序的中段与尾部，不在开头 —— 用户找不到刚教它的那条。
  2. **列表没有「页」这个单位。** 30 条记忆一次铺满，用户既看不到头也找不到尾；
     「我的材料」同理（真实数据：材料 8 件、产出 35 件）。长的东西要能一段一段看。
  3. **两种来路被画成一条连续长列表。** 「我带来的」（用户的底料）与「我产出的」
     （搭子的成果）上下堆叠，滚动之前看不出下面还有另一种东西。
  4. **产出里混着搭子的工具脚本。** 真实数据 35 件产出里有 5 个可见 `.py`
     （`make_galbot_docx.py`、`make_news_docx_20260913.py` 之类）—— 那是做事的**过程**，
     不是交出来的**成果**。把过程列进「我产出的」，等于把草稿纸放进作品集。
- **如何从真推出：**
  - 真 1 → 顺序由**加入时间**定义，且**倒序**（用户找的多半是刚教的那条，
    最新的必须在最上面）。排序放在**视图层**，不动引擎的存储顺序 ——
    引擎的顺序还喂着上下文装配，改它会顺带改提示词内容。
  - 真 2 → 三个列表同一条规则：**一页 10 条**，翻页控件在列表尾部。
  - 真 3 → 两种来路 = **两个互斥的 tab**（同一层级的切换），不是上下堆叠。
  - 真 4 → **代码 / 脚本文件不进产出列表**；判定复用既有的「交付物 vs 脚本」判断
    （`hermes_core::companion::path_looks_like_user_deliverable` 里那段后缀清单），
    **一份清单两处共用**，不另写第二份。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 天天翻「它记得的」「我的材料」的人。
- **解决什么痛点：** 刚教的记忆找不到（顺序随机）；列表一屏到底，扫不动；
  材料和产出混在一页里分不清；作品集里躺着搭子的工具脚本。
- **用完后用户多得到什么：** 最新的在最上面、一页 10 条能翻；两种来路一眼分得开；
  「我产出的」只剩成果。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期（翻页键、页码、总数）
  - [x] 不增加无意义确认或噪音（只有一页时不显示翻页条）
  - [x] 空/载/错态完整（两个 tab 各自有空态）
  - [x] 高频路径步骤少、界面干净

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户刚在对话里让搭子记住一条，回到「它记得的」想核对一下写对没有；
  又或者做完一件事，回「我的材料」看今天产出了什么。
- **怎么走完：**
  - 记忆：进「它记得的」→ 第一屏第一条就是刚记住的那条（最新在最前）→ 底部
    「共 30 条 · 第 1 / 3 页」+「上一页 / 下一页」。
  - 材料：进「我的材料」→ 顶部两个 tab「我带来的 / 我产出的」→ 点「我产出的」→
    按时间倒序列出成果（`.py` 之类不出现）→ 底部分页，同样 10 条一页。
- **看起来怎么样：** tab 沿用「它记得的 / 它学会的 / 我的材料」同款胶囊条，
  与页头副标题同一层；翻页控件是两枚安静的按钮，不是大色块；
  产出行的日期只在**换天**时出现一次（小字分隔），不每行重复。
- **好走 / 好看：** 换 tab 只点一次；搜索框管当前 tab；换 tab / 改搜索回到第一页；
  记忆高亮（从对话点进某条）会自动翻到它所在的页。
- **成功标准：** 新记的记忆在第一屏第一条；两个列表都能翻页；产出列表无代码文件。
- **明确不做什么：**
  - 不改引擎的存储顺序（只改视图层给的顺序）。
  - 不做「全部展开 / 无限滚动」（用户要的是页）。
  - 不迁移、不改名历史产出文件。
  - 不动 server / Flutter 侧（未见此视图，不假装做了）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 排序层（记忆顺序由 id 决定）＋ 视图层（没有分页单位、两种来路同层）
  ＋ 过滤层（产出列表只按隐藏文件过滤，没有按「是不是成果」过滤）。
- **正确的长期默认路径：**
  - 记忆顺序 = `frontmatter.created` 倒序；由 GUI 命令 `list_memories` 保证，
    **不改** `FsMemoryStore::list()`（引擎顺序另有消费者）。
  - 「一页 10 条」写成 UI 层的一处常量 + 一个共用组件 `Pager`，三个列表都用它。
  - 材料页 = 两个 tab；tab 与分页都是视图状态，不进 store、不进后端。
  - 「什么算成果」= 一条共享判定（代码/脚本后缀清单），产出列表与 Care 判定同源。
- **与引擎/各入口边界：** 只动 GUI（命令 + 前端）与 `hermes-core::companion` 的一条
  谓词抽取；`hermes-memory`、`hermes-sources` 的存储顺序不动。
- **安全影响：** 无新增权限、无新增写能力；产出列表仍只读 workspace。
- **如何防复发：**
  - 记忆排序：纯函数 `sort_newest_first` + 单测（乱序进、倒序出；时间解析不了不 panic）。
  - 代码文件清单：`hermes-core` 单测（`.py/.js` 不算成果，`.md/.docx/.html` 算），
    并在 `outputs.rs` 单测里断言列表里不出现 `.py`。
  - 分页：前端切页逻辑简单，靠 `tsc` 与目视；不做表单化测试。
- **为何这不是补丁：** 补丁是「在前端把数组 reverse 一下」「在列表里 if 掉 .py」；
  这里是**顺序归位**（时间定义顺序）＋**结构归位**（有页、有 tab）＋
  **判定归位**（成果与脚本同源判定）。

## 1. 方案（Plan）

- **目标：** 三个列表都可读：时间倒序、一页 10 条、来路分明、成果里不见代码。
- **范围：**
  - **做：** 记忆按加入时间倒序 + 分页；材料页改 tab（我带来的 / 我产出的）+ 分页；
    产出列表过滤代码/脚本文件；共用 `Pager` 组件。
  - **不做：** 改引擎存储顺序；无限滚动；迁移历史文件；动 server / Flutter。
- **用户路径变化：**
  - 改前：记忆按随机 id 排、一屏到底；材料页两块上下堆叠、无分页；产出含 6 个 `.py`。
  - 改后：记忆最新在最前、分页；材料页 tab 切换、分页；产出只剩成果。
- **技术要点：**
  - `crates/hermes-gui/src/commands/memory.rs`：`sort_newest_first`。
  - `crates/hermes-core/src/companion.rs`：抽出 `looks_like_code_file`，两处共用。
  - `crates/hermes-gui/src/commands/outputs.rs`：跳过代码/脚本文件。
  - `crates/hermes-gui/ui/src/components/common/Pager.tsx`（新）。
  - `crates/hermes-gui/ui/src/components/materials/MaterialsPanel.tsx`：tab + 分页。
  - `crates/hermes-gui/ui/src/components/memory/MemoryPanel.tsx`：分页 + 高亮跳页。
  - `crates/hermes-gui/ui/src/i18n.ts`：`pager.*`（中英各一）。
- **风险与回滚：** 风险 = 记忆高亮条不在当前页（已覆盖：自动翻到它所在页）；
  搜索与分页叠加（已覆盖：改搜索回到第一页）。回滚 = 还原改动。
- **方案确认：** [x] 已对照 P0/P1 · 2026-09-13 · 用户口头提出

## 2. 实施（Implement）

- **实际改动摘要：**
  - **记忆顺序**（`crates/hermes-gui/src/commands/memory.rs`）：新增纯函数
    `sort_newest_first` —— 按 `created_at` 倒序，时间解析不出来的排最后（同样解析不了时按 id
    定序，结果稳定）。**不动** `FsMemoryStore::list()`：那里的顺序还喂着上下文装配。
  - **一份代码清单两处共用**（`crates/hermes-core/src/companion.rs`）：抽出常量
    `CODE_FILE_EXTS` 与谓词 `looks_like_code_file`；`path_looks_like_user_deliverable`
    改为调用它 —— Care 收尾判定与「我产出的」列表同源，不另写第二份后缀表。
  - **产出过滤**（`crates/hermes-gui/src/commands/outputs.rs`）：遍历时跳过代码 / 脚本文件。
    真实数据：35 件 → **30 件**（滤掉 5 个可见 `.py`；第 6 个 `.tmp_tb_analysis.py` 本就是
    隐藏文件，早就被跳过）。
  - **分页组件**（`crates/hermes-gui/ui/src/components/common/Pager.tsx`，新）：
    `PAGE_SIZE = 10` · `pageSlice` · `pageCount` · `Pager`（只有一页时返回 `null`，不吵）。
  - **材料页**（`ui/src/components/materials/MaterialsPanel.tsx`）：改成两个 tab
    「我带来的 / 我产出的」（沿用「它记得的 / 它学会的」同款胶囊条），各自分页；
    搜索只作用于当前 tab；换 tab / 改搜索回到第 1 页；「加入文件 / 加入文件夹」只在
    「我带来的」出现；拖文件进来后自动切回「我带来的」（否则丢完在当前页看不见，像坏了）。
  - **记忆页**（`ui/src/components/memory/MemoryPanel.tsx`）：10 条/页；换分区 / 改搜索回到
    第 1 页；从对话点进某条记忆时**自动翻到它所在的那一页**再滚动高亮。
  - **i18n**：`pager.summary` / `pager.prev` / `pager.next`（中英各一）。
- **关键路径/文件：** 见上。
- **偏离方案处（如实记）：**
  1. 方案写「产出按日期分组展示」，实现改成**扁平时间倒序 + 换天小标题**：分组头与分页会
     互相打架（一页很可能从某天的中间开始），扁平化后「一页 10 条」和页码才说得准。
  2. 方案里想在 tab 上显示条数 —— **去掉了**。产出条数只有子组件知道，父组件写死就会撒谎
     （试过写 0，等于显示「我产出的 0」）；不显示比显示错的强。
  3. `looks_like_code_file` 的后缀清单比原 `path_looks_like_user_deliverable` 里那 5 个更宽
     （新增 `json/yml/toml/sql/css/…`）。这是**有意**的统一：写 `outputs/data.json` 不再触发
     Care 收尾建议（它不是给人读的东西）。原有 5 个后缀的行为不变。
