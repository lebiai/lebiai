## 0-fp. 第一性原理

- **拒绝的类比：** 不是把周报 App、日历、原生 date picker 墙搬进抽屉。不是蒸完只把 JSON 丢在 React state 里交差。
- **拆出的真：**
  1. 回顾的对象是**一段日子的交差账**（做成了什么），不是表单、不是离开蒸馏的规则候选。
  2. 账已经落在 `~/.lebi-ai/reviews/`。用户看不见 = 没交付。
  3. 「这段已经蒸过」是用户要核对的事实，必须在页上，不能只存在后台 `index.json`。
  4. 本产品主按钮是 `app-primary` 蓝。黑块按钮、裸系统日期框不是这套 GUI。
- **如何从真推出：** 打开回顾页先读已落盘的账；过往是同页台账；蒸完一句提示并留在页上；控件复用 `Button` / 主色芯片 / 人话区间。

## 0. 用户价值

蒸完能看见交差账；过几天回来仍能看见这段已经回顾过；按钮和区间长得像乐彼，不像后台。

## 0b. 产品经理

- **场景：** 对话右上角 → 抽屉 → 回顾。
- **怎么走：** 先看见「本周 8/11–8/17」。没账：一颗蓝色「回顾这段」。有账：先读账，写「这段已经回顾过」，次按钮「再看一次」。下面「过往」点开旧账。节奏芯片在页底。
- **看起来：** 文章，不是表。芯片选中 = 主色浅底，不是黑底白字。日期退后到「改日期」。
- **空/载/错：** 空区间人话；载是按钮文案「正在回顾…」；错 toast「没蒸成」。
- **不做什么：** 系统通知、日历、第三页、离开蒸馏混进来。

## 0c. 架构师

- **根因：** 实现只做了「能蒸」，账写进文件后 UI 不读回来；结果只活在组件 state。
- **默认路径：** `reviews/index.json` 带结构化字段；`list_reviews` 给 GUI；同一区间再蒸覆盖。
- **为何不是补丁：** 交差账成为回顾页的主内容，不是再堆一层提示条。

## 1. 方案

对照规格 §2.3 / §3 / §4 落地。规格升 v1.2，只写清「账在页上、过往是台账」。

## 2. 实施

- `hermes-commitments::review`：索引带 focus/done/outputs/still_owe；同区间覆盖；旧 md 可回读。
- GUI `list_reviews`；`get_review_prefs.reviewed`。
- `ReviewPane` 重画；`ZaibanBlock` 显示「交差 · …」。
- 去掉黑主按钮。
- 第二刀（浏览）：有账后过往在上、正文是账；点过往只换正文；蒸/节奏退后。
- 第三刀（正文空）：同一天再蒸误删刚写的 md；模型没吐 JSON 仍当成功。现不删新文件；JSON 抽不出来就用对话证据回落；页上固定「交差账」区，空了说明「再看一次」。
- 第四刀（读法）：目录与读账拆开。读账独占、文章排版、左上角收起。不再把 md 和过往挤在同一卷。

## 3–4. 测试 / 验收

`hermes-commitments` 单测（含 md 回读）。GUI 待用户走：蒸一次 → 关抽屉再开仍见账 → 过往可点 → 控件不是黑块。
