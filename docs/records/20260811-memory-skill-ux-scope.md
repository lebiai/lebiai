## 0. 用户价值

- **谁用：** 桌面 GUI 用户（中文主路径）。
- **痛点：**
  1. 侧栏「记忆」有待审角标，进页后找不到/看不清待确认区。
  2. 技能详情默认铺满模型指令（body），用户需要的是「能做什么 / 怎么用 / 效果」。
  3. 创建记忆/技能时的「用户 / 项目」范围无解释，与 zone 分区混淆。
- **用完后：** 有待审时一眼进入并完成确认；技能页像产品介绍卡；范围选择自带白话说明。

## 0b. 产品经理视角

| 场景 | 改前 | 改后 |
|------|------|------|
| 有 N 条待确认 | 侧栏有数；默认「全部」；左侧「待确认」弱样式 | 自动切「待确认」；分区琥珀角标 + 选中环；空态明确 |
| 点开技能 | 标题 + 一行描述 + 整页 body | 能做什么 / 何时有用 / 怎么用 / 效果；body 折叠 |
| 创建记忆/技能选范围 | 仅「用户」「项目」二字 | 白话 hint + 当前选项短句 |

**成功标准：**

1. `pendingCount > 0` 打开记忆 → 落在「待确认」且列表可见琥珀区。
2. 技能详情默认不展示大块 monospaced body；折叠后仍可看原文。
3. 新建记忆/技能表单可见范围说明。

**明确不做什么：** 不改 inbox 存储协议；不改 skill frontmatter schema；不实现「项目根」设置 UI。

## 0c. 架构师视角

- **根因：** UI 信息架构错位。
- **正确默认：** 待审有数即聚焦；技能 GUI 读 description/triggers；body 是 Progressive Disclosure 细节。
- **边界：** 仅 `hermes-gui/ui` + i18n。
- **非补丁：** 纠正「谁是主内容」的默认路径。
