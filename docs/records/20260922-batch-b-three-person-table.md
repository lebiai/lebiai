## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是因为「四个人少一个不整齐」、也不是「给小宋再写细一点就行」，
  更不是「留一个口播工位当兼容」。
- **拆出的真：**
  1. 用户定稿的 V1.0 标准里，这一期的**终点是一份能直接读的书面稿**（标题行 + 三栏目正文 +
     公告池）——**根本没有「口播稿」这个产物**。既然没有这个产物，桌上第 4 棒的「念」
     就既没有输入、也没有输出，它不在这一期里。
  2. 三步链路上每一棒的真实成本是**读**：海燕落料 → 吕老师整读一次全量（判据要求全量）
     → 小宋只按 ID 取那几条。**多一棒就是多一次整读，多一次整读就是用户多等一轮。**
  3. 「120 秒 / 540 字」是**节目时长**的产物，不是写作的产物。这一期不按时长交付
     （数字人与成片在系统外），硬数就**没有来源**——照着写出来的稿子是被字数撑出来的。
- **如何从真推出：**
  ① 团队名册四步 → **三步（采 / 选 / 写）**，名册是唯一真源，改它就改了整个提示词与侧栏；
  ② 小宋的产物从「配速 + 字数」换成**书面稿形态**（标题行 + 导语 + 三栏目 + 公告池），
     删掉一切字数硬数；
  ③ 三个契约文档里凡「念 / 口播 / 小雨 / 字数硬数」整块清掉，**不留史、不做兼容分支**；
  ④ 小雨**不坐这张桌**、工位保留——她的定义是写出来的资产，物理删除不可逆；
     要口播的人还能在侧栏单独找她（与扫地僧 / 雨天 / 小文同一种处置）。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 在「财富早知道」里干活的用户（组会话），以及单独找某个工位的人。
- **解决什么痛点：** ① 一棒多一次整读，用户干等；② 口播稿不是他要的产物，念完还得改回书面；
  ③ 540 字硬数把每条新闻撑成小作文，读起来发虚。
- **用完后用户多得到什么：** 一期待办从四棒变三棒；拿到手的就是能直接读的书面稿；
  每条一段、不再注水；「为什么没播」仍可回查（弃稿台账照旧）。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期（少一棒，链条更短）
  - [x] 不增加无意义确认或噪音
  - [x] 主操作一眼能找（组里少一个人，名册更好读）
  - [x] 高频路径更干净（口播相关的提示词整块清掉）

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户在组会话里「开工」；王海燕采料 → 吕老师报题（点头）→ 小宋成稿 → 这一天走完。
- **怎么走完：** 采（落料）→ 报题（**唯一必停点**）→ 成稿（**先贴全给你看，点头才落盘**）。
- **看起来怎么样：** 名册从 4 行变 3 行，不再有「小雨（缺席）」这类提醒；
  组块规矩里删掉「口播」；小宋回复的首屏是**稿子本身**（标题行 + 三栏目 + 公告池）。
- **好走 / 好看：** 少一棒、少一次整读；侧栏工位里小雨仍在，想单独要口播仍找得到。
- **成功标准：** 桌上是三个成员；「小宋交付后还有下一棒」的所有断言与提示词一律不成立；
  老码若含已下线的人，照既有规矩提示「有 N 个角色这个版本不认识」，不静默。
- **明确不做什么：** 不动三栏目结构、不动 ID 规则、不动引擎；**不删小雨的定义**（工位保留）；
  不改王海燕（C 批）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 定义层——**桌子上的棒数错了一根**（团队名册 + 三份人物契约 + 流水线断言）。
- **正确的长期默认路径：** 名册是唯一真源（`teams/caifu-zaozhidao.md` 编译进二进制）；
  棒跟产物走（`pipeline.rs` 按名册顺序推）；产物是**书面稿**，落盘即收工。
- **与引擎/各入口边界：** 只动被注入的文本与随之而来的断言；CLI / GUI / server / IM
  同源生效。引擎字段（`Item.seconds`）保留兼容既有文件，**schema 早已撤下**。
- **安全影响：** 无（无 token / 网络 / 落盘路径变化）。
- **如何防复发：** 测试锚点整体改三步三人——
  `pipeline.rs`（`next_after(xiao-song)` = `None`；成稿落盘即终点；缺席停线用吕老师举例）、
  `team.rs`（`caifu_zaozhidao_is_the_three_step_table`；组块名册里不许出现小雨）、
  `persona.rs`（接棒说话人换小宋；小宋契约的 needle 换成书面稿特征）、
  GUI（`teams.rs` 缺席提示 / `episode.rs` 交接拒绝 / `chat.rs` 记忆注入举例）、
  channel（组块位置与缺席点名）。小雨加进「仍是工位但不在这张桌上」的清单，**与 persona 定义分开盯**。
- **为何这不是补丁：** 是**删掉一棒**、把产物换回书面稿，不是给旧链路加条件或遮错；
  四步时代的提示词与断言整块删除，不留兼容分支。

## 1. 方案（Plan）

- **目标：** 桌上三步三人；小宋产物是书面稿（无字数硬数）；小雨不坐这张桌（工位保留）。
- **范围：** 做 —— 团队定义、吕老师 / 小宋 / 王海燕契约去口播、`projects.md` 规格同步、
  引擎与 GUI / channel 测试锚点、防回归断言。
  **不做** —— 王海燕动态窗口 / 事件合并 / 信源三级（C 批）；删除小雨的人物定义。
- **用户路径变化：** 改前 —— 吕老师报单里带秒数，小宋配速出稿、小雨出口播稿。
  改后 —— 吕老师只筛（A 批已落），小宋出**能直接读的书面稿**、点头才落盘，**没有下一棒**。
- **技术要点：** `crates/hermes-core/src/{teams/caifu-zaozhidao.md, personas/{lv-lao-shi,xiao-song,wang-hai-yan}.md, pipeline.rs, team.rs, persona.rs}`；
  `crates/hermes-gui/src/commands/{teams,episode,chat}.rs`；`crates/hermes-channel/src/companion_context.rs`；
  `docs/spec/projects.md`。
- **风险与回滚：** 人设是 `include_str!` 编进二进制——**必须重编重启 GUI** 才生效；
  回滚 = 把小雨放回名册（一处）并复位断言。
- **方案确认：** [x] 已对照 P0/P1 · 2026-09-22 · 用户裁决「小雨不留」
