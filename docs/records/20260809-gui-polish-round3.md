## 0. 用户价值

- **谁用：** 普通用户（国内为主，默认中文）。
- **解决什么痛点：** 没配 Key 时顶部黄色横幅像报错；技能页空白让人以为坏了；原生下拉与整体 UI 不搭；欢迎仪式一屏 5 个按钮不知点哪个；设置页像后台表单，没有设计感、要到处找保存。
- **用完后用户多得到什么：** 平时零打扰、输入时才提示配 Key；技能页一打开就有「内置」技能可看；所有下拉统一风格；欢迎仪式只做一件事（填 Key 就开工）；设置页有问候、分组清晰、改动即存。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期
  - [x] 不增加无意义确认或噪音
  - [x] 高频路径比改前更快或更省心

## 0b. 产品经理视角

- **场景：** 用户首次打开 / 日常使用 / 想调整设置。
- **路径变化：**
  - Key 提示：对话页常驻黄色横幅 → 删除；发送首条消息时 toast「请先在设置中配置 API Key」并自动进入设置（输入内容不丢失）。
  - 技能：GUI 启动与 CLI 一样自动安装 3 个内置技能（记忆宫殿 / 技能创作 / 找技能）→ 技能页分「内置（只读，带徽标）」+「我的技能（可新建/编辑/删除）」。
  - 下拉：4 处原生 `<select>` → 统一自定义 Select（圆角浮层、选中勾、深浅色适配）。
  - 欢迎仪式 step2：5+ 按钮 → 服务商（默认 DeepSeek）+ Key 输入 + 1 个主按钮「保存并开始」+ 1 行「没有 Key？跳过」。
  - 设置页：顶部问候条（Hi 称呼 + 时段问候 + 当前模型）→ 4 组 tab（账户/模型服务/体验/高级）→ 卡片化；体验组改动即存；模型组/高级组各自卡片内保存；去掉全局保存/重新加载按钮。
  - 数据位置：删掉手输路径输入框（用户反馈「居然让用户自己输入？」）→ 点「更改位置」弹系统原生目录选择器，选中即迁移；取消则不动。
- **成功标准：** 上述路径在干净环境全部可用；技能页首次打开非空；设置页任何改动不需要找顶部保存按钮。
- **明确不做什么：** 不改引擎对话逻辑；不做设置项搜索；不把「技能」移出主导航（保留入口）。

## 0c. 架构师视角

- **根因层级：** ① 内置技能安装只在 CLI 入口 → GUI 启动无；② UI 层原生控件与设计语言不一致；③ 设置页是「整表单提交」模型，与产品化目标冲突。
- **正确的长期默认路径：** 内置技能是引擎契约，应随二进制共享安装（移到 `hermes-skills/bundled/` + `bundled::auto_install_bundled()`，CLI/GUI/渠道共用）；设置页从「整体表单」改为「分区 + 即时保存」。
- **与引擎/各入口边界：** 内置技能资源与安装逻辑从 `hermes-cli` 下沉到 `hermes-skills`（共享 crate），CLI 与 GUI 同一函数；GUI `list_skills` 按 `BUNDLED_SKILLS` 标记 `builtin`，`delete_skill` 拒绝删除内置（防复发）。
- **安全影响：** 无新增网络/权限；技能仍本地明文；删除内置技能在后端被拒绝。
- **如何防复发：** 共享安装函数保证各入口一致；`bundled.rs` 测试覆盖「全新安装 / 升级感知 / 不覆盖本地编辑」。
- **为何这不是补丁：** 内置技能不是 GUI 单独补一份，而是把「内置技能随入口安装」从 CLI 特例提升为引擎默认路径；删除旧 CLI 安装函数，无重复代码。
