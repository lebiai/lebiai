## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：**
  - 不是 ChatGPT 的「危险工具先问一句」。
  - 不是邮件客户端的「附件折叠贴在顶上」。
  - 不是「先摘要再开口」当作对用户好。
- **拆出的真：**
  1. 用户已经点了发送，这一轮的工具是为他把事推进，再弹确认是第二道门，只会停住。
  2. 消息变多时慢，是因为请求体仍带着窗口之外的每一条（只截断字数，条数不减），而且开口前还可能再付一次压缩模型调用。
  3. 历史要的是时间轴往上翻，不是粘在视口顶上的图层。
  4. 过程默认合上 + 「在想这件事…」覆盖压缩/工具/首 token，所以只能干等。
  5. 组会话把**当前**说话人打在每一条历史上，名字是错的。
- **如何从真推出：**
  - 真 1 → 桌面/手机这一轮自动放行工具；IM 仍无确认 UI 则 fail-closed。进化候选（记忆/技能）仍要批准，那不是这一轮的门。
  - 真 2 → 请求体只保留最近窗口；更早的整段省略并指路 `session_recall`。压缩挪到回答之后，不挡开口。
  - 真 3 → 取消 sticky；按天插在时间轴上方，点开滚到那一天。
  - 真 4 → 正在跑的工具步写清对象并展开。
  - 真 5 → 历史气泡不再借用当前说话人；只有这一轮直播标谁在说。

## 0b. 产品经理视角

- **场景：** 说一句 → 看它干活 → 必要时往上翻旧账。
- **怎么走完：** 发送后立刻「在想 / 正在读 xx」；不再弹确认。长会话点「9 月 16 日」→ 那一天的气泡出现在上面，视口滚到那天开头，继续往上/往下翻。
- **看起来怎么样：** 一条时间轴。旧账和今天同一套气泡，没有左竖线卡片、没有粘顶横条盖住正文。
- **成功标准：** 100 条以上开口不再先空等一轮摘要；点开某天能看见那天的话；对话中无确认弹窗。
- **明确不做什么：** 不改财富早知道的选题/接力/点头流程（下一阶段）；不改记忆/技能待确认；不改 IM fail-closed。

## 0c. 架构师视角

- **根因层级：** 请求体策略（条数）+ 回合门（确认）+ 历史是控件不是时间轴。
- **正确的长期默认路径：** 请求只带最近窗口；落盘仍是全文；确认不进桌面回合；历史是同一条 scroller。
- **入口边界：** GUI/server 自动 Allow；CLI 仍可提示；IM 无通道仍拒绝高危。
- **安全：** 设置里的 deny 规则仍生效；绝对高危在桌面由用户本轮发送授权，不再二次弹窗。
- **防复发：** `fold_for_request` 测「更早的条数不进请求」；GUI 不再渲染 ConfirmModal。
- **为何不是补丁：** 改的是默认路径（请求形状、确认通道、历史滚动模型），不是给慢加上 loading。

## 2. 实施（Implement）

- **实际改动摘要：**
  - `fold_for_request`：更早的消息整段省略成一条指路，只发最近 40 条（窗口内长块仍截断）。
  - GUI：开口前不再跑摘要；回答之后再压缩，失败不影响本轮。
  - 桌面/server 这一轮工具自动放行，确认弹窗拆除。IM 仍 fail-closed。
  - 历史：取消 sticky 盖层；按天插在时间轴上方，点开滚到那天。
  - 正在跑的工具步展开并写出对象；流式时关掉虚拟列表以免滚丢。
  - 组会话不再把当前说话人盖到每一条历史上，只标这一轮。
- **关键路径/文件：** `compaction.rs`、`hermes-gui/src/commands/chat.rs`、`ChatView.tsx`、`MessageBubble.tsx`、`chatStore.ts`、`hermes-server/src/routes/chat.rs`
- **偏离方案处：** 财富早知道的选题点头 / 接力未动（下一阶段）。记忆/技能待确认保留。
