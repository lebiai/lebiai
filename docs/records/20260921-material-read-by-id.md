## 0-fp. 第一性原理（必填 · P0 第零条）

**拒绝的类比：**「既然要按 ID 取料，那就该有个**库**——接到 `hermes-sources` 上去」。
这个类比的错处是：它假设瓶颈在「没有存储」，于是把力气花在**换容器**上。要从头推的是：
**这一棒真正在花的钱是什么。**

**拆出的真（先量，再判）：**把今天真实的 182 条素材灌进 `hermes-sources` 实测（release）：

| 量 | 实测 | 说明 |
|---|---|---|
| `catalog.json` | **1.65 MB** | 素材本身 64 KB，涨 **26 倍**（chunk 存全文 + postings 存 token + pretty JSON） |
| 入库 | 一天 182 条 **0.94 s**，单条 1.4 ms → **10 ms** | 单条随存量**线性**涨 ⇒ 总量**平方** |
| 上限 | `MAX_SOURCES = 200` | 一天 182 条，**第二天直接 `Quota`** |
| `source_read` | 一次最多 **12,000 字符** | 正是上一批刚治好的放大病 |
| 检索 | `search("央行")` → **0 命中** | 中文两字短语低于 `MIN_QUERY_TOKENS_HIT`，是**现存 bug** |

两处根因在代码里：每次入库都拿新料跟**全部存量**做近似版本比对（`store.rs:414`）；每次入库都把
**整份** `catalog.json` pretty-JSON 重写（`save_catalog`，`store.rs:676`）。它是「用户自己那几份文档」
的书架，不是日报的库房。**按原样接 = 把放大病换个地方再犯一遍，外加一堵配额墙。**

**真正的钱花在哪：**上一批已把**读入量**从 23.5 万字压到 2.8 万字符，读入不再是瓶颈；
真正还在花的是**模型往返次数**——小宋原来一条料要两个来回（`grep` 拿行号 → `read(offset)` 取三行），
10 条就是 20 个来回。而**行号与偏移本来就不该由模型算**：ID 里带着日期，行号在索引里躺着。

**如何从真推出做法：**
1. **不换容器**：库还是 `资讯-<日期>.md` + `index-<日期>.md` 两个文件——不新增存储、不整份重写、不设配额。
2. **把「给我 ID，还我那条」变成一次调用**：`material_read` 收一个或多个 ID，回每条自己的三行。
3. **引擎算路径和行号**，模型不算——那两步里任何一步错，都是一次「取不到」。

## 0. 用户价值（必填）

用户的第一诉求是**慢**。这一批不改任何界面、不改任何产出格式，只做一件事：
**让小宋取料从 20 个模型来回变成 1 个。**

用户看得见的是：同一个活，从「一堆工具卡片慢慢爬」变成「两张卡片」，整体等待明显变短；
以及「这个 ID 我取不到」这类半途失败少一类（行号算错、越界都不再可能）。

## 0b. 产品经理视角（必填）

- **用户怎么走完**：完全不变。用户发「按选题单成稿」，小宋取料、写字、落盘、回话。
- **看起来怎么样**：**格式一个字没改**——成稿还是那份成稿。工具卡从 15 张减到 6 张
  （其中取料那张写着一次取回 10 条）。
- **空 / 载 / 错态**：索引没落盘 → 工具明说「材料没落盘……先让王海燕交」，小宋据此**停这一棒**
  （不许自己整读成品去凑）；ID 不在索引里 → 明说，不拿别的条目顶。
- **成功标准**：小宋这一棒的工具调用次数下降；成稿仍落盘、仍在「540 字 ±20%」内、出处仍逐条可回溯。
- **不做什么**：不新增存储、不改产出格式、不给用户加操作、不动素材文件的格式。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因**：取料这件事被拆成了「查行号」+「按行号取」两个模型动作，中间那段**算偏移**是引擎本该
  自己做的活；模型每算错一次，用户就看到一次失败。
- **正确默认路径**：一个工作区相对的工具（像 `read`/`grep` 一样，**不需要任何 store**），
  输入 ID、输出那条料。ID → 日期 → `outputs/<日期>/` → 索引里查行号 → 成品里取那几行，全在工具里。
- **边界**：
  - **短 ID 容错**：实测吕老师的框架表里写的是 `资本-037`（台账却是全 ID）。工具接受短 ID，
    但**只落在指定那一期**（`date` 参数，默认今天），绝不去别的日子乱翻；抬头一律回**全 ID**，
    谁解析成哪一期一眼看得见。
  - 形状不对就**不猜**（`../../etc/passwd`、`2026092-宏观-001` 一律拒），不拼路径。
  - 抬头**不带行号**：`read` 会带行号前缀，行号进了稿子就是脏字。
- **不做**：不接 `hermes-sources`（实测不支持）；不加缓存、不加索引文件、不加新格式。

> **追记（2026-09-21 晚）**：本文件里出现的 ID 例子（`资本-037` / `20260921-资本-037`）是
> **当时的写法**。同日晚 `20260921-editor-reads-it-all` 把 ID 改成**纯 ASCII**
> （`<YYYYMMDD>-<lane>-<NNN>`，`lane ∈ {macro\|industry\|market}`），工具同步只认 ASCII 栏名。
> 下面这些实录**保持原样不改**（它们确实是那天发生的事），读的时候按新写法换算即可。

## 1. 方案（Design）

1. 新增 `crates/hermes-tools/src/material.rs`：`material_read`，收 `ids`（字符串或数组）+
   可选 `date`；按 ID 取那一条，支持一次多条。
2. 注册为**工作区工具**（`WORKSPACE_TOOLS`），与 `read`/`grep` 同级——不需要 store，所以哪个入口都有。
3. 改契约，让下游真的用它：
   - **吕老师** 0.4.0：取料第 2 步改成 `material_read` 按 ID 取（可一次几个）；
     **ID 一律写全**（框架表与台账同一个写法）——下一棒拿 ID 取料，缩写等于让它猜哪一期。
   - **小宋** 0.4.0：取料三步 → 两步（拿 ID → `material_read` 一次取全）；索引没落盘就**停**，
     不许自己整读成品去凑。
4. 守卫同步收紧（`persona.rs`：两条契约必须提到 `material_read`；吕老师必须有「ID 一律写全」）。

### 不做
- 不接 `hermes-sources`（见 §0-fp 实测）。
- 不动 `资讯-<日期>.md` / `index-<日期>.md` / 成稿 / 选题单的格式。
- 不动 GUI（工具面自动继承）。

**踩过的坑（记下来防复发）：**
- 单测里用 `temp_dir()/固定名` 当夹具，**并行跑会互相删**——过滤跑 7 个侥幸全过，整包跑立刻挂 2 个。

- 吕老师**真的会写短 ID**（实测框架表 `资本-037`、台账 `20260921-资本-037` 并存；**这两个例子用的是当时的 ID 写法**）。工具不容错就是死路；
  但容错必须**有边界**：短 ID 只落在指定那一期，抬头回全 ID。

## 3. 测试（Test）

**单元（确定性，不需要模型）**：`cargo test -p hermes-tools --lib material` → **9 passed**
（单条不带行号、多条按序回来、未知 ID 明说且不牵连其他条、索引缺失不编、形状错、缺 ID、
全/短 ID 解析、`date` 校验）；整包 `cargo test -p hermes-tools` → **152 passed**；
`cargo test -p hermes-core --lib persona` → **30 passed**；`cargo clippy -p hermes-tools -p hermes-core --all-targets` → **无告警**。

**小宋实跑（隔离数据根 `/tmp/lebi-idx`，素材 = 今天的 182 条）**

| | 改前（0.3.0） | 改后（0.4.0） |
|---|---|---|
| 工具调用 | `read`×11 + `grep`×1 + `write`×1 + `bash`×2 = **15** | `read`×1 + `material_read`×**1** + `write`×2 + `bash`×2 = **6** |
| 取料那一段 | `grep` 1 次 + `read(limit=3)` **10 次** = 11 个来回 | **1 次调用取回 10 条** |
| 工具结果字符 | ≈11,791 | ≈10,793 |
| 成稿 | 落盘 | 落盘；口播正文 **564 汉字**（540 ±20% 内）；出处逐条带链接 |

- 模型这次给的就是**短 ID**（`资本-037`，当时的 ID 写法）——容错那条判断被真实数据验到；抬头回来的是全 ID。
- 剩下的 `write`×2 / `bash`×2 是模型自己的行为（写一遍、数一遍字数、再收一版），不是取料成本。

**没做的测试（诚实写）**：`cargo test --workspace` / `clippy --workspace` 仍未跑（留到收口统一跑）；
吕老师那一棒没有重跑（契约改用同一个工具，链路更短，但没实跑取证）。
