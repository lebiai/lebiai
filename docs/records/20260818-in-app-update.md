## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「软件都该有自动更新」；不是应用商店；不是启动弹窗；不是让人去网页下包。
- **拆出的真：**
  1. 用户要完成的事：正在用的桌面应用换成更新的同一份应用，数据还在。
  2. 谁说了算：用户点「更新」才换；没点就不换。
  3. 数据在哪：用户数据仍在本机数据目录；换的是应用文件。新包是不是我们打的，靠更新器签名，不靠用户目测文件名。
  4. 这一步实际发生什么：应用问清单有没有更高版本 → 用户点一下 → 下载、验签、覆盖、重启。
  5. 用户看见什么：设置概览一行。有新版本就一个按钮。点完是进度，完了是重启后的新版本。
- **如何从真推出：** 入口放在概览（「现在能不能好好用」的状态卡）。关掉 Tauri 自带对话框。GitHub 只当文件仓库，界面永不出现。私钥不进 git。没点就不装。

---

## 0. 用户价值

- **谁用：** 桌面 GUI 用户。
- **解决什么痛点：** 知道有新版本之后，还要自己找包、下、装，步骤长，还容易下错。
- **用完后用户多得到什么：** 设置里看见 → 点一下 → 等它重启。步骤少，不离开应用。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期（检查 / 有新版本 / 进度 / 失败）
  - [x] 不增加无意义确认（点「更新」即授权下与装；不套第二层「你确定吗」）
  - [x] 主操作一眼能找（概览一行主按钮）
  - [x] 高频路径步骤少：打开设置 → 点更新

---

## 0b. 产品经理视角

- **场景：** 用户在桌面 GUI，打开设置，想知道是不是最新，若不是就换上。
- **怎么走完：** 先看见概览版本行 → 有新版本时主操作是「更新」→ 共 1 次点击 → 失败停在同一行点「重试」。
- **看起来怎么样：** 与对话就绪 / 授权 / 微信同一套 `StatusRow`。有新版本用警告色，不恐吓。进度只改副文。失败用人话。
- **好走 / 好看：** 不新开页、不进「更多」、不打断对话。缺 Key 时配模型仍是唯一强 CTA。
- **成功标准：** 不靠人从旁指点，用户自己能在概览走完；重启后版本号变了；数据还在。
- **明确不做什么：** 静默更、强制更、启动弹窗、送到浏览器、第 6 个 Tab、对话页横幅。

---

## 0c. 架构师视角

- **根因层级：** 分发协议缺失。应用不读清单、不验签、不换自己。现有 CI 只产给人手安装的 dmg/exe。
- **正确的长期默认路径：** 发版同时产更新器包 + `latest.json`；已带更新器的桌面应用打开概览就对照清单；用户点了才下、验、装、重启。
- **与引擎/各入口边界：** 只动 `hermes-gui` 与 `release.yml`。不进 `hermes-core`，不改 CLI / server / Flutter / IM。
- **安全影响：** 更新器签名强制且 fail-closed。私钥仅本机 + Actions secrets。清单 HTTPS。不改数据目录权限模型。CSP 不用为更新开口（下载在 Rust 侧）。
- **如何防复发：** 规格写死入口、触发、产物、密钥位置；发布说明在真机点通之前不准写「应用内更新已交付」。
- **为何这不是补丁：** 补的是发版默认路径，不是给设置页加一个外链。

---

## 1. 方案（Plan）

- **目标：** 桌面 GUI 在设置概览点击后完成更新，用户不离开应用。
- **范围：**
  - **做：** 规格（本文 + `spec/in-app-update.md` + 概览加版本行写入 `settings-ia.md`）；确认后按 U0–U3 实施。
  - **不做（本轮）：** 写代码、升版本、打 tag、生成密钥。
- **用户路径变化：** 改前：设置里没有版本这件事。改后：概览一行，有新版本点「更新」即换上。
- **技术要点：** `tauri-plugin-updater` + `tauri-plugin-process`；`createUpdaterArtifacts`；Release 挂 `latest.json`；endpoint 为 `.../releases/latest/download/latest.json`。
- **风险与回滚：**
  - GitHub 在部分网络下慢或失败 → 行内失败 + 重试；不另建源。
  - 私钥丢失 → 该公钥对应的已装版本无法再走应用内更新，只能重新发安装包并换公钥（等于新链）。
  - 未签名安装包更新后，系统仍可能按首次打开拦截一次（既有安装说明，不在本方案扩 scope）。
  - 回滚：下一版可关概览按钮并停产 `.sig`；已装的更新器只是多一次失败检查。
- **方案确认：** [x] 已对照 P0/P1（含第七条）· 2026-08-18 用户说开工
