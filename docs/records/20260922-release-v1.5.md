## 0-fp. 第一性原理

- **拒绝的类比：** 不是把十几天的改动塞进 1.4 的包（客户端会拿不到新契约）；不是在说明里写没实现的能力
  （侧栏增删改人物、一键切过去、输入框提示语跟人物变——这三条这一版都没有）。
- **拆出的真：** 1.4 之后的工作树里躺着**一整层新东西**（项目组与接力、团队名册与授权按人物开关、
  采集的名单/窗口/格式、审稿标准 V1.0、按 ID 取料、口播契约），它们**已经互相依赖**——
  契约文本是 `include_str!` 编进二进制的，少发一版，客户端拿到的就是旧契约。客户要的是
  **一个能装、能配 Key、能开项目组干活的包**，那就必须换版本号、换说明、换 tag。
- **如何推出：** 升 1.5.0（四处对齐）→ 重写 `docs/releases/release-notes.md`
  （只写本版真有，并把「明确没做的」列出来）→ 全量门禁 → 推 `main` → 打 `v1.5.0` →
  `release.yml` 在 macos-14 / windows-latest 上产出 dmg / NSIS setup.exe 并挂 Release。

## 0. 用户价值

侧栏从「几个工位」变成「**一张会接力的桌子**」：喊一声采今天的资讯，王海燕采全 → 吕老师出选题单等你点头 →
小宋写成稿；产出按天落在 `outputs/<日期>/`。安装包在 GitHub 可下；1.4 用户可在设置里点「更新」升上来。

## 0b–0c

沿用既有发布链路（`release.yml` + `check-updater-secrets.sh` 验签密钥注入；
`body_path` 固定 `docs/releases/release-notes.md`；私钥不进 git，走 Actions secrets）。
**本机不构建安装包** —— Tauri 的 dmg 只能在 macOS 宿主构建、Windows exe 只能在 Windows 宿主构建，
交给 CI 是唯一正确的默认路径（`scripts/build-dmg.sh` 只是本机调试用的同一份逻辑）。
