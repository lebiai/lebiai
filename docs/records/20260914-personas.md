## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：**
  1. 不是「抄 Claude Code 的 subagent / 多智能体框架」。那套把子代理当**并发执行单元**；用户要的不是并行算力，是**分工与归属**（谁负责什么、这条记忆是谁的）。
  2. 不是「会话改个标题 + 存一段提示词」（最薄做法）。它给不了硬拦的判定依据，也分不了记忆归属——只能当 demo。
  3. 不是「把人物做成技能的一种」。技能是**按需加载的说明书**；人物是**会话的宿主 + 记忆归属 + 可判定的硬边界**。塞进技能会让"技能"这个概念变重，且 P0 第八条四类里没有这一层。
  4. 不是「一个客户一个编译版本」来实现"只给他 3 个角色"。不可运营，否决。
- **拆出的真（实测/已核实，不是推演）：**
  1. 用户在真实工作里**按身份找人**：写新闻稿找记者、看林碳找行业专家。今天的系统只有"一个搭子 + 一堆会话"，用户只能拿**会话标题**和**技能触发词**手工模拟分工——实证：数据根里已有 `skills/xiao-wang`、`xiao-wang-2`、`xiao-wen`，侧栏里对应"小王 干活""小文干活"。
  2. "只做一件事"必须**可判定**：没有明确职责清单，硬拦只是一句客气话。
  3. 记忆天然分两种：**关于用户本人的偏好**（全局）与**某专业口径**（属于这顶帽子）。今天 `MemoryFrontmatter` 只有 `id/created/source/confidence/pinned/tags/zone/supersedes`——**猜不出归属**（已核对字段）。
  4. 谁说了算：**名单与角色设定是产品方定**（用户不增删改）；用户说了算的是"在哪顶帽子下干活、切不切过去"。
  5. 数据在哪：本地明文，一条不出机器；授权决定开放哪些角色，**不引入我方服务器**（P0 本地优先 + 无账号）。
  6. 用户看见什么：打开 App 就先看见"我的那几个工位"，而不是一张空白对话。
- **如何从真推出：**
  - 真 1 + 6 → 会话要挂人物（`SessionMeta.persona`），侧栏工位常驻。
  - 真 2 → 人物定义写**具体清单**（我干的/我不干的）+ 拒绝必须指路 + **一键切过去**（把误拦的代价降到一次点击）。
  - 真 3 → 记忆长 `owner` 轴（空 = 全局）；**注入隔离、管理可见**；主题卡按可见范围分区。
  - 真 4 → 定义**编译进二进制**、名单由**签名授权**给出、**不做**用户侧管理界面。
  - 真 5 → 不做远程拉取定义；未知 id 忽略但不静默。
  - 由"可判定"再推 → 人物分**兜底**（不拦）与**专职**（硬拦）两类，硬拦落成三层（稳定层 / 不给执行路径 / 交接由用户点）。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 桌面 GUI 为主（手机 / IM 走同一引擎）。
- **解决什么痛点：** 今天所有活挤在一个搭子 + 一堆会话里，用户得靠"会话标题"和"技能触发词"自己记谁是谁；专业口径和私人偏好混在同一个记忆池里；说得再多，"它"也不知道自己该干到哪儿为止。
- **用完后用户多得到什么：** 打开就看见"我的那几个工位"；进谁的屋说谁的话；越界的活被顶回来但**旁边就有路**；专业口径彼此不串味，而关于自己的偏好处处生效。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库（定义在二进制，数据仍明文）
  - [x] 步骤可感知、可预期（输码后工位可见地多出来）
  - [x] 不增加无意义确认（只在越界时给一次"要不要过去"）
  - [x] 主操作一眼能找；空 / 载 / 错态完整
  - [x] 高频路径更短（不用建会话、不用翻标题）

## 0b. 产品经理视角（必填 · 禁止跳过）

### 场景
用户手上同时有几摊事：给中国财富网写稿、盯林碳行业、临时查资料。今天他只能开一堆会话、靠标题认人。

### 界面规划（逐屏）

**侧栏**：去掉「最近对话」与「+ 新对话」；常驻区列出工位（`名字 · 一句话职责`），自带两个（搭子小乐 / 工具人李现）在前，授权角色在后；下方仍是「它记得的 / 设置」；页脚「小乐 · 你的搭子」。

**工位内**：顶部一行「小张 · 盯林碳」；输入框提示语跟着人物变；其余与今天一致（对话、工具、过程折叠）。

**越界时**：一句拒绝（人设口吻）+ 一行指路 + 一个按钮「去小小小王 →」；点击后切过去，原话跟着过去并标「从小张那边转来」。

**「它记得的」**：逐条列表每行一个归属标签（全局 / 小张 / …）+ 一项筛选；主题 tab 顶部一个归属选择器，默认「全局」；管理页新建默认全局。

**空 / 载 / 错态**：工位空态用定义里的 `empty_hint`；一键切失败回一句人话 + 原按钮；名册里有不认识的 id 时设置里一行提示。

### 文案
用户主词仍是**对话** / **搭子**；新增「工位」「人物」只在必要处出现（侧栏不写"工位"二字，直接列角色名）。禁止词不变（聊天 / 搭档 / 工作伴侣）。

### 好走 / 好看
主操作唯一（选一个角色进去说事）；列表层级清楚（自带在上、授权在下、分隔线）；不出现两个重复入口。

### 成功标准
用户不靠人教，15 秒内知道"我该找谁"；越界时不会卡住（旁边就有路）。

### 明确不做什么
不做人物管理界面；不做自动路由；不做人格；不主动删用户数据。

## 0c. 架构师视角（必填 · 禁止修修补补）

### 根因层级
今天缺的不是"会话分组"，而是三样互相关联的东西同时缺位：**会话没有身份**（`SessionMeta` 只有 id/created_at/model/provider/title）、**记忆没有归属**（无 owner）、**身份协议不可叠加**（`companion.rs` 是唯一源码，人物只能叠加不能覆盖）。

### 正确的长期默认路径
- 定义**编译进二进制**（单一真源，与身份协议同法）；名单来自**签名授权**；显示与执行**只认签名名单**。
- `SessionMeta.persona: Option<String>`（旧文件缺省 = 无人物，可读）；`MemoryFrontmatter.owner: Option<String>`（缺省 = 全局，**零迁移**）。
- 注入：人物会话只给「全局 + 本人物」；反思落盘按会话人物打标。
- 主题卡按可见范围分区（全局一份 + 每个专职人物一份）。
- 人物块在系统提示里**固定在搭子协议之后**，顺序写成断言。

### 与引擎/各入口边界
引擎层承载人物（定义、注入、归属、别名解析），**不为某个入口写私有逻辑**；GUI 全量、server/Flutter **最小贯通**（归属必须写对，否则数据被写歪）、CLI `--persona`、IM 渠道级固定人物。

### 安全影响
不新增网络面、不引入我方服务器；授权仍是本机验签、不绑机、无账号；本地明文不变。已知取舍：未购买角色的定义在二进制里可被逆向（见规格 4.5）。

### 如何防复发
- 顺序断言：人物块必须在搭子协议之后，且不得覆盖身份协议。
- 隔离测试：人物会话不广告未绑定技能；检索不跨人物。
- 归属测试：反思不得把"关于用户的偏好"挂到某人物名下。
- 兜底测试：搭子小乐不触发拒绝。

### 为何这不是补丁
它补的是**会话身份 + 记忆归属**这两根从第一天就缺的轴，并把"越界"从一句提示词升级为**可判定的边界 + 无执行路径 + 明确的交接动作**；不是给旧逻辑叠一个 if。

`1.5-a` 我最初的规则 4 写的是「没写 → 全局」，**它与规格 §5.2 直接冲突**：§5.2 原文是「写入自动打标：**在谁的会话里说的就归谁**，`memory_save` **不需要模型自己填**」，Task 1.6 工单的验收断言也是 `memory_save` 落盘后 `owner == Some("lin-tan")`。照我的原规则实现，1.6 当场验收失败，而且归属轴会形同虚设——绝大多数记忆都会落成全局，工位隔离等于没做。

修正后的**唯一判定点**：

```rust
pub enum OwnerDefault { Session, Global }   // 没写 owner 时往哪边倒
pub fn resolve_owner(
    session_owner: Option<&str>,
    asked_owner: Option<&str>,
    zone: &str,
    default: OwnerDefault,
) -> Option<String>
```

1. `session_owner` 空 → 全局（自带角色靠调用方的 `Persona::memory_owner()`，函数内不判 `builtin`）。
2. `zone ∈ {preferences, standards}` → 全局（用 `hermes_core::companion::zones` 的 `normalize`/`is_preferences`，不手写字符串比较）。
3. `asked_owner` == `session_owner` → 归该人物。
4. 其余：`OwnerDefault::Session` → 归该人物（§5.2 的「自动打标」）；`OwnerDefault::Global` → 全局（§5.3 反思的安全方向）。

```rust
//! Persona (人物/工位) definitions — compiled in, product-owned, never user data.
//!
//! A persona is a **hat, not a second personality**: it narrows what the
//! companion takes on and how it talks, never how it treats the user
//! (`docs/spec/personas.md` §6.3).

use std::sync::OnceLock;

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum PersonaKind {
    /// 专职：越界硬拦 + 指路 + 可一键切。
    Dedicated,
    /// 兜底：不拦——"其他人物不干的"就是它的活。
    Fallback,
}

#[derive(Debug, Clone, serde::Deserialize)]
pub struct Persona {
    pub id: String,
    pub name: String,
    pub role: String,
    pub voice: String,
    #[serde(default)]
    pub skills: Vec<String>,
    pub kind: PersonaKind,
    /// 自带角色：谁都有（不进授权码），且其会话产生的记忆算全局。
    #[serde(default)]
    pub builtin: bool,
    pub empty_hint: String,
    pub version: String,
    #[serde(skip)]
    pub body: String,
}

impl Persona {
    /// 会话里产生的记忆归谁。自带角色是地基不是专业分工 → 一律全局。
    pub fn memory_owner(&self) -> Option<&str> {
        if self.builtin { None } else { Some(self.id.as_str()) }
    }

    pub fn is_fallback(&self) -> bool { self.kind == PersonaKind::Fallback }
}

const SOURCES: [&str; 4] = [
    include_str!("personas/xiao-le.md"),
    include_str!("personas/li-xian.md"),
    include_str!("personas/lin-tan.md"),
    include_str!("personas/xiao-wang.md"),
];

fn parse(raw: &str) -> Persona {
    let mut it = raw.trim_start().splitn(3, "---");
    let (Some(""), Some(yaml), Some(body)) = (it.next(), it.next(), it.next()) else {
        panic!("persona definition must open with a --- YAML frontmatter block");
    };
    let mut p: Persona = serde_yaml::from_str(yaml).expect(
        "persona frontmatter needs id/name/role/voice/kind/empty_hint/version",
    );
    p.body = body.trim().to_string();
    p
}

pub fn all() -> &'static [Persona] {
    static ALL: OnceLock<Vec<Persona>> = OnceLock::new();
    ALL.get_or_init(|| SOURCES.iter().map(|raw| parse(raw)).collect())
}

pub fn get(id: &str) -> Option<&'static Persona> {
    all().iter().find(|p| p.id == id)
}

pub fn ids() -> Vec<&'static str> { all().iter().map(|p| p.id.as_str()).collect() }

pub fn builtins() -> impl Iterator<Item = &'static Persona> { all().iter().filter(|p| p.builtin) }

/// 稳定层文本。调用方负责把它放在搭子协议**之后**（规格 §6.1）。
pub fn block(p: &Persona) -> String {
    format!(
        "## 你现在是谁\n\
         你是 **{name}**，工位是「{role}」。\n\
         说话方式：{voice}\n\n\
         {body}\n\n\
         ## 人设红线\n\
         上面写的是「怎么说」和「干什么」，不是「怎么待用户」。\
         关系基调与交互结构（接住 → 说清张力 → 给选项 → 由用户定）\
         与乐彼AI 的身份协议完全一致，不得因为戴了这顶帽子就改掉。\n",
        name = p.name, role = p.role, voice = p.voice, body = p.body.trim()
    )
}
```

/// 注入隔离：全局 + 本人物的可见；别人的一条不给
/// （`docs/spec/personas.md` §5.2；管理页不受此限——「注入隔离，管理可见」）。
pub fn visible_to(m: &LoadedMemory, owner: Option<&str>) -> bool {
    match m.frontmatter.owner.as_deref() {
        None => true,
        Some(o) => Some(o) == owner,
    }

pub fn filter_visible<'a>(items: &'a [LoadedMemory], owner: Option<&str>) -> Vec<&'a LoadedMemory> {
    items.iter().filter(|m| visible_to(m, owner)).collect()
}

```rust
//! A per-persona view of a [`MemoryStore`].
//!
//! The store itself stays persona-agnostic: 归属 is one filter, not a second
//! storage layout. Writes made through a scoped view are stamped automatically
//! (the model never fills `owner` by hand); reads only ever return globals plus
//! the owner's own memories.

use std::path::PathBuf;
use std::sync::Arc;

use crate::memory::{filter_visible, visible_to, LoadedMemory, MemoryFrontmatter, Scope};
use crate::store::{MemoryStore, Result};

pub struct ScopedMemoryStore {
    inner: Arc<dyn MemoryStore>,
    owner: Option<String>,
}

impl ScopedMemoryStore {
    pub fn new(inner: Arc<dyn MemoryStore>, owner: Option<String>) -> Self {
        Self { inner, owner }
    }

    fn visible(&self, items: Vec<LoadedMemory>) -> Vec<LoadedMemory> {
        let keep = filter_visible(&items, self.owner.as_deref());
        let ids: std::collections::HashSet<&str> = keep.iter().map(|m| m.id()).collect();
        items.into_iter().filter(|m| ids.contains(m.id())).collect()
    }
}

impl MemoryStore for ScopedMemoryStore {
    fn list(&self) -> Result<Vec<LoadedMemory>> { Ok(self.visible(self.inner.list()?)) }
    fn list_active(&self) -> Result<Vec<LoadedMemory>> { Ok(self.visible(self.inner.list_active()?)) }
    fn list_pinned(&self) -> Result<Vec<LoadedMemory>> { Ok(self.visible(self.inner.list_pinned()?)) }

    fn get(&self, id: &str) -> Result<Option<LoadedMemory>> {
        Ok(self.inner.get(id)?.filter(|m| visible_to(m, self.owner.as_deref())))
    }

    fn put(&self, scope: Scope, mut frontmatter: MemoryFrontmatter, body: &str) -> Result<PathBuf> {
        if frontmatter.owner.is_none() {
            frontmatter.owner = self.owner.clone();
        }
        self.inner.put(scope, frontmatter, body)
    }

    fn delete(&self, scope: Scope, id: &str) -> Result<bool> {
        match self.inner.get(id)? {
            Some(m) if visible_to(&m, self.owner.as_deref()) => self.inner.delete(scope, id),
            _ => Ok(false),
        }
    }

    /// 先过滤再排序，不是「取 top-k 再过滤」——否则本人物的记忆会被别人的挤掉。
    fn search(&self, query: &str, k: usize) -> Result<Vec<LoadedMemory>> {
        let active = self.list_active()?;
        Ok(crate::relevance::search_memories(&active, query, k)
            .into_iter()
            .cloned()
            .collect())
    }

    fn check_near_duplicate(&self, body: &str, threshold: f64) -> Result<()> {
        self.inner.check_near_duplicate(body, threshold)
    }
}
```

/// 由 [`dispatch`] 路由的记忆工具名。`BuiltinToolHost` 与 `PersonaToolHost`
/// 共用这一张表——记忆面只允许有一个路由表。
pub fn handles(name: &str) -> bool {
    matches!(name, "memory_search" | "memory_save" | "memory_delete" | "memory_distill")
}

/// 路由一次记忆工具调用。`None` = 不是记忆工具，调用方继续往下走。
pub async fn dispatch(
    store: &dyn MemoryStore,
    name: &str,
    args: serde_json::Value,
) -> Option<Result<ToolCallOutcome>> {
    match name {
        "memory_search" => Some(run(store, args).await),
        "memory_save" => Some(save_run(store, args).await),
        "memory_delete" => Some(delete_run(store, args).await),
        "memory_distill" => Some(distill_run(store, args).await),
        _ => None,
    }

//! Per-persona view of the tool surface.
//!
//! The tool host is built once per process and shared by every session, so it
//! cannot know which persona is talking. This wrapper is built **per turn**
//! (cheap — it borrows the inner host) and routes the memory tools through a
//! [`ScopedMemoryStore`]. Everything else falls through untouched: this is a
//! view, deliberately not a second host.

use std::sync::Arc;

use async_trait::async_trait;
use hermes_core::{Error, Result, ToolCallOutcome, ToolHost, ToolSpec};
use hermes_memory::{MemoryStore, ScopedMemoryStore};

use crate::memory;

pub struct PersonaToolHost {
    inner: Arc<dyn ToolHost>,
    store: Option<Arc<dyn MemoryStore>>,
    owner: Option<String>,
}

impl PersonaToolHost {
    pub fn new(
        inner: Arc<dyn ToolHost>,
        store: Option<Arc<dyn MemoryStore>>,
        owner: Option<String>,
    ) -> Self {
        Self { inner, store, owner }
    }
}

#[async_trait]
impl ToolHost for PersonaToolHost {
    async fn list_tools(&self) -> Result<Vec<ToolSpec>> {
        self.inner.list_tools().await
    }

    async fn call(&self, name: &str, args: serde_json::Value) -> Result<ToolCallOutcome> {
        if memory::handles(name) {
            if let Some(store) = &self.store {
                let scoped = ScopedMemoryStore::new(store.clone(), self.owner.clone());
                return memory::dispatch(&scoped, name, args)
                    .await
                    .unwrap_or_else(|| Err(Error::ToolHost(format!("unknown memory tool: {name}"))));
            }
        }
        self.inner.call(name, args).await
    }
}

- **如何从真推出**：A 抽出 `fn resumed_persona_or_none(identity: ResumedIdentity<'_>, path: &Path) -> Option<&'static Persona>`（`Unknown` → `tracing::warn!` + `None`），`run` 只调它，测试直接钉三态；B 两处改读 `hermes_core::companion::tags::is_episode_tag`，**保留**原来的 `zones::is_work(zone)` 与 `body.contains("【工作情节】")` 两条或条件，各补一条带空格 tag 的测试。

## 4. 验收（Accept）

**阶段 1 的验收口径（2026-09-15 收）**：阶段 1 是**用户看不见的地基**，所以它的验收不是产品目视，而是**四条引擎级承诺 + 一条不变量**：

1. **会话带身份**：新会话把人物写进 `meta.persona`；续会话以**文件**为准，命令行与文件冲突**报错**（不静默改身份）。
2. **记忆有归属轴**：写入自动打标（在谁的会话里说的就归谁；两个自带角色与偏好/标准归全局），读写都按「全局 + 本人物」；判定点仍各只有一处。
3. **反思分流**：关于用户本人的落全局，专业口径归当前人物（模型不说清 → 落全局，安全方向）。
4. **主题卡是派生视图**：按视图合并，全局 + 自己，同 id 以自己为准。
5. **不变量**：**「人物会话只看得到自己的记忆」在四条读面 + 一条写面上都成立**——注入切片（`views_for`）、slash 显示面、`palace_*` 三件套、subagent 的**读**、以及 subagent 的**写**；外加「`profile.md` 只装全局口径」（它是被所有视图注入的那个文件）。

**验收方式**：`hermes chat --persona <id>` 在临时数据根上端到端跑（存 → 换工位搜 → 换回搜得到），加 §3 的全量测试与突变证伪。**证据落点**：§2.0.1 每个任务行 + §3。
