## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是因为「别人家人设都写得很长」「多写点保险」「注释多便于维护」。
- **拆出的真：** 这份文件**每个字符都进模型上下文、都被当成现行命令读**。所以：① 任何一句「当初为什么这么定」都会被当成规则执行；② 任何一处指向已删站的示例都会被照抄成一次抓取；③ 同一件事写两处，就一定会有一天两处不一样（今天已经发生：统计行规格 vs bash 实际输出）。真只有三条 —— **契约只装现在必须做的动作 / 每个细节只有一处 / 出现的站名与路径必须当前存在**。
- **如何从真推出：** 删三类句子（变更史、实测 anecdote、给未来的备忘录），把重复三处的删除名单收成一份，把模板里写死的日期与已删站示例换成本轮真实可复制的内容；现行规则一字不动。历史不是丢掉，是**归位到本台账**。

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户在项目组里让王海燕开工；她读契约 → 派六个子代理 → 接栏 → 交卷。用户看见的是**卷 + 文末统计行**。
- **怎么走完：** 改前，契约里并存「六块 / 七块 / 1a 官方块」「Wind 已移出 / 不编造 Wind」「官方源为第一真值 / 官方源已删」等互相打架的句子，模型得自己猜哪句算数。改后，每节只有一句现行做法，模板可原样复制。
- **看起来怎么样：** 章节层级不动（我干什么 → 我不干什么 → 时间窗口 → 全量 → 校验 → A/B/C → 输出格式 → 怎么采 → 红线 → 名单 → 采集怎么跑 → 拿不到 → 越界），下游与用户的阅读习惯不被打断；删的是行内的史，不是节。
- **好走 / 好看：** 用户面（卷 / 统计行 / 对话里的清单）**一个字都没改** —— 这一批是给执行者看的，不是给用户看的；成功与否由「卷还一样、不再出现已删站」判定。
- **成功标准：** 跑一轮采集，卷与统计行格式不变、无已删站条目、无落到昨天目录。
- **明确不做什么：** 不改条目格式、不改名单成员、不改块数、不动工具与并发机制；不动「谁在手上」那个显示问题（另开一批）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 提示词 / 契约层（`crates/hermes-core/src/personas/*.md`，经 `include_str!` 编译进引擎 —— CLI / GUI / server / IM 同源）。
- **正确的长期默认路径：** 契约 = **现行规则的唯一副本**；版本沿革的归属地是 `docs/records/`；机器生成物（索引、统计行）由主循环那两条 `awk` **一处**生成，契约只描述「长什么样」。

- **如何防复发：** 原有防回归测试继续钉死锚点（20 站 / 六块 / 无 Wind 表行 / 无 `1a-宏观-官方` / 无「三个子代理」/ 三种日期写法 / 索引 ID 规则）；「不许留史」这一类由本台账与文档铁律（根目录只许 4 个 md、其余进 `docs/`）把关。
