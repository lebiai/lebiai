## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 终端客户（无技术背景）+ 所有入口使用者
- **解决什么痛点：** 「工作伴侣 / AI 同事 / 搭档」的框架暗示「替我干活的分工关系」，容易把 AI 用成工具、把对话变成下达指令；用户要的是**陪你一起做**的在场感和默契——「搭子」才说得清这种关系
- **用完后用户多得到什么：** 关系基调从「雇了个帮手」变成「多了个懂我的搭子」：更愿意开口、更敢让它较真、更愿意教它——直接强化爱上 ①被理解 ④有来有回 ⑤第二次更顺
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期（纯定调 + 文案，无行为变化）
  - [x] 不增加无意义确认或噪音
  - [x] 高频路径比改前更省心（一句话说得清「它是什么」）

---

## 0b. 产品经理视角

- **场景：** 客户第一次打开应用（引导页 / 欢迎语 / 侧栏副标题），或向朋友介绍「乐彼AI 是什么」
- **路径变化：** 改前：工作伴侣 / 同事 / 搭档（分工替活）→ 改后：**搭子**（陪你一起把事做成，平等、在场、有来有回）
- **成功标准：** 权威文档与全部用户可见文案统一为「搭子」调性；不再出现「工作伴侣 / AI 同事 / 搭档」作为关系主词
- **明确不做什么：** 不改 Slogan（越用越像你的手感）与一句话；不改产品名；不动技术层（crate 名、companion 协议内部标识）
