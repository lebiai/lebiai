## 0-fp. 第一性原理（必填 · P0 第零条）

**拒绝的类比：**「学数据库那一套 —— 建表、写库、用 SQL 查」。这个类比的错处是：它假设
瓶颈在「存得乱」，于是把力气花在**换存储引擎**上。真正要从头推的是：**为什么慢、为什么贵。**

**拆出的真（今天实测，可核对）：**
项目组会话 `test/sessions/2026-09-20T07-38-43-a4a4d465.jsonl`（1039 条事件 / 68 轮）：

| 量 | 实测 |
|---|---|
| 累计输入 tokens | **≈ 2,000 万**（1,503 万 + 缓存 495 万） |
| 单轮输入 | 中位 **12.4 万**，最大一轮 **216 万**（那轮跑着六个子代理） |
| 累计输出 tokens | 86 万 |
| `read` 吐回正文 | `资讯-2026-09-21.md` **16 次 ≈ 7.9 万字**；`选题单-2026-09-21-重出.md` **13 次 ≈ 5.9 万字**；`资讯-2026-09-20.md` 7 次 ≈ 4.4 万字；合计 **≈ 23.5 万字** |

拆开来，贵的不是「读文件」，是**同一份东西被反复整读**，和**下游拿到的是比原料还大的衍生品**
（`选题单-重出` 48KB > `资讯` 33KB）。换成 SQLite 一分钱不省：`SELECT *` 回来的东西一样整个进上下文。

**如何从真推出做法（三件，与「数据库」无关）：**
1. **稳定 ID** —— 接力棒只传 ID，正文不必搬来搬去；
2. **一份索引** —— 先看轻的一层（ID/等级/来源/时间/一句线索），要细节再按行号取那一条；
3. **衍生品不许比原料大** —— 选题单只写「ID + 秒数 + 角度」，不抄概要。

**为什么不用真数据库：** P0 要求数据本地**明文**、用户能直接打开、能 grep/diff —— 文件库符合，
SQLite 是二进制，破线且用户无感；而且引真库要带 C 编译（Windows 打包）或让用户装，正好踩
AGENTS 自检第 1 条。**第二步**再评估接已有的 `hermes-sources`（`catalog.json` + `body.md` + 倒排索引，本身就是文件库）。

## 0. 用户价值（必填）

用户连续两天报的痛点是**慢**。今天实测把慢归到一处：**同一份材料在会话里被反反复复整读**，
以及**衍生品比原料还大**。这一批做的事，让「采 → 选 → 写 → 播」四棒各自**只读自己该读的那点东西**：
- 吕老师不用再整读 33KB 素材，先扫索引、只取拟选那几十条的概要；
- 小宋不再读 48KB 选题单，拿 10 个 ID 精确取 10 条；
- 小雨只读成稿（本来就该如此，写进契约免得走回头路）。

预期：这一条链路的读入从实测 **≈23.5 万字** 降到 **≈1.5 万字** 量级。

## 0b. 产品经理视角（必填）

- **用户怎么走完**：王海燕交卷时，工作区里除了 `资讯-<日期>.md` 还多一份 `index-<日期>.md`
  （一条一行，人是能读的）。用户照旧在对话里看到全量清单（这条不变，是他要的）。
  吕老师报题时，用户看到的是一张**短单**：序号｜ID｜秒数｜角度，底下一行一条的弃稿台账。
  用户点头后，小宋按 ID 取料成稿。
- **看起来怎么样**：`outputs/<日期>/` 里现在是两个文件：`资讯-<日期>.md`（成品）+ `index-<日期>.md`（目录）。
  索引用 `｜` 分隔、一条一行，用户在编辑器里打开就能扫。
- **空 / 载 / 错态**：索引缺失 → 吕老师必须**明说「索引没落盘」并退回读素材**（不许假装扫过索引）；
  索引里某条行号取不到内容 → 记一笔，不编。
- **成功标准**：吕老师这一棒的读入量降一个数量级；选题单体积降到个位数 KB 且**逐条带 ID**；
  小宋的 read 只命中 `limit=3` 左右的短读；成品格式与用户定死的三行**一字不改**。
- **不做什么**：不引数据库；不动成品格式（ID **不进正文**）；不给用户增加新操作步骤。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因（一处）**：产物只有「一份大文件」这一个粒度，下游没有**更轻的一层**可用，
  于是每个下游都只能整份读；而写下来的衍生品又各自把概要抄一遍。
- **正确默认路径**：产物分两层 —— **成品**（给人看，格式定死）+ **索引**（给下游读，一条一行）。
  索引是**唯一**的 ID 来源，ID 由主循环的 `awk` **确定性**生成（不是模型随手编号）。
- **边界**：
  - ID 格式 `<YYYYMMDD>-<栏>-<NNN>`，栏 ∈ {宏观, 产业, 资本}，NNN 三位、从 001 起、按成品里出现顺序。
    **确定性生成**：同一份 `_parts` 跑两次必须得到同一套 ID。
  - 索引列：`ID｜等级｜来源｜时间｜线索｜链接｜L<行号>`；`L` 是**成品里这条的起始行号（1 起）**，
    取正文用 `read(offset = L-1, limit=3)`（`read` 的 offset 是 0 起）。
  - **线索**列 = 概要的第一句（按「，」切、攒到 ≥45 个汉字为止，再补「…」）——
    用**分隔符切分**而不是按字符截断，避免 BSD awk 把汉字切半。
- **怎么落地（改谁）**：见 §1 范围。
- **防复发**：`persona.rs` 加守卫 —— 王海燕契约必须含索引与 ID 规则；吕老师契约必须含
  「先读索引」「不许整读素材」；小宋契约必须含「按 ID 取一条」。

## 1. 方案（Plan）

### 共享规格（三个人物契约都按这一段写，不许各自发明）

```
素材两层：
  outputs/<日期>/资讯-<日期>.md     成品。格式一个字都不许动（等级/来源/时间 + 概要 + 链接，三行一条）。
  outputs/<日期>/index-<日期>.md    索引。一条一行，七列，用 ｜ 分隔：
      <ID>｜<等级>｜<来源>｜<时间>｜<线索>｜<链接>｜L<行号>
  ID = <YYYYMMDD>-<栏>-<NNN>，栏 ∈ {宏观|产业|资本}，NNN 三位从 001 起，按成品出现顺序。
  L<行号> = 这条在成品里的起始行号（1 起）。取正文：read(offset = 行号 - 1, limit = 3)。
  例：20260921-资本-007｜B｜中国证券报｜2026-09-21 07:54｜动力电池退役量逼近百万吨级｜https://…｜L412
```

### 做（四件）

1. **王海燕**（`wang-hai-yan.md` 1.1.0 → 1.2.0）：主循环那条 `bash` 在合并去重之后**多出一条 awk**，
   扫成品、按栏编号、落 `index-<日期>.md`（ID 确定性生成；**ID 不进正文**）。交卷那行加「索引已落盘」。
2. **吕老师**（`lv-lao-shi.md` 0.2.0 → 0.3.0）：筛选改成**先读索引**（一条一行，轻），
   据索引判进 / 不进；只对**拟选与拟弃的边界条目**按行号取概要核实。交卷格式改成
   「序号｜ID｜秒数｜角度」+ 弃稿台账「ID｜落在第几条标准」的**一行一条**。**禁止整读《资讯》。**
   `decision` 的 items 带 `id` 与 `seconds`。
3. **小宋**（`xiao-song.md` 0.2.0 → 0.3.0）：取料改成**按 ID**：`grep -n '<ID>' outputs/<日期>/index-<日期>.md`
   拿行号 → `read(offset=行号-1, limit=3)`。**禁止整读《资讯》与整读《选题单》。**
4. **小雨**（`xiao-yu.md` 0.1.0 → 0.2.0）：写死「只读成稿那一个文件；不进素材、不读索引、不读选题单」。

### 不做
- 不引 SQLite / 不接 `hermes-sources`（那是第二步，要单独评估）。
- 不动成品三行格式；不在正文里加 ID。
- 不动 `_parts` 的生成方式（那是上一批的事）。

**踩过的坑（记下来防复发）：**
- BSD awk（macOS 自带）**不认中文函数名** —— `function 线索(...)` 直接 `bailing out`。函数名一律 ASCII。
- 别用「按字符截断」写线索：BSD awk 是字节语义，会把汉字切半。**按分隔符切、按字节长度累加**才安全。

## 4. 验收（Accept）

**成功标准（§0b 定的）**：吕老师读入降一个数量级；选题单降到个位数 KB 且逐条带 ID；小宋只做短读；
成品格式一字不改。

| 项 | 旧（今天真实数据） | 新（本批） | 结果 |
|---|---|---|---|
| 选题单 | 48,746 B（`-重出`） | **13,538 B** | 3.6× 小，逐条带 ID + 一行一条台账 |
| 成稿 | 11,828 B | **3,770 B / 567 汉字** | 落回「540 字 ±20%」口径内 |
| 吕老师这一棒读入 | 整读 33KB 成品（今天实测同一文件被读 16 次） | 1 次索引 + 18 次定点读 ≈19.2k 字符，**整读 0 次** | 达标 |
| 小宋这一棒读入 | 整读 48KB 选题单（同一文件被读 13 次） | 1 次选题单 + 10 次定点读 ≈8.4k 字符，**整读 0 次** | 达标 |
| 两棒链路读入 | 基线实测 ≈23.5 万字 | **≈2.8 万字符** | ≈8.5× |
| 成品格式 | 用户定死的三行 | **一字未改**（ID 不进正文） | 达标 |

**实跑里发现的两件事（如实记，不藏）**
1. **吕老师的「角度」列会带进素材里没有的数字**：它给第 8 条写了「分拆限制期 3 年→1 年」，
   小宋按 ID 取回原文后**核不到这个数字**，主动标了出来并建议口播时改说法。→ 说明「交 ID 不交正文」
   这条路走得通（能查出来），但也说明**角度列不许写入素材里没有的事实**，下一批要收紧这条。
2. **CLI 的 `decision` 没接「谁定的」**：吕老师按契约要记一条 `kind: topic-list` 的决定，
   在 CLI 里被拒（「自由对话里没有人物」）。GUI 那条路是对的（`hermes-gui/src/commands/chat.rs:381`
   由引擎把「谁定的 / 哪一期 / 哪个组」盖上去），CLI 这个调试入口没接。**不影响用户默认路径**，
   记在这里待办。
