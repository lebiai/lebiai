## 0. 用户价值

- **谁用：** 所有在欢迎仪式里填写称呼的用户。
- **解决什么痛点：** 在欢迎页认真填了名字，进入产品后侧栏头像、设置页问候、对话欢迎页全都显示「游客/未设置」——用户以为产品丢了他们的信息。
- **用完后用户多得到什么：** 填一次，处处一致；改名也即时全端同步，不用重启。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期
  - [x] 不增加无意义确认或噪音
  - [x] 高频路径比改前更省心（无需重启）

---

## 0b. 产品经理视角

- **场景：** 首次打开 → 欢迎仪式填称呼 → 进入对话/设置/侧栏；日常改名。
- **路径变化：** 欢迎仪式无论走「保存并开始 / 开始 / 没有 Key 跳过」都会保存称呼；保存后立即同步到全部入口（无需重启、无需再次输入）。设置页改名沿用同一路径。
- **成功标准：** 欢迎页填「张强」→ 设置页问候「Hi 张强」、侧栏显示「张强」、对话欢迎页「你好张强」；改名后同样即时生效。
- **明确不做什么：** 不改变称呼的存储位置（仍是唯一一条 pinned memory）；不做多称呼/头像等新功能。

---

## 0c. 架构师视角

- **根因（双 bug）：**
  1. **后端解析缺陷：** seed 正文是 `用户自称「张强」。`（句号结尾），`onboarding_seed_get` 用 `strip_suffix('」')` 解析，永远失败 → 名字恒为空。
  2. **前端无同步：** 称呼只在 Settings/Sidebar 各自挂载时拉一次，欢迎仪式完成时底层组件早已挂载（读到旧值），且跳过路径根本不写 seed → 各入口显示不一致。
- **正确的长期默认路径：** 称呼是**结构化数据**，不再是靠正则解析散文正文；正文保留给引擎做 pinned 上下文。前端把 `uiStore.displayName` 作为**唯一前端数据源**，App 启动时一次性加载，欢迎仪式/设置写入后即时更新。
- **与引擎/各入口边界：** seed 仍是唯一 pinned memory（tag `onboarding-seed`），CLI/GUI 共读；新增结构化字段走 `MemoryFrontmatter.extra`（forward-compat 机制，不改共享类型 API）；旧数据（无字段的正文）保留一次性兜底解析（迁移）。
- **如何防复发：** 结构化字段 + 兜底解析拆为独立函数并单测覆盖（名字-only / 带场景 / 无名字 / 无关正文）；前端单一数据源消除各组件各自拉取的漂移。
- **为何这不是补丁：** 不是「修一行解析」堵症状，而是把称呼从「散文解析」提升为「结构化字段 + 单一前端源 + 即时同步」的正确默认路径，同时保留旧数据迁移。
- **安全影响：** 无新增网络/权限；称呼仍本地明文。

## 1. 方案（Plan）

- **目标：** 称呼填一次、处处一致、即时生效。
- **范围：** 做：① seed 落盘加结构化 `display_name` ② 读取先结构化后兜底解析 ③ App 启动加载进 `uiStore` ④ 欢迎仪式/设置写入后同步 `uiStore` ⑤ 欢迎仪式跳过路径也保存 ⑥ 删除 Sidebar 冗余拉取。不做：存储位置迁移、称呼新功能。
- **技术要点：** `serde_yaml` 从 dev-deps 移入 hermes-gui 正式依赖（命令内使用）；`display_name_from_body` 兜底解析（首个「」截止）。
- **风险与回滚：** 单文件小改动；回滚还原 `onboarding.rs` 与 4 个前端文件即可。

## 2. 实施（Implement）

- **后端 `crates/hermes-gui/src/commands/onboarding.rs`：** `onboarding_seed_set` 写入 `fm.extra["display_name"]`；`onboarding_seed_get` 优先读结构化字段，缺省回退 `display_name_from_body`（修复后的解析：截到首个 `」`）；新增 4 个单测。
- **前端：**
  - `App.tsx`：启动时 `onboarding_seed_get` → `uiStore.setDisplayName`（唯一前端数据源）。
  - `OnboardingRitual.tsx`：seed 写入成功后即时同步 `uiStore`；「没有 Key？跳过」改为 `finishWithSeed(true)`（不再丢失已填称呼/场景），保存中禁用。
  - `Sidebar.tsx`：删除挂载时重复拉取（由 App 引导统一加载）。
  - `WelcomeScenes.tsx`：称呼改读 `uiStore.displayName`（即时同步）；场景列表在称呼变化时重拉 seed，保证欢迎页卡片顺序与刚写入的 seed 一致。
- **依赖：** `serde_yaml` 移入 `[dependencies]`（此前在 dev-deps）。
- **偏离方案处：** 无。
