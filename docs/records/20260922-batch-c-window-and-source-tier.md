## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是「把窗口从一天改成三天」（那是拍脑袋放大）；不是「把 `A／B／C` 换个词叫官方／主流／其他」（换个词不治事）；不是「再加一条去重规则」。
- **拆出的真：**
  1. **窗口的真**：一期该覆盖的是「**上一期发出去之后、这一期发出去之前**发生的全部新闻」。实测 09-20 卷止于 **16:24**、09-21 卷起于 **07:54** —— 中间 **15.5 小时**既不在上一卷、也不在本卷。这不是"当天料不够"，是**边界切错了**：按自然日切，每天都会在边界留一条缝，而周末那条缝有三天的宽。
  2. **等级的真**：`【A／B／C】` 是采集端自己贴的，**含义从未定义**（同一类证监会条目被标过 A、也被标过 C）。下游拿它当"重要性"用，等于**拿一个没有定义的东西做判断**。标准要的是另一样**真实存在、可判定**的东西——信源可信度（官方／主流／其他），而它只有**一个**作用：决定这条**要不要再找一个来源**。
  3. **合并的真**：传闻 → 回应、调查 → 处罚，是**同一件事的两个阶段**，不是两条新闻。按链接去重只能删掉「同一篇文章的重复」，删不掉「两篇文章讲同一件事」。
- **如何从真推出：**
  ① 窗口按**上一期目录日期 + 发布时刻 06:00** 推出 `[T_prev, T_current)`，**写进卷首**（我们没有真实发布记录 → 常挂 `FALLBACK_TIME_WINDOW`）；
  ② 卷间再比一次首尾时间戳，空档 **≥ 6 小时**就点名（`COVERAGE_GAP`）；
  ③ 条目第一字段从等级换成**信源层级**（官方／主流／其他，按名单站点一一对照 —— 站点属性，不由模型裁量），**栏内排序改回发布时间倒序**（层级不许进排序）；
  ④ **索引去掉等级列**（引擎取料只认 ID 与 `L<行号>`）；
  ⑤ **事件级合并落到看全量的那一棒（吕老师）**：事件组是**竞争的基本单位**，而他正是做竞争的人；采集端只保留按链接去重。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 每一期都要走 王海燕 → 吕老师 → 小宋 的用户。
- **解决什么痛点：** ① **边界漏稿**（周末那份最容易漏，而且事后查不出来）；② 卷里上百条只有一个来路不明的等级可看；③ 同一条链的两篇被当两条，白占版面。
- **用完后用户多得到什么：** 窗口**明白写在卷首**（可回查、可对账，不用猜这期到底覆盖了哪一段）；层级有定义、能指导"要不要再找一个来源"；同一条链只占一个名额，版面腾出位置给真正的新事。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库（窗口从目录推出，不建发布记录库）
  - [x] 步骤可感知、可预期（多一条打印窗口的 bash，其余不变）
  - [x] 不增加无意义确认或噪音
  - [x] 主操作一眼能找（卷首一行就是窗口）
  - [x] 高频路径更干净（索引少一列、栏内一种排序）

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户在组会话里说「开工」；王海燕采料交卷，吕老师报题，小宋成稿。
- **怎么走完：** 海燕先出**一条窗口**（一句 bash 打印起止）→ 六个子代理按这个窗口采 → 海燕接栏落卷（**卷首带窗口**）→ 交卷带**统计行**与**卷间空档**一行 → 吕老师整读、按**事件组**合并后再竞争 → 小宋成稿。
- **看起来怎么样：**
  - 卷首：`# 财富早知道 · 资讯卷｜窗口 2026-09-21 06:00 — 2026-09-22 06:00（北京时间）｜FALLBACK_TIME_WINDOW`
  - 条目第一行：`【官方】中国证券报｜2026-09-21 07:54｜`
  - 统计行：`本次采集统计：有效资讯 N 条（官方 a／主流 b／其他 c；…）。`
  - 空档那行只在 ≥6 小时时出现：`卷间衔接：上一卷止于 …，本卷起于 …，空档 15 小时（COVERAGE_GAP）——这段时间可能有事没采到，回头补。`
- **好走 / 好看：** 层级用的是人话（官方／主流／其他），不是字母；窗口在卷首第一行，谁都能对账。
- **成功标准：** 周一那一期窗口**跨 3 天**（含周末）；空档 ≥6h 会在交卷里被点名；索引 5 列、没有等级列；吕老师那边同一条链只占一个名额。
- **明确不做什么：** 不建发布记录（`T_prev` 仍从目录推，标 `FALLBACK_TIME_WINDOW`）；不改「三行一条」的格式（只换第一字段的含义）；不动三板块与 ID 规则；**不把窗口写进吕老师的产出**（他被裁定与时间无关 —— 标准 §8.1.4「决策记录写明窗口」由**卷首**承担，见 §0c）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 提示词层（采集契约的**窗口口径**与**条目字段语义**）+ 一处确定性脚本（接栏 `awk` 的字段与行号）。
- **正确的长期默认路径：** 窗口由**上一期目录**推出、**写进卷首**；层级是**站点属性**，按名单一一对照，不由模型自由裁量；索引只带 `ID｜来源｜时间｜线索｜行号`。
- **与引擎/各入口边界：** 只动被注入的文本；`material_read` 解析不变（它只读 **ID** 与结尾 `L<行号>`）——但**测试夹具改成新格式**，免得夹具教出旧格式。接线在 CLI / GUI / server 同源。
- **安全影响：** 无（纯本地明文，无 token / 网络变化）。
- **如何防复发：** `persona.rs` 断言钉住 —— 王海燕契约**必须**含窗口三样（起止、`FALLBACK_TIME_WINDOW`、`COVERAGE_GAP`）与三个层级词，**不许**再出现 `【A／B／C】` 与 `A x／B y／C z`；吕老师契约**必须**含「事件组」，且不许把信源层级当重要性。**接栏 bash 整段实跑一遍**（临时工作区）验证卷首 / 去重 / 统计行 / 索引列 / 空档。
- **为何这不是补丁：** 换的是**窗口口径**与**字段语义**（定义层），不是给旧口径加特例；旧的 A／B／C 标记与索引等级列整块删除，不留兼容分支。

## 1. 方案（Plan）

- **目标：** 一期覆盖「上一期到这一期」的完整区间；条目带**有定义**的信源层级；同一条链只占一个名额。
- **范围：**
  - **做** —— 王海燕契约（窗口 / 卷首 / 卷间空档 / 信源层级 / 索引去等级列 / 接栏 bash / 子代理契约）；吕老师契约（事件组 + 信源层级口径 + 索引那句）；`material_read` 夹具；防回归断言；本台账。
  - **不做** —— 发布记录数据库；`_parts` 目录形态；HOT 形态；三板块结构与 ID 规则；吕老师的时间口径（继续保持无关）。
- **用户路径变化：** 改前 —— 默认「当日北京时间」；条目带 `【A／B／C】`；索引 6 列带等级；吕老师只按链接去重。改后 —— 默认「上一期发布时刻 → 本期发布时刻」；条目带 `【官方／主流／其他】`；索引 5 列；吕老师按事件组合并后再竞争。
- **技术要点：** `crates/hermes-core/src/personas/wang-hai-yan.md`、`.../lv-lao-shi.md`、`crates/hermes-tools/src/material.rs`（夹具）、`crates/hermes-core/src/persona.rs`（断言）。
- **风险与回滚：** 人设 `include_str!` 编进二进制，**必须重编重启 GUI** 才生效；窗口跨天会让子代理多扫一天（周一多两天）——慢一点，但漏稿的代价更高；回滚 = 契约文本与断言复位。
- **方案确认：** [x] 已对照 P0/P1 · 2026-09-22 · 用户「C 批」
