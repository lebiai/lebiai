## 0-fp. 第一性原理

- **拒绝的类比：** 不是因为"别的爬虫也这么抓"，也不是因为"名单是我们写的所以一定对"。
- **拆出的真：**
  1. 一轮采集的耗时 = **每个入口各自耗时的总和**，而不是"模型有多聪明"；
  2. 名单是**我们对站点的一厢情愿**，站点是否可读是**外部事实**；
  3. "某个站拿不到"必须是**可核对的结果**，不能是模型的叙述（第 1 期卷尾写"15 个站点拿不到"，
     而同一轮 curl 实测 18 个站里 16 个返回 200 —— 站是活的，是我们读不出正文）。
- **如何从真推出：**
  1 → 把入口**逐条实测**，把"怎么取"写成表，模型不再自己猜路径；
  2 → 按实测结论重写名单（改协议、改路径）；
  3 → 同一回复里**一次性发完全部调用**，引擎 `join_all` 并发执行（`hermes-turn/src/lib.rs:520`），
      20 个站的总耗时 ≈ 最慢那个。

## 0b. 产品经理视角

- **场景：** 用户在《财富早知道》里说"开工"，海燕开始采集当天资讯。
- **怎么走完：** 海燕先按窗口和名单，**一条回复里发完 A 组全部 web_fetch** → 再**一条回复里发完 B 组全部 bash** → 汇总 → 三栏落盘 → 对话里给同一份清单。
- **看起来怎么样：** 用户立即看到一整排抓取行同时起跑、同时收敛，而不是一行接一行慢慢爬。
- **好走 / 好看：** 过去 25 轮串行 → 现在 2 轮。
- **成功标准：** 一轮采集里，来源分布不再被单一站点垄断；总耗时显著低于"站数 × 单站"。
- **明确不做什么：** 不做无头浏览器（本轮）；不改三栏/三行格式；不动 A/B/C 规则。

## 0c. 架构师视角

- **根因层级：** 提示词层（名单含大量已删站点、入口写错协议/路径、没有取法），叠加模型默认串行发调用。
- **正确的长期默认路径：** 名单是**实测过的入口表**，不是愿望清单；取法是表的一部分；
  采集按"两棒并发"执行；引擎侧已有 `join_all` 并发（无上限），无需改造即可受益。
- **与引擎/各入口边界：** 只改 `hermes-core` 的人物定义与团队定义；引擎行为不变。
- **安全影响：** 无新增。`bash` 已在 `permissions.allow` 内；`web_fetch` 的 SSRF 校验不变。
- **如何防复发：** 名单表里每一行都有"入口 + 取法"，模型无处可猜；"只试一次 + 台账"让失败可核。
- **为何这不是补丁：** 不是给某一站加特判，而是把"名单"从叙述改成**实测入口表 + 执行方法论**。

### 真正的瓶颈：抽取预算，不是并发（本轮新查出的根因）

第一轮实跑（`wang-hai-yan`，2026-09-20 18:18）并发是成功的 —— 17 个 `web_fetch` 一条回复发完、
12.6 秒收敛。**但整轮零产出**：模型最终在 16384 tokens 处被截断，报「这一轮没能产出内容」。

顺着会话 JSONL 与 usage 查下去，链条是：

1. `web_fetch` 带 `prompt` 时走抽取：把页面压成 markdown（上限 48000 字）交给抽取模型，只回答案。
2. 抽取预算写死 **2048** tokens（CLI / GUI / server 三处各写一份）。
3. 配置的模型是推理模型：**2048 会全被看不见的推理吃掉**，`content` 回空串、`finish_reason=length`。
   实测（新华财经首页）：`completion_tokens=2048, reasoning_tokens=2048, content_len=0`。
4. `web_fetch` 那时**静默退回整页原文**（默认 `max_chars=20000`）→ 6 个重页各倒回 20000 字。
5. 一次 159632 字的 tool_result 灌进上下文 → 输入 293622 tokens → 模型要在同一条回复里
   既解析又出全卷 → 撞爆 16384 输出上限 → **整轮作废**。

同一页换 **8192** 再抽：`finish_reason=stop`、正文 **6620 字**（推理 4234）。所以：

- 预算 2048 → 8192（提到 `hermes-tools::web::DEFAULT_EXTRACT_MAX_TOKENS`，三处共用一份）；
- **抽不出来不许静默退回整页**：回一句「拿不到」，让采的人记一笔往下走。

另发现：央视网 `news.cctv.com` 的 `Content-Type` 不带 charset、页面声明 `gbk`，
按 UTF-8 解→26 字，按 GBK 解→4519 字。`web_fetch` 用 `resp.text()`，此类页面会返回乱码（本轮记为缺口，不在本次改动内）。
