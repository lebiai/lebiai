## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是因为「视频脚本工具都带 `seconds` 字段，所以留着」「谁写稿谁配速是行业惯例」「多写一句少写一句无所谓的保险」。
- **拆出的真：**
  1. **「播哪几条」是判断，「每条几秒 / 全篇多少字」是把判断兑成长度——两件不同的活。** 判断错了要重筛全量，长度错了只要重排，返工面差一个量级。原判据把两件活压在同一个人的同一次报单里，等于让关口替下游拍板。
  2. **用户只看得见对话里那一段。** 文件写到哪、ID 长什么样、谁在几点落盘，对他来说都是黑箱；他抱怨「看不懂」，是把**工位之间的行话**当成了交付。
  3. **「先写文件再说」= 用户没点头就定了稿。** 全流程唯一必停点那道门，被「落盘即交付」的老写法绕过去了。
- **如何从真推出：** ① 把秒数从吕老师契约与团队流程里整体摘掉、交给小宋（并给出 120 秒 / 4.5 字/秒 的硬数和「只自检一次」的纪律），工具 `items.seconds` 从 schema 撤下（引擎字段留着兼容旧文件）；② 给三个人物各加一节「给用户的话（说人话）」，写死内部词黑名单与「先把内容念出来」；③ 小宋 / 小雨加「先给人看，再落盘」，把落盘压在用户点头之后；④ 吕老师契约里**一个时间词都不留**——连「我不定秒数」这种否定句也写不得：提一句就是给模型一个念头，迟早漏成一个 `seconds` 字段。

## 0. 用户价值（必填 · 站在用户角度）

- **谁用：** 在「财富早知道」项目组里看报题、看稿子的用户。
- **解决什么痛点：** ① 吕老师的报单里全是「12 秒、13 秒」，用户看不懂他到底在定什么；② 小宋 / 小雨不说话就把稿子落了盘，用户拿到的是文件路径而不是稿子；③ 给用户的话里全是 `ID`、`秒槽`、`口径`、`让秒`、`对账` 这类行话。
- **用完后用户多得到什么：** 报单只剩「播哪几条、什么顺序、为什么是它」，一眼能念；稿子**先在对话里贴全**、点头才落盘，用户不用去翻文件；三个工位给用户的那一段，人话、无内部词。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期（多了一道「先看后点头」的门，门后才是文件）
  - [x] 不增加无意义确认或噪音（吕老师那一段反而更短）
  - [x] 主操作一眼能找（这一期播什么 → 稿子 → 口播稿）
  - [x] 高频路径步骤少、界面干净（用户不必打开 outputs 目录）

## 0b. 产品经理视角（必填 · 禁止跳过）

- **场景：** 用户在组会话里，先看吕老师报这一期的题，再让小宋出稿、小雨出口播稿。
- **怎么走完：** 吕老师报「播哪几条、什么顺序、每条什么角度」→ **用户点头**（全流程唯一必停点）→ 小宋在对话里**把成稿贴全** + 一行配速 → 用户点头才落 `outputs/<日期>/成稿-<日期>.md` → 小雨同理，先念给用户看，点头才落盘。
- **看起来怎么样：** 吕老师的报单从「序号｜ID｜秒数｜角度」变成**按三板块分段、一条新闻一组三行**（`ID ｜ 来源` / 这条新闻是什么 / 为什么播它），板块里有几条就写几组；他给用户的那一段里再没有任何与时间有关的字；小宋 / 小雨回复的首屏就是**稿子本身**，不是「已落盘」。
- **好走 / 好看：** 用户少打开一次文件夹；失败态明确（「这个 ID 我取不到」「这一期的料没落盘」，不许拿别的条目顶）。
- **成功标准：** 用户读完吕老师那一段能说出「今晚播哪几条」；读完小宋那一段能**直接念**；三段里都不出现内部词。
- **明确不做什么：** 不改三板块结构、不改 ID 规则与工具调用方式、不给吕老师加新职责；不重写 `Item.seconds` 这个引擎字段（旧文件要能读）。

## 0c. 架构师视角（必填 · 禁止修修补补）

- **根因层级：** 提示词层 —— persona 契约 + 团队流程 + 工具 schema 描述，三处都写着同一条错误的职责边界。
- **正确的长期默认路径：** 职责边界只写一处（契约里），并且**工具的形状要跟契约一致**：schema 里还留着 `seconds`，模型就会填，契约写十遍也没用。
- **与引擎/各入口边界：** 只动被注入的文本（`personas/*.md`、`teams/*.md`、`reflect` 提示词）与一处工具 schema 属性；不碰引擎状态机、不碰 UI、不碰数据模型。三个入口（CLI / GUI / server）同源生效。
- **安全影响：** 无（本地明文、无 token / 网络变化）。
- **如何防复发：** `crates/hermes-core/src/persona.rs` 的防回归测试加断言 —— 吕老师契约**不许出现任何时间词**（`秒` / `配速` / `时长` / `分钟` / `时间`），**必须**出现「给用户的话」；小宋 / 小雨**必须**有「先给人看，再落盘」「没点头不许写文件」「给用户的话」；小宋**不许**再出现「序号｜ID｜秒数｜角度」。
- **为何这不是补丁：** 不是给吕老师打一句「不要写秒数」的特判，而是把**「秒数归谁」这一条边界**在 人设 / 团队 / 工具 三层同时改到同一个真值，并把「说人话」「先看后落盘」写成三个人共有的硬约束。

- **范围：**

## 2. 实施（Implement）

- **实际改动摘要：**
  - 吕老师：**契约里一个时间词都不剩** —— `秒` / `配速` / `时长` / `分钟` / `时间` 全清（连「我不定秒数」这种否定句也删）；items 不带 `seconds`；新增弃稿第 6 条「不选国外新闻」（原只活在记忆里）；新增「给用户的话（说人话）」；清掉两处实测史。
  - 吕老师（用户当场定的输出格式）：《选题单》正文由「`序号｜ID｜角度` 四列清单」改成**三板块分段、一条新闻一组三行**——板块名（宏观 / 产业动态 / 资本市场）→ `<ID> ｜ <来源>` → 这条新闻是什么（一句话）→ 为什么播它（角度与侧重）；板块里有几条就写几组，组间空行；三板块之后仍是弃稿台账。「角度列」这个说法随之取消，改叫「新闻与理由两行」（同样不许带素材外的事实与数字）。
  - 小宋：新增「**配速是我的活**」（120 秒 / 4.5 字每秒 ≈ 540 字含开场收尾）、「字数只自检一次（±10%）」、整节「**先给人看，再落盘**」、禁读前一天稿 / 禁 `find` / 禁 `conversation_recall`；新增「给用户的话（说人话）」+「成稿正文必须贴全」。
  - 小雨：新增「先给人看，再落盘」、禁读旧稿 / 禁到处翻、「给用户的话（说人话）」。
  - 团队文件：秒数归属改口（一期几条吕老师定，每条几秒小宋配）；第 3 步写「先贴全、点头才落盘」；第 4 步写「先念给用户看」。
  - 工具：`decision` 描述改成「what runs tonight, in what order, and why」+ 明写 **Do not set `seconds`**；schema 里撤下 `seconds` 属性。
- **关键路径/文件：** `crates/hermes-core/src/personas/{lv-lao-shi,xiao-song,xiao-yu}.md`、`crates/hermes-core/src/teams/caifu-zaozhidao.md`、`crates/hermes-tools/src/decision.rs`、`crates/hermes-core/src/decision.rs`、`crates/hermes-reflect/src/prompt.rs`、`crates/hermes-core/src/persona.rs`、`docs/spec/projects.md`
- **偏离方案处：** 无。
