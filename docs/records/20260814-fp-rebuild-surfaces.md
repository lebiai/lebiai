## 0-fp. 第一性原理（必填 · P0 第零条）

- **拒绝的类比：** 不是因为 ChatGPT/Cursor 用 thinking 折叠 + tool 列表；不是因为记忆产品做成 CRM 通讯录；不是因为侧栏「少几个 tab 更干净」的行业习惯。
- **拆出的真：**
  1. 用户打开桌面是来共事，要知道「事有没有被推进」，不是来读 agent 轨迹。
  2. Continuity 的真是「它懂我」：偏好、标准、做过的事——不是 zone/confidence 库存表。
  3. 技能是批准后的可复用做法，不是每天的家。默认路径是对话 → 批准进化。
  4. 进不去的面板、token 角标、Hermes/写 Rust 函数空态，会把产品说成另一件事。
- **如何从真推出：**
  1. 过程区一行人话（查资料 / 写了文件 / 在想这件事）；细节折叠；去掉 token 角标。
  2. 侧栏只留「对话 / 它记得的 / 设置」。「它记得的」里：它懂你（按偏好/标准/做过的事）+ 你的做法。
  3. 删 MCP / 提炼死路由与死常量 `CHAT_TOOL_WHITELIST`。
  4. Flutter 用户可见面改成搭子话术与同事场景，过程卡用人话。

## 0. 用户价值

- **谁用：** 桌面 GUI 默认用户；手机端同一引擎的表面。
- **解决什么痛点：** 做事时像在看调试台；「记忆」不像它懂你；技能和对话抢主场；手机还在说 Hermes。
- **用完后用户多得到什么：** 过程看得懂；打开「它记得的」能认出自己；技能不挡对话；手机空态是共事不是写代码。
- **好用性自检：**
  - [x] 不需要额外运行时 / 数据库
  - [x] 步骤可感知、可预期
  - [x] 不增加无意义确认或噪音
  - [x] 主操作一眼能找；空/载/错态完整
  - [x] 高频路径步骤少、界面干净

## 0b. 产品经理视角

- **场景：** GUI 对话里模型在做事；打开侧栏看它记得什么；手机打开空对话。
- **怎么走完：**
  1. 发话 → 过程区一行「正在查资料」→ 答完塌成「查了资料」→ 点开才看细节。
  2. 点「它记得的」→ 先待你点头（有候选时）→ 偏好 / 标准 / 做过的事。要点做法再切「你的做法」。
  3. 手机打开 → 「你好，我是乐彼AI」+ 谋划/表达场景卡，不是报错/Rust。
- **看起来怎么样：** 过程区是浅底细字，不是代码块墙；记忆卡片先正文；侧栏三项。
- **好走 / 好看：** 主导航从四项变三项；技能不再和对话平级。
- **成功标准：** 不读说明书也能完成「对话 → 看它记得的 → 确认候选」；过程区没有 token、没有 `web_search` 当标题。
- **明确不做什么：** 不重做设置页；不删引擎工具；不把 MCP 配置从 `mcp.json` 拿掉；不改授权逻辑。

## 0c. 架构师视角

- **根因层级：** UI 信息架构与过程呈现仍按 coding-agent 骨架；导航类型多出死表面。
- **正确的长期默认路径：** `Panel = chat | know | settings`；过程文案单一函数；记忆分组对齐 companion zones。
- **与引擎/各入口边界：** 只改表面呈现。工具、确认、inbox、IM 白名单不动。Flutter 只改用户可见文案与过程卡。
- **安全影响：** 无。删 `CHAT_TOOL_WHITELIST`（从未过滤 CLI chat）不改变 IM 的 `IM_TOOL_WHITELIST`。
- **如何防复发：** 导航类型收窄后编译期禁死面板；过程动词集中在 `processLabel.ts`。
- **为何这不是补丁：** 改默认 IA 与过程语义，不是给旧列表加 i18n 贴皮。
